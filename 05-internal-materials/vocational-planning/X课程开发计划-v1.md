## 二、各阶段详细说明

### Phase 1: 实验代码开发

**目标**：为每个课时编写完整的实验代码项目包，供用户在 K1 真机上逐课验证。

**定位**：你编写，我验证。代码不是验证报告，而是可运行的工程包。

**每个课时的实验代码包包含**：

| 内容 | 说明 |
|---|---|
| `main.py` | 核心实验脚本，运行即执行该课时的轻任务 |
| `README.md` | 本课时实验说明：目的、操作步骤、预期结果 |
| `requirements.txt` | 依赖声明（如有额外包） |

**实验代码设计原则**：
1. **低耦合**：每课时一个独立脚本或工程包，不依赖其他课时的代码
2. **可渐进**：从 `boosteros` 最简 API 出发，逐步打开 SDK 各能力面
3. **有输出**：每个脚本运行后能产生可见结果（print / 保存文件 / 机器人动作），便于验证
4. **有注释**：关键 API 调用处标注说明
5. **安全第一**：涉及机器人运动的脚本有安全提示和限速

**知识缺口标注**：
- 如果某课时实验需要用到未在之前课时中教授的前置知识（Python 语法/ROS2 概念/工具操作），在 `README.md` 的「前置知识」小节中标注
- 这些标注汇总后将作为大纲修订的依据

**执行顺序**：U1 → U2 → ... → U8（逐课时推进）

**交付物**：32 个实验代码项目包（每课时 1 个）

**目录结构**：
```
vocational-planning/实验代码/
├── U1-L1_K1连接与信息/
│   ├── main.py
│   ├── README.md
│   └── requirements.txt
├── U1-L2_ROS2通信基础/
│   └── ...
├── U1-L3_传感器速览/
│   └── ...
├── U1-L4_模式控制与安全/
│   └── ...
├── ...
└── U8-L6_成果展示/
    └── ...
```

**存储位置**：`vocational-planning/实验代码/`

### Phase 2: 课时大纲结构

**目标**：为每课时设计 90 分钟的教学环节安排，按单元组织。

**前置条件**：Phase 1 对应的单元实验代码验证通过
**组织方式**：**按单元**（一个单元一个课时大纲文档）

**每单元课时大纲包含该单元所有课时的环节设计**：
1. **教学环节表**：时间分配、环节名称、内容概要、教学方法
2. **过渡设计**：环节间如何自然衔接
3. **重难点标注**：标注本课时的重点和难点
4. **前后衔接说明**：与上一课时和下一课时的关系

**环节参考模板**（按课时特点调整）：

| 环节 | 时长 | 内容 |
|---|---|---|
| 导入 | 5-10min | 上节回顾 + 本节目标 + 演示最终效果 |
| 知识讲解 | 20-30min | 核心概念讲解 + 教师演示 |
| 实操练习 | 35-45min | 轻任务分步执行，每步有可验证产出 |
| 整合产出 | 10-15min | 小项目整合 + 总结 + 下节预告 |

**交付物**：8 份单元课时大纲（每单元 1 份，每份涵盖该单元全部课时的环节设计）

**存储位置**：`vocational-planning/课时大纲/`

**门禁**：⚠️ 确认① — 用户审核课时大纲后进入 Phase 3

## 五、执行策略

### 批次推进

按单元推进，Phase 1-2（代码+大纲）全课程优先完成，Phase 3-5（教学设计+PPT）按单元批次推进：

```
第一阶段：全课程实验代码 + 课时大纲
  U1: Phase 1 → Phase 2 ─┐
  U2: Phase 1 → Phase 2 ─┤
  ...                     │ → [确认①]
  U8: Phase 1 → Phase 2 ─┘

第二阶段：按单元批次制作
  U1: Phase 3 → Phase 4 → [确认②] → Phase 5
  U2: Phase 3 → Phase 4 → [确认②] → Phase 5
  ...
```

**关键策略**：
- Phase 1-2 全课程优先完成——验证结果可能影响后续单元的大纲调整
- Phase 3-5 按单元批次推进——每单元完整闭环，可即时用于教学
- 前 16 课时（U1-U4）优先完成，支持"前 16 独立开课"设计

### 并行优化

| 场景 | 可并行操作 |
|---|---|
| Phase 1 进行中 | U_n 代码包完成 → 可开始 U_n 的 Phase 2 课时大纲 |
| Phase 2 确认后 | 教学设计与实训手册可并行编写 |
| Phase 3 完成后 | Phase 4 可立即开始 |

### 依赖关系

| 阶段 | 前置条件 | 产出后解锁 |
|---|---|---|
| Phase 1 | SDK 文档可访问 | Phase 2 |
| Phase 2 | Phase 1 通过 | 确认① → Phase 3 |
| Phase 3 | 确认①通过 | Phase 4 |
| Phase 4 | Phase 3 完成 | 确认② → Phase 5 |
| Phase 5 | 确认②通过 | — |
