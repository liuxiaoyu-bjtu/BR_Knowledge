# P0 · 课程定位与大纲设计 · 规格 v0.1（已定稿）

> **定位**：P0 是整条流程的源头。**产出 = 课程大纲**，而大纲是 P1（教案）的输入契约。
> **本文件三件事**：入口（引导式收集）· 出口（大纲规格）· 闸门（确认⓪）。
> **依据**：`人形机器人基础课程大纲.md` v0.2 回抽 + 教学法参考库。

---

## 一、P0 干什么

把"一门课的需求"变成"一份可开工的课程大纲"。**这是一个多轮交互的过程，不是一次生成。**

```
引导式需求收集 →（调研，按需）→ 大纲起草（多轮：补边界 / 对期望）→ 确认⓪ → 大纲定稿
```

- **多轮交互**：起草细化大纲时，Agent 与共建者要**来回若干轮**，逐轮明确"各种边界"与"设计期望"（单元边界、概念准入、授课形式、考核取向…），**每轮复述确认后再往下**。
- **不许**在需求没收集全时直接写大纲——这是专家工作流第〇条（先锁定受众与目标）。
- 大纲没定稿，**不许**进 P1。

> **边界定义的粒度（重要）**：P0 是宏观层，只在**课程级 / 单元（模块）级**定义"不做什么"；**逐课的"不做什么"下移到 P1 教案确认阶段**——那里才有足够信息判断每课该砍什么。P0 不越俎代庖。

## 二、入口 · 引导式需求收集

### 2.1 需求采集模板（共建者填写）

共建者按此表提供信息；Agent 用它约束输入、检查空槽。

| 字段 | 说明 | 必答 | 示例 |
|---|---|---|---|
| 课程主题 / 名称 | | ✔ | 人形机器人基础 |
| 学段 | 小学 / 初中 / 高中 / 高职 / 本科 / 成人 / 企业 | ✔ | 高职 |
| 学生年龄 / 年级 | | ✔ | 大一（约 18 岁） |
| 专业方向 | | ✔ | 理工类（机器人 / AI / 自动化 / 智能制造…） |
| 基础水平 | 零基础 / 有基础 / 进阶；班级规模 | ✔ | 零基础，大班 |
| 课时规模 | 总课时 × 单次时长 × 排课形式 | ✔ | 8 × 45′，4 次 × 2 节连排 |
| 教学载体 | 硬件 / 软件 / 平台 | ✔ | Booster K1 + Booster Studio |
| 课程定位 | 通识 / 专业基础 / 专业核心 / 实训 | ✔ | 专业基础课（课链最前端） |
| 目标取向 | 认知 / 技能 / 上岗 / 兴趣 | ✔ | 认知（"看懂"级） |
| 考核方式 | | ○ | 调研小论文 |
| 先修 / 后置课程 | | ○ | 先修无；后置 数采 → X 课程 → Agent |
| 场景约束 | 线上/线下、机房/教室、网络与设备限制 | ○ | 阶梯教室大课，不进机房，不写代码 |
| 已有素材 | 已有大纲 / 教案 / 调研 / 参考课 | ○ | 大纲 v0.2、调研①-④ |
| 呈现 / 合规约束 | 公司呈现规范、概念准入、品牌口径 | ○ | 前沿代表优先级；概念分层植入 |
| 期望交付物 | 大纲 / 教案 / 课件 / 考核 / 读本… | ○ | 全套 |

> **规则**：必答项缺任一 → 不能进大纲起草；可选项缺 → 用**显式假设**（`📌 假设：…`）补位并请用户确认。

### 2.2 苏格拉底提问清单（Agent 用，分轮）

Agent 对照 2.1 的空槽，**分轮提问**补全。每轮问完先复述、再往下。

| 轮 | 主题 | 要问到什么 | 示例问法 |
|---|---|---|---|
| 1 | **对象** | 学段 / 年龄 / 专业 / 基础 / 班级规模 | "这门课教的是哪一段的学生？什么专业、什么基础？" |
| 2 | **目标** | 学完**能做什么**、解决什么具体问题 | "学完以后，你希望他们**能做到什么**？现在缺的是什么？"（逼出可观测目标） |
| 3 | **约束** | 线上/线下、课时、设备/平台限制 | "线上还是线下？多少课时？有没有设备或平台限制？" |
| 4 | **素材** | 手头已有材料、参考过的课 | "你手上已经有哪些材料？有没有参考过相近的课？" |
| 5 | **边界（单元级）** | 课程级 + **各单元 / 模块**层面"不做什么" | "这门课最容易讲过头的地方在哪？**在单元层面**，哪些内容你决定**不讲**？"（**逐课"不讲什么"留到 P1 再定**） |
| 收束 | **确认** | 复述 + 列出"待补项"与"显式假设" | "我复述一下：…… 对吗？还有两处我先按假设填，你后面可以改。" |

**提问纪律**：
- 必答题**先问**（≤4 轮问完）；可选题后问或给默认。
- 一次问一组，不连环拷问；问完复述。
- 用户答不上来的，**标为待定**并继续，不卡死。

### 2.3 小知识库维护引导

Agent 主动提示共建者把散落材料归拢成**单一来源**的素材库。

> **建议话术**：
> "如果你手头已经有下面这些材料，建议整理到**一个文件夹**（如 `课程素材库/`）给我，我归档为这门课的素材库：
> `01_需求/`（人才培养方案、课标、专业建设方案）
> `02_调研/`（产业 / 技术 / 政策）
> `03_参考课/`（同类课、竞品课）
> `04_平台手册/`（硬件、SDK、软件）
> 命名统一、单一来源。后续每个阶段都从这里取料——**避免同一份规则出现两个副本**。"

### 2.4 调研触发与发起（信息 / 素材不足时，Agent 主动补）

共建者给的**基础信息或素材库若不足，且其本人未主动提调研**，Agent 不能干等项目——要**主动识别缺口并建议发起调研**。

**触发条件（任一命中）**：
- 必答字段拿不到（如缺产业数据、缺技术前沿、缺参考课）；
- 素材库缺关键项（某单元内容无据可依）；
- 共建者明说"这块我不清楚"。

**Agent 动作**：
1. 列出**信息缺口清单**——缺什么、缺在哪一课 / 哪一单元；
2. 给出**建议调研主题 + 优先级**（先做哪个）；
3. 提议方式："建议先做 X / Y / Z 三份调研，我可以**起草调研提纲**，或**直接检索整理**。"
4. 拿到共建者**确认 / 授权**后再执行——**建议 ≠ 擅自执行**（守闸门文化）。

**产出落回**素材库 `02_调研/`，成为后续阶段（P0 大纲 / P1 教案 / P5 读本）的取料来源。

> **先例**：`人形机器人基础` 的 调研①-④，正是这一机制的产物——当时发现"多源发展史 / 研究前沿 / 产业人才数据 / 元器件厂商清单"无据可依，才补的。

## 三、出口 · 大纲产出规格（回抽自 v0.2）

一份合格大纲**必须**包含以下 8 节：

| # | 章节 | 关键内容 |
|---|---|---|
| 1 | 课程基本信息 | 名称 / 性质 / 对象 / 定位 / 总课时 / 授课方式 / 先修 / 后置 / 考核 |
| 2 | 学情分析与设计原则 | 学情特征 × 设计应对；全课设计原则（够用为度、一课一演示、一课一落点…） |
| 3 | 课程目标 | 知识 / 能力 / 素养，**每组可观测、并标注能力层次（布鲁姆）** |
| 4 | 模块结构表 | 模块 / 课时 / 核心内容 / 递进逻辑 / **单元边界（★本单元不讲：…）** |
| 5 | **每课时明细** | 标题 / 所属模块 / **45′ 时间轴** / 概念准入（**逐课"不讲什么"不在此定义，留到 P1**） |
| 6 | 全程约束 | 呈现优先级 / 概念准入通则 / 术语三级处理 |
| 7 | 衔接逻辑 | 模块间递进 + 与前后课程的接口 |
| 8 | 待办与未决项 | 尚需调研 / 确认的事项清单 |

> **边界分两级**：**单元级**在 P0 定（写进模块结构表 §4），**逐课级**在 P1 教案确认阶段定。P0 不越俎代庖去定每课砍什么——那时信息不足。

---

## 四、规则与红线

1. 目标用可观测动词；**交付前扫一遍**：了解 / 掌握 / 熟悉 / 知道 / 懂得 / 理解——命中即改（如"了解产业规模"→"说出 2-3 项硬数据"）。
2. 课时与学时对得上；单次时长的节奏要能承载环节数。
3. 概念准入逐课落地（哪个概念在哪课首次出现）。
4. 事实 / 数据 / 政策条款有疑即核，不编造。

---

## 五、闸门 · 确认⓪

- **停点**：大纲起草完成 → **停**，交共建者审结构与课时。
- 通过才生成 P1；不通过就改，改完再停。
- 大纲定稿后，它就是 P1 的输入契约（不可在 P1 中私自改课程级设定）。
