# 课程研发流程总纲 v0.1（草案）

> **定位**：整套「课程研发 Agent」的主轴。给每个阶段定死 **输入 → 规则 → 产出 → 闸门 → 子SKILL**，让上下游对得上。
> **用法**：研发任何一门课都按 P0→P6 走；**上一阶段的产出就是下一阶段的输入契约**。

---

## 一、Agent 五层架构

| 层 | 装什么 | 现状 |
|---|---|---|
| **L1 原理层** | 教育观 + 学习科学：建构性对齐、UbD、布鲁姆、认知负荷、去AI化 | ✅ 专家库 `teaching-reference` |
| **L2 流程层** | 本文件——P0–P6 的契约与闸门 | 🟡 本文件起步 |
| **L3 规则层** | 各阶段体例：大纲规格、教案体例、分页规范、考核规范、读本规范 | 🟡 P1 教案体例 v2 已有，其余待建 |
| **L4 工具层** | 各阶段可执行子 SKILL | 🟡 `courseware-page-design` 已有 |
| **L5 模板层** | 可复制模板 + 自检清单 | 🟡 部分已有 |

> **封装时机**：等 L3/L5 沉淀够，再用 expert-manager 打包成「课程研发 Expert」。规则没攒够就封装，只会得到一个空壳。

## 二、全流程主脉（P0–P6）

| 阶段 | 输入 | 规则 / 体例 | 产出 | 闸门 | 子 SKILL |
|---|---|---|---|---|---|
| **P0** 课程定位与大纲设计 | 引导式需求 + 素材库 | 大纲规格（见 P0 文档） | 课程大纲（**多轮交互**生成） | **确认⓪** | 需求引导（待建） |
| **P1** 分课时教案 | 课程大纲 | 教案体例 v2 | 设计版教案 | **确认①** | 教案生成 |
| **P2** 演示物料 | 教案（图示规格）+ 平台手册 | 物料 / 配图规范 | 图集 · SVG · 演示脚本 | **确认②** | 物料生成 |
| **P3** 课件详细设计 → 产《课件设计蓝图》 | 教案 + 物料 | 蓝图规范（v0.2） | 课件设计蓝图（.md，**非 .pptx**） | **确认③** | `courseware-page-design` |
| **P4** 考核配套 | 教案（对齐表） | 考核规范 | 试卷 / 评分量规 | **确认④** | 出题 |
| **P5** 课程读本 | 教案（读本要点）+ 调研 | 读本规范 | 学生读本 | **确认⑤** | — |
| **P6** 对外交付版 | 全部定稿 | 纯净版清洗清单 | 交付版套件 | — | 交付版清洗 |

> 阶段之间是**强闸门**：上一阶段的产物没被确认，不进入下一阶段。

> **编号说明**：P0–P6 是本骨架的**一版实例编号**；课型不同，阶段数可不同。跨课程对齐一律按「**阶段目标 + 产出类型**」，不按 P 号——如"**课件详细设计**"阶段在{人形机器人基础}为 P3、在{X 课程}为 P5，二者产出同名同类的《**课件设计蓝图**》。详见 `通用阶段_课件详细设计_规格与契约-v0.2.md`。

## 四、引导式协作原则（★核心机制）

这套 Agent 与"普通生成器"的分水岭：**它主动引导共建者，而不是等一句模糊需求就开干。**

1. **模板约束输入**：用固定模板收口关键字段（见 P0 文档 2.1），避免漏项。
2. **苏格拉底提问补全**：Agent 分轮提问，逐个填满模板空槽（见 P0 文档 2.2）。
3. **提问预算**：字段分「必答 / 可选」。必答先问（≤4 轮）；可选可先给**显式假设**再确认，不把共建者问烦。
4. **复述确认**：每轮填完，Agent 复述一遍让用户点头，再推进。
5. **小知识库引导**：主动提示"有这些材料请归到一个文件夹"，并给命名约定，形成**单一来源**。
6. **阶段闸门强停**：到确认⓪–⑤ 必须停，等用户拍板才进下一阶段。
7. **主动补调研**：信息 / 素材不足、共建者又没提调研时，Agent **主动列出缺口 + 建议调研主题与优先级**，**经确认后**发起，产物落回素材库。
8. **入口防呆 · 技能兜底（★可靠性底线）**：核心能力一律沉淀为**可移植资产**——**项目规则文件（跟 repo 走）+ 子 SKILL（跟账号走）**，**不依赖任何专家被预先加载**。
   - **为什么**：整套 Agent 可能在**没有本专家的其他 AI 应用**里被触发；把能力押在专家上 = 押一个可能不存在的东西。
   - **技能必须自包含**：每个阶段的子 SKILL 自带其所需规则（含必要的原理要点），**不靠专家注入**。→ 需要把 L1 原理层中"用得到的判定规则"**固化进各阶段技能的 references**。
   - **专家降级为"可选入口 / 增强"**，不是依赖；没它 Agent 照样跑及格线。
   - **入口自检 + 主动提示**：Agent 首轮检测任务类型，命中课程设计就主动提示"建议启用课程研发能力；未启用也可按内置规则直接走"——**Agent 主动提，用户不必记**。

> **三条纪律**：① 信息不足时**先出假设版并标注**，不硬编；② 绝不跨闸门一次性把后续阶段全做完——"继续"只等于推进当前审查中的那一步；③ 能力落点**优先级：项目文件 > 子 SKILL > 专家**（越靠前越可移植）。

> **多轮是常态**：从 P0 起，每个阶段都不是"一次生成"——P0 起草大纲要来回若干轮补边界、对期望；P1 逐课确认也要来回。**每轮复述确认后再往下。**

## 五、生成控制逻辑（★定位 · 粒度 · 验收）

> 本节回答三个问题：**谁服务谁（定位）、拆到多细（粒度）、怎么算合格（验收）**。这是"生成怎么被控制"的总规则。

### 5.1 定位：教学设计 ↔ 课件设计

- **课件是"细颗粒度资源"**；**教学设计的流程，本质就是"课件如何被使用"的解读**。
- 反向看：**教学设计的各环节，是指导课件设计的关键信息**——课件把教案"用起来"。
- 一句话链：`教学设计（教什么 / 怎么教）→ 课件（怎么上屏 / 怎么可视化）`。

### 5.2 粒度：目标 → 环节 → **内容块** → 页

- 当前断裂点是 **"内容块 / 教学步骤"这一级**——教案只到环节，课件便退化为"一个环节一页"。
- **教案**须补「环节 → 内容块」层（每块：一句内容 + 学生活动 / 提问 + 预估时长）——属**教学决策**。
- **课件**按内容块 × "一页一动作"展开页（重难点加码 / 问题链 / 留白递进）——属**呈现决策**。
- **覆盖检查**从"环节级"升到 **"内容块级"**（检查点由个位数变二十余个，欠拆藏不住）。
- **页数由内容块导出，不由环节数决定**。密度基准：讲解 / 信息类 **≥2 分钟/页**；一事件一页（2–3 分钟）；关键问题可**连续两页仅差问题文字**；45′ 课量级 **≈18–22 页**。

### 5.3 验收：以"使用教师视角"发起（★关键）

- **哲学**：审核不是查"信息是否齐全"，而是问"**使用教师敢不敢直接拿去上**"。
- **教学设计闸门（三问）**——读完教案后，使用教师能否：
  1. 清楚**每个环节要做什么、要关注学生什么表现**？
  2. 清楚该环节的**设计意图与教学侧重**？
  3. **认同**（"这么设计合理，时长也合理"）？
- **课件设计闸门（两问）**：
  1. 这个**拆解**，是否**有利于讲解对应知识**？
  2. 是否**形象化**——文字 + 图等多元素把知识**可视化传达**？
- **归属**：两阶段都由"**使用教师**"视角发起审核，但标准不同——**教案审"清楚 + 认同"，课件审"利于讲 + 形象"**。
- **可视化是课件的首要质量维度**：课件是细粒度资源，可视化传达就是它存在的意义。

### 5.4 单向生成 + 双向修订

- 生成是**单向**的（教案 → 课件）；但课件阶段发现问题，**反向更新建议**回退教案（时长 / 重难点 / 内容块缺口）。
