# P0 回抽验证 · 人形机器人基础（v0.1）

> **目的**：拿一份真实的成熟大纲（`人形机器人基础课程大纲.md` v0.2），检验 P0 的**需求采集模板**与**大纲产出规格**是否可用、能否抓出真问题。
> **方法**：① 用模板把已知信息回填一遍；② 用规格逐节核对大纲；③ 记录发现与对模板/规格的修订建议。
> **结论先行**：模板与规格**均可用**；规格抓出 2 个真问题（目标动词、逐课边界）。

## 四、发现的问题

**F1｜课程目标含不可观测动词（对应规格红线 1）**
大纲 §三出现：
- "**了解**产业规模、政策与人才缺口现状"
- "**掌握**基本安全常识"
- "**知道**人形机器人'怎么被开发出来'"

→ 三处违"禁用了解 / 掌握 / 知道"。改法示例：
- "了解产业规模…" → "**能说出** 2-3 项产业规模与人才缺口的硬数据"
- "掌握基本安全常识" → "**能复述**安全四条并说明其顺序"
- "知道…怎么被开发出来" → "**能按'仿真→连接→控制→部署'复述**工具链四步"

> 另：课程目标未标**布鲁姆层次**，建议补一列。

**F2｜每课"能力边界（讲什么·不讲什么）"未逐课显式**
大纲把边界散在"高职落点"里（L3"不引入 DH 参数/正逆运动学"、L5"杜绝公式"已做对），但不系统。建议 §五每课固定加一行：

`★本课不讲：……`

**F3｜§七 小节编号重复**（出现两个"3."）——格式 bug，顺手修。

**F4｜§十 未决项 3 条**（多模态演示素材、小论文细则、与通识课关系）——属正常待办，符合规格第 8 节，**不算缺陷**。

## 五、对模板 / 规格的修订建议

| 对象 | 建议 | 理由 |
|---|---|---|
| 需求采集模板 | 基本沿用；**"已有素材""呈现/合规约束"标记为 Agent 必问** | 最易漏、最易返工 |
| 大纲产出规格 | 把第 5 节"能力边界"**升为独立子项 + 固定写法** `★本课不讲：…` | 极易漏，且是 P1 越界源头 |
| 大纲产出规格 | 新增一条：**课程目标须标注能力层次** | 与教案体例的布鲁姆层次对齐 |
| 大纲产出规格 | 加一条自检：**"目标动词扫描"**（搜 了解/掌握/熟悉/知道） | F1 这类问题可自动拦下 |

## 六、结论

1. **模板可用**：15 字段完整覆盖一门真实课程，无冗余、无缺项。
2. **规格可用**：能对成熟大纲做出分级判定，并抓出 2 个真问题。
3. **最有价值的发现**：连一份成熟大纲都被抓出"目标动词"问题——印证 **P0 的红线自检不是形式**，越早拦越省事。
4. **对流程的意义**：P0 一旦按此规格固化，P1 拿到的就是"目标可观测、边界清晰"的大纲，教案体例 v2 的对齐表才有稳定的输入。

> 下一步（待确认）：是否据本验证结果，微调 P0 规格并**定稿 P0**，然后进入 P1 的批量回填（L2-L8）。

## 七、后续修订（2026-09-11 追加）

据用户反馈，两处结论调整如下：

1. **F2 的处置改了**：原来建议"在 P0 大纲里逐课写明不讲什么"——**撤回**。P0 是宏观层，边界只定到**单元 / 模块级**；**逐课"不讲什么"下移到 P1 教案确认阶段**（那里信息才够）。
2. **P0 本身是多轮交互**：起草细化大纲要来回若干轮，逐轮明确边界与设计期望——已写进 P0 规格 §一。

另：
- **F1 已按规格就地修复**（大纲 §三 目标的"了解 / 理解 / 掌握 / 知道"→ 可观测动词），此为唯一改动的大纲内容；
- **F3（§七 编号重复）、F4（待办）暂不改**（F3 属格式、F4 属正常待办），按"本轮只动目标用词"的约束留待后续。
