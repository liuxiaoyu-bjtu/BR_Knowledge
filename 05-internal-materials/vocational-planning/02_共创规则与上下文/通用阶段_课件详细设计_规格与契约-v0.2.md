# 通用阶段 · 课件详细设计 · 规格与契约 v0.2（草案）

> **定位**：「课程研发 Agent」P0–P6 主脉中的**通用阶段**之一——**教学设计定稿之后、课件成品生成之前**的课件详细设计阶段。

## 一、为什么是"通用阶段"（阶段目标对齐，而非课程 P 号对齐）

**原则**：Agent 用"**阶段目标 + 产出类型**"对齐；课程之间阶段**数量**可以不同（课型不同），但**同名通用阶段的目标与产出类型恒定**。P 号只是**实例编号**。

| 通用阶段 | 人形机器人基础（理论课实例） | X 课程（含实训实例） |
|---|---|---|
| 教学设计 | P1 教案 v2 | P4 教学设计 |
| （教学物料，课型相关） | P2 演示物料 | 实训素材（notebook / 手册） |
| **课件详细设计 → 产《课件设计蓝图》** | **P3** | **P5** |
| 课件物化 → 产 `.pptx`（执行者无关） | 交付外部 AI 工具 | P6（本 Agent 流程） |

> 用户原话锚点："{人形机器人基础} P3 的目标与 {X 课程} P5 是一致的"。

## 二、阶段定义

| 项 | 定义 |
|---|---|
| **阶段名（通用）** | **课件详细设计** |
| **一句话目标** | 把已定稿的**教学设计**，转成一份**结构化的课件设计蓝图**——供人审核 + 供下游任意生成器物化 |
| **上游输入** | 教学设计（教案 / 目标—证据—活动对齐表）+ 教学物料 + 风格规范 + 大纲（呈现优先级 / 概念准入） |
| **产出（唯一）** | **一份文档**：《课件设计蓝图》（`.md`） |
| **闸门** | **确认**（审"体例 / 完整性 / 对齐 / 四准则"） |
| **本阶段边界** | **只出文档，不出 `.pptx`** |
| **下游（本阶段之外）** | **课件物化 · `.pptx`：执行者无关**——① 外部 AI 工具、② 本研发 Agent（按阶段流程）、③ 人工排版，皆可。两个过程都真实存在，标准不得写死执行者 |

**为什么产出是"文档"**（五条价值）：

| # | 价值 | 落到的机制 |
|---|---|---|
| 1 | 格式可校验 | 固定字段 + 体例 → 可写成模板 + 自检清单，甚至机器检查 |
| 2 | 内容可查漏 | 页面清单 vs 时间轴、每页挂环节与目标 → 可机械核对覆盖 |
| 3 | 跨课程共性模板 | 理论课 / 实训课共用同一骨架，字段按需裁剪 |
| 4 | 人机皆可读的交接契约 | 教师看得懂、下游 AI 吃得进 → 换执行者零成本 |
| 5 | 守住层级边界 | 蓝图属**教学决策层**；`.pptx` 属**呈现渲染层**。研发资产只到蓝图为止 |

## 三、产出文档结构 · 《课件设计蓝图》

> 一份文档，含 **8 节**。**§A / §B 是"交接头"**，**§5 是"反向更新建议"**，其余为正文。

| 节 | 名称 | 内容 | 面向 |
|---|---|---|---|
| **§0** | 元信息 | 课程 / 课时 / 对应教案版本 / 时间轴总长 | 人+机 |
| **§A** | **生产上下文 · 交给下游生成器** | 一段可直接复制的**提示词块**（机器可读的生产约束） | 下游 Agent / 工具 |
| **§B** | **生产准备 · 交给讲师/操作者** | 人的准备清单（素材 / 文字纪律 / 校对点） | 人 |
| **§1** | 页面清单（框架层） | 序号｜章节｜**对应环节**｜**对应内容块**｜页型｜教学动作｜**对应目标**｜时间区间｜**预估时长** | 人+机 |
| **§2** | 逐页详细设计 | 页标题 / 副标题 / 核心要点 / **对应环节** / **对应目标** / 配图需求 / 配表需求 / 配色 / 页脚 / 演讲备注要点 | 人+机 |
| **§3** | 配图 / 配表清单 | 页｜类型｜**来源类型**｜来源需求｜**授权·替换时机**｜状态 | 人+机 |
| **§4** | 自检记录 | 勾选项 + 结论（未过项留痕） | 机检+人 |
| **§5** | **反向更新建议** | 回退上游的登记项（时长 / 重难点 / 其他）——见 §四 准则二、三 | 人 |

### §A 生产上下文（模板 · 交给下游生成器）

```text
【课件生产上下文 · 供下游生成器/Agent 使用】
- 课程/课时：{{课程名}} {{课时}}｜{{时长}}分钟｜{{学段/受众}}
- 交付目标：生成 16:9 课件（.pptx），共 {{N}} 页；严格按《课件设计蓝图》§2 逐页设计
- 必须遵守的呈现规范：
  · 配色：{{配色角色说明，含 HEX}}
  · 正文 ≥36px；一页一动作；核心要点目标 2–3、硬上限 4；主图示 ≤1；新增概念 ≤1
  · 页脚格式：Ln · 起-止′ 环节名
- 术语/缩写边界：{{本课禁止出现的缩写与术语}}
- 对齐不可丢失：每页须保留其「对应目标」（{{T1–Tn}}），写入演讲备注
- 覆盖不可丢失：页数/页序已按教学设计的环节覆盖与重难点加权定死——不得增删页、不得改页序
- 文字纪律：全文过《去AI化表达通用规则》
- 素材引用：配图见 §3（已产 SVG 路径 / 待绘图规格 / 网络图出处）

```

## 四、课件设计准则（四条保障）★ 教育专家 / 专业教师视角

> 这四条是"**课件设计是否合格**"的判据，**全部可核查**。前两条管"**接得住**"（不漏、不拧），后两条管"**教得好**"（重点足、形象化）。

### 准则一 · 覆盖无遗漏（内容块级双向追溯）

- **要求**：教学设计的**每一个"内容块 / 教学步骤"**都必须被蓝图的**至少一页**承载；且**每一页**都能追回它的来源内容块、环节与目标。
- **机制**：§1 页面清单增列「**对应环节** + **对应内容块**」；与 §2 的「对应目标」共同构成"**内容块 ↔ 页 ↔ 目标**"追溯矩阵。
- **判据（机检）**：① **内容块覆盖 = 100%**（无内容块落空）；② **孤儿页 = 0**（每页都追得到内容块）。
- **粒度**：覆盖**不在环节级**检查——环节级太粗（6 个检查点，8 页也能"通过"）；应下到**内容块级**（20+ 个检查点，欠拆藏不住）。

### 准则二 · 时长一致性 + 反向更新（双向流程）

- **要求**：蓝图的页数与内容量要与教学设计各环节的**时长**对得上；对不上时**不是硬塞进课件，而是回退上游**。
- **机制**：§1 页面清单增列「**预估时长**」（按页、并按环节 rollup）；与教学设计 §4.1 速览表的**逐环节时长对账**。
- **判据**：单环节"设计所需时长 − 规划时长"偏差 **> ±15%**（默认阈值，可调）→ **必须**在 §5 反向更新建议登记，给出四选一建议：**扩 / 缩时长 ｜ 拆环节 ｜ 精简内容 ｜ 移到课后**。
- **页数密度基准（不按环节数定页数）**：讲解 / 信息类 **≥2 分钟/页**；一事件一页（2–3 分钟）；关键问题可**连续两页仅差问题文字**；45′ 课量级 **≈18–22 页**。**页数由内容块导出**。
- **意义**：课件设计是把时长估准的最好时机（材料一落纸就知道讲得完不完）→ 本阶段由此成为**反向修订教学设计的正式入口**。

### 准则三 · 重难点加权（更形象、更多页）

- **要求**：重难点目标所在的环节，对应课件页数**更多**、呈现**更形象**。
- **重难点来源**：① 教学设计**显式标注**（若有）；② 缺标注时，**默认取"布鲁姆层次较高（应用 / 分析 / 评价）的目标"及其所在环节**、以及**大概念所在环节**。
- **机制**：重难点环节 → 页数**加码**（页数占比 > 其时长占比）+ 优先用「**问题链三页（提问 → 引导 → 解答）**」+ 多图示 / 多例子。
- **判据（机检）**：每个重难点环节的"**页数 / 时长**"比 ≥ 全课平均；且至少含 **1 处形象化**（图 / 表 / 类比 / 问题链）。
- **缺口处置**：教学设计 v2 体例**无"重难点"字段**（已知）→ 若判不清，**在 §5 反向更新建议**中提出"**建议在教学设计补标重难点**"。本阶段**不擅自改上游**，只提议。

### 准则四 · 生动形象（图文配套 + 图示三来源）

- **要求**：课件不是把教学设计"搬上屏"，而是**结合学习者基本情况**（如高职大一、零基础、抽象概念多），把知识**形象化**。
- **图文配套**：抽象概念 / 过程 / 关系 → **必须**配可视化（图 / 图表 / 类比）；照做类步骤可纯文字。依据：*抽象过程用示意/动画、操作演示用实拍/录屏、知识梳理用结构图*。
- **图示三来源**（§3 配图清单须标"**来源类型**"，各有规格）：

| 来源类型 | 适用 | 须注明 |
|---|---|---|
| **AI 规划生成**（示意图 / 概念图 / 数据图 / SVG） | 抽象原理、结构、流程、对比 | 配图四要素（主体 / 关键标注 / 回答什么问题 / 来源） |
| **互联网引用真图**（实拍 / 历史照片 / 公开图） | 历史事件、真实场景、人物 / 产品实照 | **出处链接 + 授权 / 版权状态**（无授权 → 改用可商用图或自绘） |
| **产品截图 / 实拍**（Studio 界面、K1 实物） | 真实工具、真实设备 | **获取方式 + 授课替换时机**（如"授课替换为实时投屏"） |

- **判据（机检）**：抽象页 **100%** 有配套图 / 表；每张图**来源类型已标**；网络图**无授权风险**。

## 五、单页信息量口径（回答"要点是什么级别"）

技能 `courseware-page-design` 原文口径：**核心 bullet ≤ 4 条** + **正文行数 ≤ 6 行** + 主图示 ≤ 1 + 新增概念 ≤ 1。
"4" 是**上限**。为消除歧义，此处把"要点"的三级粒度**显式定义**：

| 级别 | 单位 | 口径 | 上限 |
|---|---|---|---|
| **L0 · 页** | 教学动作 | 一页只做一件事 | 1 |
| **L1 · 核心要点（bullet）** | **信息单元（chunk）**——一个可独立成句、独立上屏的要点，典型形态="关键词（+短说明）"或一个短句 | 并列信息单元数 | **目标 2–3；硬上限 4** |
| **L2 · bullet 内子项** | 不再嵌套 | 禁止在 bullet 内再套子 bullet（视觉 1 条 ≠ 认知 1 条 → 隐性超载） | 0 |
| 正文行数 | 视觉行（含换行） | 与 bullets 双重约束 | ≤6 行 |

> **"要点"≠ 一行文字，也≠ 一个子项**。判断单位是**语义单元**：一个概念 / 一个事实 / 一步操作 = 1 条。

**满 4 条时的复核三问（负荷判据）**：
1. 这条是**知识必需**，还是并列装饰？（装饰 → 删）
2. 能否把并列项**降级为一张图示 / 一张表**？（能 → 降级）
3. 是否其实是**两个教学动作**？（是 → 拆页）

**依据**：阶梯教室投影、正文 ≥36px，一屏容量有限；工作记忆容量约 **4±1 chunk**，塞满 4 条即顶上限。放不下的正确解法是**拆页或转图示**，绝不是缩字号。

## 七、规则（渲染层）

分页 / 配色 / 配图 / 自检的规则正文在技能 `courseware-page-design`。本节只列需**补强**的三条：

1. **蓝图 vs 教学设计的职责边界**：页面只承载"**要点 + 图示 + 关键词**"，讲解**沉到演讲备注**，不搬上页面正文。
2. **负荷判据**：见 §五"复核三问"（替代单纯计数）。
3. **课首"旧知检索"页型**：用 1 页、1–2 个问题唤醒上一课（问什么由教学设计定）。

> 这三条**尚在技能外**，需补进技能 references——列为第一批动作。

## 八、闸门 · 确认（以"使用教师视角"发起）

- **停点**：蓝图产出 → **停**，交**使用教师**视角审核。
- **两问（过闸标准）**：① 这个**拆解**，是否**有利于讲解对应知识**？② 是否**形象化**——文字 + 图等多元素把知识**可视化传达**？
- 辅以自检：体例 / 完整性 / 对齐 / 四准则。
- 通过才进下游（物化 / 考核）；不通过就改，改完再停。
