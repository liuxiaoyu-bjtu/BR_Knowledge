# 教案体例规范 v3（草案）

> **一句话**：把设计者脑中"目标 → 怎么验证 → 用什么活动"的隐式链，落盘成教案字段；再把"环节"往下切一层「**内容块**」，让课件有颗粒度可依。
> **适用**：人形机器人基础（8×45′ 大课，讲授 + 演示，不写代码）；体例本身可复用于 X 课程及其后课程。
> **理论依据**：建构性对齐（Biggs）｜逆向设计 UbD 阶段 2 评估证据先于阶段 3 活动（Wiggins & McTighe）｜布鲁姆修订版｜认知负荷（Sweller）｜九大教学事件（Gagné）/ BOPPPS。
> **表达**：所有话术要点须通过《去 AI 化表达通用规则》审校。

## 〇、v3 相对 v2 改了什么

| # | 变化 | 为什么 |
|---|---|---|
| 1 | **新增「内容块分解」层**（每个环节块内） | v2 只到"环节"，课件没有更细的上一级可依，就退化成"一个环节一页"——欠拆的根因 |
| 2 | **新增「本课重难点」字段**（§1.3） | 课件要按重难点加权，但 v2 无处可标，下游只能靠猜 |
| 3 | 逐环节块模板插入「内容块分解」表 | 内容块紧贴环节与话术，读起来不断链 |
| 4 | 填写红线加两条 | ① 内容块须能"一块导一页"；② 重难点须显式标注 |
| 5 | 与下游接口更新 | P3 课件不再只读"环节"，而是读"内容块"导页 |

> v2 的全部可用内容（话术、演示脚本、图示规格、FAQ、高职落点、读本要点、两种交付版本）**原样保留**，v3 只做加法。

## 一、教案整体结构（骨架）

```
0. 元信息           课程 · 模块 · 学段/班级 · 学时 · 授课形式 · 前置 · 依据 · 阶段
1. 教学目标         【大概念与基本问题】→【学习目标（编号/维度/布鲁姆层次）】→【本课重难点】 ★v3新增末项
2. 目标—证据—活动 对齐表   验证方式 · 观察信号 · 承载环节                    （v2 新增）
3. 课前准备         授课环境 · 设备 · 网络 · 软件 · 课程资源包
4. 逐环节教学设计    【速览表】+【内容块分解】+【块头 + 块状正文】             ★v3新增中项
5. 演示脚本         操作要点 · 安全注意
6. 图示规格         P2 物料制作依据
7. FAQ             学生高频疑问 + 标准回答
8. 高职落点         "这对将来干什么有用"
9. 本课读本要点      P5 埋点
```

> ★ 为 v3 新增或改造的部分。**§1、§2、§4 三处共同构成"目标—活动—评估"对齐的落盘；§4 的「内容块」是课件导页的唯一来源。**

## 二、逐节填写规范

### §1 · 教学目标（大概念/基本问题 → 目标 → 重难点）

**1.1 大概念与基本问题**（目标的来源，先写）
- **大概念**：一句话，本课要让学生带走的那个"大观念"。
- **基本问题**：一个贯穿全课的问题，**首屏抛出、收束回收**。

**1.2 学习目标**（由 1.1 细化而来）

| 编号 | 维度 | 学习目标（学完后能… + 标准） | 布鲁姆层次 |
|---|---|---|---|
| T1 | 知识 | … | 记忆 / 理解 / 应用 / 分析 / 评价 |
| T2 | 能力 | … | … |
| T3 | 素养 | … | …（素养落到**具体行为**，不写空洞口号） |

- 目标动词必须可观测（说出、解释、复述、指认、举例、判断…）；**禁用**：了解、掌握、熟悉、知道、懂得。
- 编号 T1/T2/T3 供后面各表引用。

**1.3 本课重难点**（★v3 新增——课件加权与讲解加力的依据）

```
- 重点：T_ —— 因为……（本课必须让全班拿走的东西）
- 难点：T_ —— 因为……（学生最容易卡住 / 最容易误解的地方）
```

- **重点 ≠ 难点**：重点指"必须掌握、值得多花时间"；难点指"认知门槛高、易卡壳"。二者可以重合，也可以分开。
- 缺此标注时，下游课件阶段只能按"布鲁姆高层次 + 大概念所在环节"**默认推断**——能标就标，别让下游猜。
- 一般 1 个重点 + 1 个难点；确有并列可多标，但**不超过 2 + 2**，否则等于没标。

### §2 · 目标—证据—活动 对齐表（本课骨架，最重要）

| 编号 | 验证方式（怎么知道达成的） | 观察信号（学生做什么 = 通过） | 承载环节 |
|---|---|---|---|
| T1 | 环节_ 提问 / _ | 能说出…… | 环节_ |
| T2 | … | … | … |

- **填写顺序即设计顺序**：先写目标（§1）→ 再想"怎么验证"（本表）→ 才定活动/环节。这是 UbD 阶段 2 先于阶段 3。
- 每条目标**至少**一个验证方式、一个观察信号；**观察信号必须写"学生的行为"**，不写"学生理解了"。
- 一条目标可由多个环节验证；若某条目标填不出"观察信号"，说明它不可测——回 §1 重写。

### §3 · 课前准备（授课环境与物料）

> 这一节写给**备课 / 授课**的老师：开课前要准备什么环境、设备、软件、资源。**不要**写成课程开发阶段的物料产出清单（那些多在课件 / 物料制作时完成）。

| 类别 | 要准备什么 | 说明 |
|---|---|---|
| 教室环境 | 投影大屏、音响、灯光 | 是否需放视频、是否需要遮光 |
| 设备 | 机器人实物 / 备用电源 / 演示道具 | 是否上台、是否需要提前开机 |
| 网络 | 教室 WiFi 是否与机器人同网段 | 跨网段是常见翻车点，必要时备网线直连 |
| 软件 | 演示所需软件是否已装、版本、登录 | 如 Booster Studio |
| 课程资源包 | 本节课件 / 视频 / 图示是否已就位并试播 | 提前到教室电脑上试一遍 |

### §4 · 逐环节教学设计

**4.1 环节速览表**（放 §4 开头，供一眼纵览全课节奏）

| 环节 | 时长 | 内容概述（一句话） | 关联目标 |
|---|---|---|---|
| 1 | 0–5′ | 本环节讲什么 / 做什么，一句话说清 | T_ |
| 2 | … | … | … |

> 第 3 列写**内容概述**（这个环节的内容是什么），**不写**"呈现新知"这类每课雷同的教学事件；教学事件只在下面的块头里作设计标注。

**4.2 内容块分解**（★v3 新增，**课件导页的唯一依据**）

> **什么是内容块**：环节内部一个**可独立成句、可独立上屏**的教学步骤或信息单元。它夹在"环节"（太粗）和"一句话"（太碎）之间，是课件分页的**直接来源**。

- **粒度判据（一块 ≈ 一页）**：
  - 一个内容块，应当在课件上**讲得满、又不挤**——大致 **1 页**。
  - 若"一块"在课件上要摊成 2 页以上 → 说明它其实是**两个块**，拆开。
  - 若"两块"在课件上只能挤进 1 页 → 说明它们本就是**一块**，合并；或本来就该退回环节层。
- **每块必填三样**：一句内容（讲什么 / 做什么）+ 学生活动 / 提问 + 预估时长。
- **编号**：`环节号.序号`（如 `2.1`、`2.2`），供课件 §1 页面清单逐页回指。
- **内容块是"教学决策"**（讲几个点、每点给多久、学生做什么）；**怎么上屏、怎么配图是"呈现决策"**——留给课件阶段，此处不越界。

**4.3 逐环节块（块头 + 内容块分解 + 块状正文）**

> **为什么用"块"不用大宽表**：环节里装着两种信息——**字段型**（时长 / 教学事件 / 关联目标 / 观察信号，短、可枚举）和**叙述型**（话术成段、需原样朗读）。前者适合表格，后者适合文字块。硬揉进一张大宽表，话术会被压成几十行的长单元格，朗读和投屏都难受。

```
### 环节n · 环节名 ｜ 起–止′ ｜ 教学事件：___
**关联目标**：T_　　**观察信号（学生）**：___（写"学生做什么"）

**内容块分解**（★ 课件导页依据；一块 ≈ 一页）
| 块 | 一句内容（讲/做什么） | 学生活动 / 提问 | 预估时长 |
|---|---|---|---|
| n.1 | ___ | ___ | _′ |
| n.2 | ___ | ___ | _′ |

**教师行为**：
**话术要点**：
> （原样保留，可多段；须过去 AI 化）
**学生活动 / 互动**：（学生做什么 + 组织方式）
**设计意图**：
**本环节教学重点注意**：
```

- **内容块时长之和 = 本环节时长**（对账不上的，回 4.1 速览表重估）。
- **互动并入此处**：不再单设"课堂互动设计"一节。每个互动写在"学生活动 / 互动"里，其判读标准即"观察信号（学生）"。
- 45 分钟课**至少 2 个全员参与点**。

### §5–§9

演示脚本、图示规格、FAQ、高职落点、读本要点——沿用 v1 / v2，此处不重述。

## 三、填写红线（出稿自检）

1. **可观测**：无"了解/掌握/熟悉"类目标动词。
2. **三对齐**：每条目标都有验证方式 + 观察信号；每个环节都挂到目标。
3. **层次一致**：目标是"应用/分析"→ 必须有动手/指认/对比类活动，不能全程只听讲。
4. **观察信号可判**：写"学生做什么"，不写"学生懂了没"。
5. **时间闭合**：各环节时长加总 = 学时；**且每个环节内，内容块时长加总 = 环节时长**。
6. **内容块可导页**（★v3 新增）：每块能对应到课件的 1 页；块数 ≈ 该环节课件页数（重难点环节允许块数 < 页数，即一页再拆）。
7. **重难点已标**（★v3 新增）：§1.3 有显式重点 / 难点，不让下游推断。
8. **概念准入**：本课不该出现的缩写/概念不提前甩（见大纲"前沿概念准入通则"）。
9. **话术去 AI 化**：过《去 AI 化表达通用规则》。

## 四、与下游的接口

| 下游 | 从本表取什么 |
|---|---|
| **课件详细设计 → 《课件设计蓝图》** | **以「内容块」逐块导出页**（一块 ≳ 一页；重难点环节可一页再拆）；每页标注"对应内容块 + 对应环节 + 对应目标"；据 §2 观察信号把问题链设计成**目标验证提问**；§1 大概念/基本问题成首屏与收束页；**§1.3 重难点**决定哪些页加码、哪些配图更足 |
| **P4 考核** | 终结性评估与 §2 的验证方式**呼应**（课堂验证什么，期末就考什么层次） |

> **上下游口径**：教案产出「内容块」（教学决策）；课件把内容块翻成「页」（呈现决策）。**教案不越界设定"几页、什么版式"，课件不越界改动"讲几个点、每点多久"。**

## 五、两种交付版本（设计版 / 纯净版）

同一节课的教案，最终产出**两份**：

| 版本 | 面向谁 | 特征 |
|---|---|---|
| **设计版** | 课程开发 / 教研 | 含设计备忘、开发状态、交叉核对，便于复核与迭代 |
| **纯净版（可公开交付版）** | 授课教师 / 对外交付 | 删去设计过程痕迹，只留干净的课程内容 |

### 纯净版清洗清单

| 项 | 设计版 | 纯净版 |
|---|---|---|
| 元信息 | 课程 + 模块 + 学段 + 授课形式 + 前置 + 依据 + 阶段 | 只留 **课程名 + 学时**；授课形式留简版（删"学生不进机房、不写代码"）；删 模块 / 学段班级 / 前置知识 / 大纲依据 / 阶段 |
| 层次走向 memo | 保留 | 删除 |
| 对齐表标题 | 目标—证据—活动 对齐表（本课骨架） | 目标—证据—活动 对齐表 |
| 内容块分解 | 保留 | 保留（授课老师按块讲，用得上）；删"★ 课件导页依据"这类开发字样 |
| 交叉核对 | 保留 | 删除 |
| 开发状态字样（P1/P2/P3…、待确认、草案、闸门） | 保留 | **全部删除** |
| 演示脚本 / 图示规格 / 高职落点 / 读本要点 / 附（改动表） | 保留 | **不提供** |
| 待定项 | 设计意图、块头"教学事件"是否随纯净版保留 | 待定（见 §七） |

> 清单"包括但不限于"：凡属课程开发过程、而非课程内容本身的字样，一律清除。

### 存放与阶段

- **存放**：设计版在 `教案/`；纯净版建议另置 `06_对外交付/`（或命名 `<课名>_教案（交付版）.md`）。
- **阶段**：建议新增 **P6 · 对外交付版（纯净版）统稿**，置于 P5 之后。
  - 理由一：纯净版是设计版的**派生清洗**，母本未冻结就做会返工。
  - 理由二：教案、考核、读本等多份物料都要出纯净版，**集中在 P6 一次清洗**，口径统一、省重复劳动。
  - 注意：清洗含去 AI 化与口径判断，不是纯机械删除，需人过一遍。

## 六、填写示例

完整示例见 `教案/L1_智能的新形态_教案-v3.md`（设计版）。核心片段：

**重难点（§1.3）**

```
- 重点：T1 —— "离身会说 / 具身会做"是全课记忆点，后面每一课都建在它之上。
- 难点：T3 —— 里程碑要记的不是年份，而是"间隔在变短"这个规律，初学者容易只当历史流水账。
```

**内容块分解（§4.2）**

| 块 | 一句内容 | 学生活动 / 提问 | 预估时长 |
|---|---|---|---|
| 2.1 | ChatGPT / 豆包这类 AI 很能聊 | 听讲 | 2′ |
| 2.2 | 但让它"挪个水杯"，它只能说"我做不到" | 点 1-2 人猜原因 | 2′ |

**环节块**

```
### 环节2 · 会说话 vs 会行动 ｜ 5–15′ ｜ 教学事件：呈现新知
**关联目标**：T1　　**观察信号（学生）**：能说出"它没有身体 / 动不了手 / 走不了路"

**内容块分解**
| 块 | 一句内容 | 学生活动 / 提问 | 预估时长 |
|---|---|---|---|
| 2.1 | ChatGPT / 豆包很能聊 | 听讲 | 2′ |
| 2.2 | 让它"挪水杯"，只能说"我做不到" | 点 1-2 人猜原因 | 2′ |

**教师行为**：讲授 + 类比（ChatGPT / 豆包 vs K1）
**话术要点**：
> "你们现在用的 ChatGPT、豆包，都很能聊。但让它'挪个水杯'，它只能回你一句'我做不到'。为什么？"
**学生活动 / 互动**：听讲 + 随口应答；末了请 1 人复述区别
**设计意图**：建立本课第一记忆点
**本环节教学重点注意**：这句话建议板书或投屏
```
