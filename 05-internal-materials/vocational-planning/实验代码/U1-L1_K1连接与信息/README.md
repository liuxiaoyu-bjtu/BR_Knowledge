# U1-L1：认识 K1 — 首次连接与信息探索

> **所属课程**：X 课程（具身智能机器人实践 / 人形机器人开发实训）
> **单元**：U1 机器人开发入门 · 课时 1
> **实验时长**：约 20 分钟
> **难度**：★☆☆☆☆（入门）

---

## 一、实验目的

1. 完成 BoosterOS SDK 安装，建立与 K1 机器人的首次连接
2. 通过 SDK 接口探索 K1 的"身份信息"（型号、序列号、固件版本）
3. 了解 K1 的关节体系和预定义动作库
4. 建立"SDK = 操作机器人的统一入口"的认知

---

## 二、前置知识

| 知识点 | 是否必备 | 说明 |
|---|---|---|
| Python 基础（import、print、变量） | **必备** | 本实验假设学生已能独立运行 `.py` 脚本 |

## 三、实验设计说明

### 3.1 设计思路

本实验遵循"先看不动"原则——学生第一次面对 K1 时，**不操作机器人运动**，而是以"探索者"身份通过 SDK 接口获取静态信息：

```
连接K1 → 读取身份信息 → 浏览关节列表 → 浏览动作列表 → 查看当前状态
```

每步都有明确的打印输出，学生可以边看边理解 K1 的"身体结构"。

### 3.2 教学衔接

| 方向 | 说明 |
|---|---|
| **前接** | 本课时是课程起点，无前置实验（假设学生已上过通识理论课，了解基本概念词汇） |
| **后接** | U1-L2（ROS2 通信基础）将深挖：这些信息是通过什么机制从 K1 传到你的 Python 脚本的 |
| **跨单元** | U4-L3（状态监视器）将基于本课的 `get_mode()` 和 `get_battery()` 构建循环监控 |

### 3.3 关键 API（本实验使用的 SDK 接口）

| API | 类型 | 说明 |
|---|---|---|
| `BoosterRobot()` | 构造函数 | 创建机器人连接实例（首次调用自动建立 ROS2 节点） |
| `robot.robot_info` | 属性 | 返回 `RobotInfo`：manufacturer / model / serial_number / firmware_version |
| `robot.list_joints()` | 方法 | 返回 `list[JointInfo]`，每个含 name / limits / max_torque / max_velocity |
| `robot.list_actions()` | 方法 | 返回 `list[ActionInfo]`，每个含 id / type / duration / interruptible |
| `robot.get_mode()` | 方法 | 返回当前模式：`"damping"` / `"prepare"` / `"walk"` / `"custom"` |

### 3.4 知识缺口标注

| 缺口 | 处理方式 |
|---|---|
| `pip install` 操作 | 本 README 步骤 1 给出明确命令，无需前置讲授 |
| Python 导入机制（`from ... import ...`） | 作为编程常识，脚本中注释说明即可，无需单独课时 |
| `list[xxx]` 类型标注 | 不在本课讲解，学生只需理解"返回一个列表"即可 |

## 四、实验步骤

### 步骤 1：安装 BoosterOS SDK（首次）

```bash
# 在终端中执行（仅第一次需要，后续课时无需重复）
pip install boosteros
```

**验证安装**：
```bash
python -c "from boosteros.robots.booster import BoosterRobot; print('SDK 安装成功')"
```

### 步骤 2：连接 K1

确认 K1 已开机，学生电脑与 K1 连接同一 WiFi。

## 六、思考题

1. K1 有 22 个关节，观察关节名你能大致推断每个关节在身体的哪个部位吗？（提示：AAHead/Head/ALeft/Left/...）
2. 关节限位（`limits.min` / `limits.max`）的单位是弧度（rad），`1.57 rad` 约等于多少度？为什么头部关节的限位通常比腿部关节小？
3. 10 个预定义动作中，哪个动作你觉得最有趣？如果你可以命令 K1 做一个新动作，你会设计什么？
4. `get_mode()` 返回的 `"damping"`、`"prepare"`、`"walk"` 三种模式分别对应机器人的什么状态？你觉得执行运动控制前应该处于哪个模式？
