# U2-L4 教学设计（教师用）

## 一、课时目标

1. 能解释剩余电量、电压和充放电状态，区分 `is_low` 与 `is_critical` 两条告警线。
2. 能读懂摔倒状态，说明调用起身任务前需要检查的状态与现场条件。
3. 能定时读取电池、摔倒状态和当前模式，补全电量与模式的联合判断，并用给定情景检查各分支的输出。

本课以状态综合判断结束 U2。学生必做包括读取、显示、补全分支和情景验证；起身动作只作教师有条件演示。

## 二、重难点

| 类型 | 内容 | 教学建议 |
| --- | --- | --- |
| 重点 | 电池字段与告警线 | 读出三个电池字段；说明低于 10% 时 `is_low`、`is_critical` 同时为 True |
| 重点 | 摔倒状态与起身条件 | 区分五种状态；能说明 `fallen`、`recoverable` 与现场确认缺一不可 |
| 重点 | 电量与模式的联合判断 | 补全 `and` 条件，通过四个假设情景检查三条分支 |
| 难点 | 模式不能证明实际在运动 | `walk` 为可运动的控制模式，静止站立也可能处于该模式 |
| 难点 | 状态综合与保护动作的区别 | 当前程序只打印提示；学生能说明告警后仍需教师按流程处理 |
| 难点 | 循环间隔与采样遗漏 | 读数、输出和等待共同构成间隔；可能漏过短暂状态，不要求实现精确定时 |

## 四、教学环节详解

### 环节 1·导入（0–3 分钟）

- 【提问】：“电量同为 15%，一台处于 walk，一台处于 prepare。都需要充电，提示内容应该一样吗？”
- 【话术】：“电量决定是否触发低电量告警，模式帮助我们说明接下来该怎样处理。今天把这些条件写进程序，再检查不同条件下的输出。”
- 【注意】：本课不安排走路。用给定情景讨论，不切换真实设备来制造情景。

### 环节 2·电池与读取（3–11 分钟）

- 【投影】：实训手册 §一的电池量表和返回值属性表。
- 【步骤】：按页面顺序先连接，再 `print(robot.get_battery())` 查看全貌，然后读电量、电压、充放电状态、`is_charging` 和 `is_low`，填写 §六前两行。
- 【核心概念】：电量用于估计剩余可用时间；电压反映当前供电情况，单次读数不能诊断电池健康；充放电状态可能为 Charging、Discharging、Full、NotCharging 或 Unknown。部分字段可能为 None，照实记录。
- 【板书】：`is_low：<20%`；`is_critical：<10%`。低于 10% 时两者同时成立。
- 【话术】：“低电量时应结束运动、停稳并安排充电。我们不靠耗尽电量来测试。短时间电量不变，也不能说明机器人没有耗电。”
- 【提问】：“剩余电量 8% 时，两个布尔值分别是什么？”

### 环节 3·摔倒状态（11–17 分钟）

- 【投影】：§二的五种状态表。
- 【板书】：可能的过程 `normal → falling → fallen → getting_up → normal`；`unknown` 单列为未知。
- 【核心概念】：倾斜会改变姿态读数，但本课接口没有给出 K1 内部检测阈值和完整保护算法。不能用 pitch 的某个数值替代系统摔倒状态，也不能保证每次轮询都能看到全部中间状态。
- 【步骤】：先打印完整 `FallDownState`，再读 `state`、`recoverable`、`is_normal` 和 `has_fallen`。记录现场实际值。
- 【提问】：“读到 unknown，能否按 normal 处理？读到 fallen，是否就可以立即起身？”
- 【核心概念】：`get_up()` 返回不可取消的任务句柄。状态条件满足后，还需教师确认倒地姿势、设备情况和周围空间；任务提交不表示站立成功。
- 【安全红线】：学生不推倒、晃动机器人，不寻找触发摔倒的角度。

### 环节 4·综合判断（17–21 分钟）

- 【投影】：§三的电量与模式判断表。
- 【核心概念】：多传感器融合可以用于姿态、位置等估计。本课采用基础的多来源状态综合判断：电池读数、摔倒状态与模式共同支持判断，当前模式本身不是传感器测量。
- 【步骤】：先让学生预测 low=True、mode=walk 与 low=True、mode=prepare 的提示，再解释 `and`。
- 【提问】：“处于 walk 能否证明正在走路？prepare 下电量低是否可以不管？”
- 【话术】：“walk 说明控制模式，不能直接说明运动速度。两种模式下的低电量都要处理；walk 情景还需要提醒教师按流程结束运动、停稳。”

### 环节 5·状态监视器（21–27 分钟）

- 【步骤】：运行 §四 4.1 的三路单次读取，检查电量、摔倒状态与模式；再运行 4.2 的 10 轮循环。
- 【活动】：组内分别核对三列，记录首末轮值。保持机器人原有安全姿势，不为了看到变化而拨动它。
- 【核心概念】：每轮读取、输出后 `sleep(1)`；相邻两轮略长于 1 秒，序号只是轮次。若读取花 2 秒，间隔约 3 秒，短暂状态可能被漏掉。
- 【注意】：三项不变属于正常观察结果，不能要求学生填出变化。

### 环节 6·联合告警（27–36 分钟）

- 【步骤】：在 §五 5.1 第一格将 `if False` 改为 `if bat.is_low and mode == "walk"`。让学生解释为什么联合分支放在单独判断 `bat.is_low` 之前。
- 【活动】：先预测当前机器人会进入哪个分支，再运行真实读取循环；记录提示及其依据。
- 【步骤】：学生先填四个假设情景的预期提示，再把三条分支移入下一格，用 `low` 替换 `bat.is_low`，去掉真实电量和轮次显示，替换 `pass` 后运行。
- 【注意】：该格只用普通变量，不含运动调用。验证 True/walk、True/prepare、False/walk、False/damping；前两种都告警但提示不同，后两种不触发低电量告警。
- 【FAQ】：“为什么电量充足时还要用假设数据？”——真实读数通常只覆盖一条分支，假设数据可检查其余分支，无需耗电或切换模式。
- 【步骤】：逐行比较预期与实际输出，修正后再读一次真实状态。巡视检查联合条件、分支顺序和情景表，不以“程序跑完了”作为唯一标准。
- 【话术】：“这些输出只是提示。程序没有发出停止或保护指令，现场仍要按设备操作流程处理。”

### 环节 7·起身检查与收尾（36–40 分钟）

- 【步骤】：学生保持 `teacher_confirmed = False`，运行 §五 5.2，解释当前为何没有下发起身任务；回答思考题 2。
- 【安全红线】：仅在设备确实倒地、`state == "fallen"`、`recoverable` 为 True，且教师检查姿势、设备正常、周围 1 米无人后，才可由教师将确认变量改为 True 并亲自运行。学生不主动制造倒地。
- 【演示】：若现场恰有合适设备和条件，教师可演示起身，观察实际动作并重读摔倒状态与模式；没有条件时只做只读检查，本课仍可完成。
- 【FAQ】：“recoverable=True 是否保证起身安全？”——它只是系统状态条件，不能代替对周围障碍、人员和设备情况的检查。
- 【步骤】：演示后先切回准备模式（PREP），人工扶坐，坐稳后进入阻尼模式（DAMP）；未演示的组保持原有安全姿势。严禁从行走模式（WALK）直接切换到阻尼模式（DAMP）。

### 环节 8·检查与评价（40–45 分钟）

- 【活动】：核对 §六记录、7.1 检查点；独立完成 7.3 的 3 题。重点抽查第 3 题能否区分低电量在两种模式下的提示。
- 【注意】：未执行起身的组记录“未执行”，不要求补造动作结果。思考题 3、4 与扩展阅读课后完成。
- 【话术】：“U2 练习了通信、数据读取、姿态与位置解释，以及条件判断。下一单元开始读取图像、识别画面中的目标。”

## 五、板书设计

**电池与起身条件**

- `is_low：<20%`；`is_critical：<10%`，两者可以同时为 True。
- 起身状态条件：`fallen and recoverable`；现场条件：教师检查并确认。
- `unknown`：先检查数据和设备，不下发动作。

**联合告警与验证**

| low | mode | 提示 |
| --- | --- | --- |
| True | walk | 请教师按流程结束运动、停稳后充电 |
| True | prepare | 保持安全状态，安排充电 |
| False | walk | 未触发低电量告警，显示模式 |
| False | damping | 未触发低电量告警，显示模式 |

`if low and mode == "walk" → elif low → else`；本课仅打印提示。

## 六、学习评价

> 题目与实训手册 §7.3 一致。

1. 电量低于 10% 时，`is_low` 与 `is_critical` 会同时为 True。（判断）  
   **答案：√。**
2. 起身调用前应先确认 `state` 为 ______、`recoverable` 为 ______，并由教师检查现场。  
   **答案：fallen；True。**
3. 假设 `low = True`，分别令 `mode = "walk"` 和 `mode = "prepare"`。写出你的程序输出的两条提示，并说明为什么不能只判断 `low`。  
   **参考答案**：walk 提示按流程结束运动、停稳后充电；prepare 提示保持安全状态、安排充电。电量条件决定是否告警，模式条件用于区分处理提示。两种情景都需要充电。只写“都告警”未体现模式判断。

课堂操作评价另查：第一条联合分支已补全，四个假设情景输出符合预期，并能解释真实读数进入的分支。

## 七、教学资源与附件

- Jupyter、安装 boosteros 的 Linux 环境、K1、同一网络；本课不需要 Studio 组件。
- 课前检查电量充足、数据可用；告警分支统一用假设数据验证，不以真实低电量为开课条件。
- 学生必做仅需安全静止设备。无合适起身演示条件时，预先决定只做状态检查。

## 八、安全与设备准备

- 已完成 U1-L2、U2-L2、U2-L3；复习准备模式（PREP）、行走模式（WALK）、阻尼模式（DAMP）的使用条件。
- 状态读取与告警均不发运动指令，无需进入行走模式（WALK）；保持坐姿、趴姿或准备模式（PREP）站姿。
- 起身动作不可取消，由教师按环节 7 的全部条件决定是否演示；不保证起身一定成功，不为课程制造摔倒。
- 演示后先切回准备模式（PREP）、人工扶坐，坐稳后进入阻尼模式（DAMP）。未演示的组保持原有安全状态。
