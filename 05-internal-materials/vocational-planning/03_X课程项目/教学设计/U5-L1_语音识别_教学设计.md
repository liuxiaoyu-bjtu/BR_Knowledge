## 一、课时目标

1. 能区分录音与语音识别的输入、输出：录音得到声音的采样数据，语音识别将语音转成文字；转成文字后还需要结合语境理解意思。
2. 能说明采样率、声道数和采样格式的含义，并用它们估算 PCM 数据量与音频长度。
3. 能说明播放队列如何暂存声音块，比较不同队列容量下的写入等待与播放现象。
4. 能比较整句识别与流式识别的适用场景，并启动、观察和停止流式识别任务。

> 教学提示：从“录下来能回放，为什么还没有文字”引入识别。先用一段完整录音认识数据，再观察分块、队列和文字回调。公式始终带声道数：单声道为32000 B/s，本课K1三声道采音为96000 B/s。程序运行时间、声音数据长度和队列写入时间分别记录，不能互相替代。`threading.Event` 仅解释为停止采集的标志，不展开线程知识。

## 四、教学环节详解

### 环节1·声音数据与文字（0–4min）

【活动】阅读§一、§2.1。学生指出录音得到的内容和聊天时需要的文字有什么不同，用麦克风与扬声器的日常经验说明“能听见回放”不能证明机器已理解内容。

【核心概念】采样率是每个声道每秒取样次数；声道数是同时记录的路数；S16LE每个采样数值占2字节。PCM换算不含WAV文件头，不套用于MP3。

【活动】计算一秒单声道与三声道的数据量，再口算3秒三声道约有多少采样数据，保留估算用于回看实际录音。

【投影】拟展示：声音→采样数据→文字的关系图、三个参数及两行换算；依据：Notebook第1～5格；PPT定位待P5-B回填。

【提问】“从一路改成三路，一秒声音会变成三秒吗？得到文字以后，是否一定知道说话人的意思？”

### 环节2·录音、保存与回放（4–12min）

【步骤】运行STEP 01，连接并核对系统音量；说明0.5是当前实验设置。阅读§2.2，若已有录音，先检查并停止，不叠加启动。

【步骤】运行STEP 02，正常音量说一句话。核对开始、查询录音时长、停止并取得AudioData的顺序。运行STEP 03，读数据字段、打印格式和长度，保存my_voice.wav。

【活动】填写§6.1，比较按实际时长算出的PCM长度与len(audio.data)。文件大小含文件头，不能直接当采样数据长度。录音的实际时长可能与等待设置有差异，以对象字段为准。

【步骤】运行STEP 04回放，观察wait返回状态。仅SUCCEEDED说明成功完成；失败时结合error检查，不能依据固定打印或“没声音”猜测。

【投影】拟展示：start_recording→内存数据→stop_recording返回对象→save文件→play_sound播放；依据：Notebook第5～15格；PPT定位待P5-B回填。

【提问】“stop_recording返回的是文件名吗？保存成功能否代替播放成功？”

【安全红线】音量从较低值开始，播放前提醒同组。机器人保持固定，不为录音效果切换行走模式；本课无需运动收尾程序。

### 环节3·按块采音（12–19min）

【演示】用“水流分杯接取”的比喻说明连续声音按块读取：杯子对应一块，杯中仍是采样数据。块大小不是一句话的边界。

【步骤】运行STEP 05，采20块并累计字节；将总字节除以96000。阅读STEP 06后采60块，保留chunks用于后续两次播放，不在每次对照前重新录音。

【活动】根据3200字节一块估算约0.033秒、20块约0.67秒、60块约2秒，再与实际总字节核对。若块长度不同，按实际累计字节计算。

【核心概念】record_stream持续提供音频块；停止标志通知采集结束。音频数据包含的时长与运行这一格经过的时间不是同一个量。

【投影】拟展示：采样数据分块示意、3200÷96000的换算与20/60块对照；依据：Notebook第16～23格；PPT定位待P5-B回填。

【提问】“本次取20块为什么约0.67秒？把声道数漏掉，会把结果算大还是算小？”

### 环节4·比较播放队列（19–30min）

【活动】阅读§三播放说明，沿采集块→write→等待队列→扬声器找出暂存位置。将队列比作等待播放的杯子，指出队列满后如何处理由overflow决定。

【核心概念】block在满时等待；drop_oldest丢最早等待块；drop_newest丢新块。大队列增加暂存容量，不能保证永不等待，也不能直接推出实际播放延迟。

【步骤】运行STEP 07，先用queue_size=4，再用64，均保持overflow="block"、同批60块和相同格式。每次先确认原流已终止。写完先close结束输入，再wait等待排队声音播完；记录真实状态。

【活动】填写§6.2，记录全部块写入耗时、是否明显等待、完整性与最终状态。区分声音长度约2秒和写入耗时。旧输出可作已有现场例，不能把其数值当验收要求；以本次输出和听感为据。

【投影】拟展示：4与64个等待位置、满队列的三种策略、写完→close→wait→查状态的时间线；依据：Notebook第20～25格、§6.2；PPT定位待P5-B回填。

【提问】“写入很快，声音是否已经播完？close后为什么还需要wait？如果中途cancel，声音完整性会怎样？”

【注意】本实验先录后放，测全部块的写入耗时，不测实时端到端延迟。wait超时后任务可能仍在进行，保留原流检查，不直接重开。

### 环节5·两次流式识别（30–39min）

【活动】阅读§四，比较录好留言再处理与会议字幕边听边更新的需要。ASR将音频转为文字；整句与流式按输入、返回节奏理解，不将产品名称直接当算法分类。

【步骤】运行STEP 08，正常说一句约定的话，观察回调文字是否逐步变化。6秒是观察窗口。结束后cancel、有限wait并核对done，原任务未结束时先处理它。

【步骤】保持句子不变，运行STEP 09再说一次；记录语速、音量、环境变化与转写差异，按出现顺序填§6.3。最近回调不保证是最终整句，不补写未收到的文字。

【投影】拟展示：音频块→ASR→文字回调、留言/字幕对照、启动→观察→取消→终态核对；依据：Notebook第26～33格；PPT定位待P5-B回填。

【提问】“输出了一次文字，任务就结束了吗？cancel返回请求已提交，为什么还要看done？”

【注意】回调接收一个text参数。本课不增加recognize()或最终结果标志，不讲线程与锁。语音服务失败时如实记录状态，先排查配置和网络。

### 环节6·检查与应用判断（39–45min）

【活动】依据§6.4四项检查点，分别用录音数据、队列对照和识别记录举证。分组短答§6.5三问：同句对照、满队列策略、留言与字幕的识别需要。

【步骤】检查录音已经停止、播放和识别任务已经结束；未终态则保留句柄继续处理。关闭实验前确认无持续采集或播放。

【投影】拟展示：记录表关键列、四项检查点及三道思考题题干；依据：Notebook§六；PPT定位待P5-B回填。

## 五、板书设计

```text
麦克风 → PCM采样数据 → ASR → 文字 → 结合语境理解
PCM字节数 = 秒数 × sample_rate × channels × 每采样字节
16 kHz / S16LE：单声道32000 B/s；三声道96000 B/s
声音块 → write → 等待队列 → 播放
写完：close → wait → 状态；持续识别：cancel → wait → done
```

## 六、学习评价

采用Notebook§6.1～6.3记录、§6.4检查点和§6.5思考题，不新增延迟达标题。以下参考要点供教师使用，学生课件只呈现题干；P6学生PDF删除参考答案。

1. 能否区分音频、转写文字和理解，并从一组采音参数算音频长度？

   **参考要点：** 录音得到采样数据，ASR输出文字，文字仍需结合语境理解；时长等于数据字节数除以采样率、声道数和每采样字节数的乘积。本课三声道96000 B/s。
2. 能否用本组记录说明队列容量与满队列策略的取舍？

   **参考要点：** 比较相同声音在4/64队列下的写入耗时及完整性；block等待，丢弃策略可能损失声音。容量不等于实际延迟，不以微小函数调用时间证明发生阻塞。
3. 能否说明播放与识别如何收尾，并正确解释回调记录？

   **参考要点：** 播放流close结束输入后wait，成功才算播完；持续识别取消后等待并检查终态。回调可能更新，最近文字不保证最终；6秒只是观察窗口。
4. §6.5：为什么同一句话对照？队列满了怎么办？留言与字幕各适合怎样处理？

   **参考要点：** 同句减少内容差异，仍需记录环境等变化；按完整性、及时性要求选择等待或丢弃；留言可录完再处理，字幕需要持续更新。概念选择不等于本课已实现全部应用。

## 七、常见问题FAQ

**为什么三声道录音不是单声道时长的三倍？**

三路记录同一段时间的信号，增加的是数据量。换算时分母也包含声道数。

**close是不是关闭扬声器、丢掉剩余声音？**

播放流close表示不再输入新块，排队声音仍可继续播放；wait用于等任务结束。cancel用于请求中止，可能影响完整性。

**为什么没有识别文字也不能直接再开一次？**

是否输出文字与任务是否结束是两件事。先检查原任务状态，未终态时保留句柄并处理，避免叠加采集。
