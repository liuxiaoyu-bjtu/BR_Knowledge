# U3-L2 目标检测入门教学设计（教师用）

> 修订日期：2026-10-21。用于确认④复审；本轮受影响代码待补充真机核对。
> 【投影】记录拟由 PPT 展示的内容及 Notebook 依据，P5-B 再回填实际页码；现场运行记为【操作】或【演示】。

## 一、课时目标

1. 能说明目标检测的输入和输出：输入一张图像，输出若干条「类别 + 检测框 + 模型评分」结果，并说出它与整图分类的区别。
2. 能读懂检测结果中的 `class_name`、`confidence` 与 `bbox`，用 `plot()` 核对数字和画面位置。
3. 能把检测结果整理成 JSON 发布到话题，并在 BoosterStudio 图层中显示检测框、中心点和标签。
4. 能说清图像坐标系的约定：原点在左上角、x 向右、y 向下，并算出检测框中心的横向比例。
> 教学提示：本课使用预训练模型，不需要深度学习前置知识。学生要能把输入图像、结果列表和画面中的框对应起来，并读懂发布与图层绘制之间的数据关系。JSON 发布代码采用提供的示例，重点解释字段和顺序，不要求当堂从空白写出整个回调。

## 二、重难点

| 类型 | 内容 | 教学建议 |
| --- | --- | --- |
| 重点 | 整图分类与目标检测 | 分类判断整图内容，检测为目标提供类别、框和评分；不将分类限定为只能输出一个标签 |
| 重点 | 输入类型与检测结果 | 测试图片用 PIL；SDK `AnyImage` 先转数组。逐项核对 `class_name`、`confidence`、`bbox` 和画框结果 |
| 难点 | 持续发布与 Studio 图层 | 图像回调检测后发 JSON，附件脚本订阅后绘图；先发布、观察，再退订；不重复启动订阅 |
| 难点 | 坐标、比例与新旧帧 | 原点左上，x 右 y 下；移动目标后重新取图检测，空结果不沿用旧帧数据 |

## 四、教学环节详解

### 环节 1·检测任务与模型（0–4 分钟）

- 【投影】：拟展示同一图片的整图分类标签与多目标检测框对照；依据 §一、§2.1。
- 【讲解】：相机输出像素图像；预训练检测模型接收图像，输出若干条类别、检测框和评分。`Detection` 不负责拍照，本课调用已有模型，不开展训练。
- 【提问】：画面有多个人和物品时，只有整图标签还缺少哪些位置信息？说明框也是模型预测结果。

### 环节 2·固定图片检测（4–13 分钟）

- 【投影】：拟展示图片输入、结果列表、单个结果字段和对应检测框；依据 §2.2。
- 【操作】：依次运行读图、`Detection.list_models()`、创建默认检测器并检测、读取字段、`plot()` 五步。模型清单以当前环境为准，不把历史编号或类别能力当成固定配置。
- 【核对】：输入是 PIL 图片；返回值是列表，长度表示本次返回的结果数。让学生在图中找到一条 `class_name`、`confidence`、`bbox` 对应的框，不预设每个物体都能检出。
- 【准备衔接】：下一环节按 Notebook 步骤完成模型加载，比较固定图片与相机画面两种输入；本课代码在 §2.3 再次创建默认检测器。

### 环节 3·相机画面与输入输出（13–20 分钟）

- 【投影】：拟展示 `get_image()` → `to_numpy()` → `detect()` → `plot()` 的类型与数据流程，以及三个输出字段；依据 §2.3～2.5。
- 【操作】：连接机器人、取一帧、转数组并显示、检测、画框。SDK 对象不能直接传给检测接口。BGR 数组在 Matplotlib 显示时转为 RGB，送入检测器仍用原 BGR 数组。
- 【讲解】：类别和框来自模型预测，图层负责绘制。评分用于比较和筛选，不等于真实正确概率。没有输出达到阈值的结果，不能证明画面没有该目标；遮挡、尺寸、光照、视角和类别能力都可能影响结果。
- 【核对】：让学生说出模型输入和三项输出，纠正“检测器自己拍照”“图层自己找出框”的混淆。

### 环节 4·发布、图层观察与退订（20–31 分钟）

- 【投影】：拟展示图像回调—检测结果—JSON 话题—Studio 图层的流程和字段对应；依据 §3.1～3.3 及附件。
- 【操作】：§3.1 启动代码只运行一次。对照 `image_width`、`image_height`、`detections`，以及每条结果的 `label`、`conf`、`bbox_xyxy`、`x`、`y`。指出 `bbox_xyxy` 是两个对角坐标，来自左上角加宽高的换算。
- 【附件使用】：在 §3.2 打开《U3-L2_图层脚本.md》，复制到 Studio「机器人」→「图像」组件→「面板配置」→「图层」→「编辑脚本」。按附件流程观察框、中心点、连线、类别与评分。
- 【观察】：固定机器人，缓慢移动目标。图像与检测消息未经本课程序做严格时间同步，框可能落后或跳动；`queue_size=1` 与 `drop_oldest` 限制积压，不能消除推理耗时。
- 【结束】：先记录现象，再运行 §3.3 的 `unsubscribe()`，确认没有新的检测消息继续发布；残留图形不算新结果。本课不销毁正在使用的发布节点，也不调用 `rclpy.shutdown()`。如需重启发布，先退订并重启内核，再从连接步骤运行。

### 环节 5·坐标与比例观察（31–39 分钟）

- 【投影】：拟展示左上角原点、坐标轴、框中心和横向比例计算，以及空白记录表；依据 §四～五。
- 【操作】：在订阅已结束的状态下，固定机器人，把目标从画面左侧移至右侧；每次重跑 §4.3 的取帧与检测格。框与打印数值来自同一帧，按表填写目标数、类别、评分、宽高、横向比例与框的位置核对结果。
- 【计算】：手算一条 `center_x/图像宽度`，与代码输出核对；数组索引仍按 `[y,x]`。只有构图不变、同图等比例缩放时，比例才保持一致。
- 【讨论】：覆盖 §6.2 三题：缩放的条件、未检出的含义、换角度或遮挡引起的框中心变化。若空结果，记录“无”，调整场景后重新取图；不访问空列表或填写旧值。

### 环节 6·检查与评价（39–45 分钟）

- 【投影】：拟展示 §6.1 七项检查点和 §6.3 三题，不显示参考答案。
- 【检查】：逐组确认固定图和相机两种输入、字段解读、画框、JSON 发布/图层、坐标手算及退订均有记录。缺少图层观察或固定图实验的组保留补做项。
- 【活动】：学生独立作答；教师依据实际运行与记录判断目标达成情况，不以成功出现一个框代替全部任务。

## 七、常见问题 FAQ

| 问题 | 教师处理 |
| --- | --- |
| 相机有画面，图层没有框，先查哪里？ | 依次查发布订阅是否仍在运行、是否连接同一机器人/通信环境、话题名称和 JSON 字段是否匹配、当前帧是否有检测结果；区分无消息与有消息但目标数为 0。 |
| 退订后画面还有旧框，能继续记录吗？ | 旧图形不代表新检测。第四节运行单帧取图和检测格，以同一帧的打印值及画框结果填写记录。 |
