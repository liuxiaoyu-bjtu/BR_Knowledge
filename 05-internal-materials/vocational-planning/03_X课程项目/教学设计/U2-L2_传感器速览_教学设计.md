# U2-L2 传感器速览（教师用）

## 一、课时目标

1. 能说明相机、IMU、里程计、关节、电池五类数据分别测什么，以及常见 ROS2 消息类型。
2. 能比较快照式与订阅式取数，按属性表读出加速度、角速度、姿态、位置、关节角与电量。
3. 能说明 `subscribe_imu()` 与 `ros2 topic echo` 都会建立订阅，比较 Python 回调、命令行输出和退订方式。

本课建立数据地图，不在速览课展开姿态融合、里程计漂移和电池告警原理；这些内容分别在 U2-L3、U2-L4 处理。学生仍需完成全部读取和订阅操作。

> 教学提示：本课先给学生一张数据地图，再用快照和订阅各取一次。讲到能读字段、看时间戳和完成退订即可；姿态融合、里程计漂移和电池告警分别留给 U2-L3、U2-L4。相机只用 BoosterStudio 的「图像」组件观察，不在本课展开采图接口。

## 二、重难点

| 类型 | 内容 | 教学建议 |
| --- | --- | --- |
| 重点 | 五类数据与消息类型 | 用表格对照，学生从实际话题或文档中核对类型，不要求死记话题名 |
| 重点 | 快照和订阅 | 用 `get_imu()` 与 `subscribe_imu()` 对照；学生完成退订 |
| 重点 | 返回值字段 | 先打印对象，再依据属性表读本课字段；区分 SDK 属性和 ROS 消息字段可能存在整理 |
| 难点 | 时间戳与刷新 | 间隔一秒读取两次，记录时间戳；说明快照取当前可用数据，不等于硬件同步读取 |
| 难点 | 安全姿态观察 | 只读数据，保持原有姿势；拖动或改变姿态前由教师确认，不抬离支撑面 |

## 四、教学环节详解

### 环节 1·导入（0–4 分钟）

- 【提问】：“上一课看到的话题，里面传的到底是什么？”
- 【话术】：“今天先把五类数据认全，再比较一次读取和持续接收。读到的字段要回到对象和消息类型，不凭名称猜含义。”

### 环节 2·数据地图（4–10 分钟）

- 【板书】：相机–Image、IMU–Imu、里程计–Odometry、关节–JointState、电池–BatteryState。
- 【核心概念】：这些是常见 ROS2 消息类型；SDK 对象可能保留同名字段，也可能整理结构或提供派生属性，具体以当前 SDK 返回对象为准。
- 【活动】：让学生从 U2-L1 的话题列表或设备文档找一项实际话题，与表格类型配对。
- 【注意】：不要把“消息字段完全原样包装”为 SDK 的普遍规则。速览课目标是找到可用字段，不是背内部实现。

### 环节 3·Studio 观察（10–14 分钟）

- 【步骤】：打开图像组件，选择 `/boostercamera/head/rgb`；若本机话题名不同，按实际列表调整。
- 【活动】：观察画面是否持续更新，记录显示的话题名。
- 【提问】：“画面停止可能有哪些原因？”
- 【回答要点】：发布者停止、话题名或 QoS 不匹配、网络或组件状态异常等；不能只归因于没有数据。
- 【注意】：不在本课编写图像代码；U3-L1 再深入。

### 环节 4·快照与订阅（14–18 分钟）

- 【板书】：快照 = 主动取一次；订阅 = 注册回调，消息到达时处理。
- 【步骤】：对照 Notebook 的 `get_imu()` 和 `subscribe_imu()`；指出订阅必须退订。
- 【核心概念】：`ros2 topic echo` 也是订阅入口，但由命令行打印；Python 回调和命令行可能有不同 QoS、处理位置和输出方式。
- 【提问】：“如果只检查一次状态，为什么不一定需要订阅？”

### 环节 5·IMU（18–25 分钟）

- 【步骤】：运行连接、`get_imu()`、字段读取格，填写加速度、角速度、frame_id、时间戳。
- 【核心概念】：6 轴指三轴加速度和三轴角速度；本课只说明可用于姿态与运动状态观察，不讲设备内部控制器。
- 【活动】：保持支撑，在教师确认后做小幅姿态变化；比较三个加速度分量。不能抬离支撑面，不追求某个固定读数。
- 【话术】：“合成加速度常接近重力加速度，但不能要求某一个轴恰好是 9.8。先记录 frame_id，再按设备文档确认坐标方向。”
- 【注意】：orientation、rpy 可能为空；本课后半段从 `get_odom().rpy` 读取姿态角，下一课再解释估计原理。

### 环节 6·里程计（25–31 分钟）

- 【步骤】：打印返回值，读取 position、rpy、pose_2d。
- 【核心概念】：里程计是相对运动估计，可结合关节、足部接触、惯性等信息；不把 K1 简化成单靠编码器，也不在本课断言“走得越远误差一定越大”。
- 【活动】：若安全条件允许，保持支撑做小幅拖动，前后读取并记录；若不执行，记录“未执行”。
- 【提问】：“`pose_2d` 打包了哪些量？”
- 【回答要点】：x、y、yaw；`linear_velocity`、`angular_velocity` 可能为 None，本课不读。

### 环节 7·关节与电池（31–35 分钟）

- 【步骤】：读取关节总数和前六个实际名称、位置；再读取电量、电压、充放电状态。
- 【核心概念】：本课只依赖 `name`、`position`；velocity、effort 是否有值以返回对象为准。不能硬编码未经确认的关节名和顺序。
- 【活动】：只有教师确认安全时才改变姿势；不按猜测的关节名发运动指令。
- 【话术】： “电量是否够用要结合任务要求判断；单次电压读数不能诊断电池健康。”

### 环节 8·刷新与订阅（35–41 分钟）

- 【步骤】：两次读取时间戳；再订阅 IMU 2 秒、统计数量并退订。
- 【核心概念】：时间戳变大说明两次返回记录时间不同；快照取当前可用数据。订阅计数会受发布频率、网络、QoS和处理速度影响，不规定一个统一条数。
- 【注意】：先确认回调已注册，结束时确认已执行 `unsubscribe()`；不让回调跨单元持续运行。

### 环节 9·检查与评价（41–45 分钟）

- 【活动】：收齐观察表，核对 4.1；独立完成 4.3 三题。
- 【注意】：未执行拖动记录为“未执行”。思考题 2、3 课后完成，不挤占检查与评价时间。
- 【话术】：“今天读取了运动、电源和关节数据。判断这些数据的含义时，还要核对单位、坐标系和记录时间。”

## 五、板书设计

**五类数据**

| 数据 | 常见消息类型 | 本课读取 |
| --- | --- | --- |
| 相机 | `sensor_msgs/msg/Image` | Studio 图像组件 |
| IMU | `sensor_msgs/msg/Imu` | `linear_acceleration`、`angular_velocity` |
| 里程计 | `nav_msgs/msg/Odometry` | `position`、`rpy`、`pose_2d` |
| 关节 | `sensor_msgs/msg/JointState` | `name`、`position` |
| 电池 | `sensor_msgs/msg/BatteryState` | `percentage`、`voltage`、`power_supply_status` |

**快照与订阅**

| 项目 | 快照 | 订阅 |
| --- | --- | --- |
| 触发 | 主动调用 | 消息到达触发回调 |
| 例子 | `get_imu()` | `subscribe_imu(on_imu)` |
| 结束 | 调用完成 | `unsubscribe()` 或订阅失效 |

## 六、学习评价

> 题目与实训手册 §4.3 一致。

1. 快照式取数需要主动调用；订阅式注册回调后由消息到达触发处理。（判断）  
   **答案：√。**
2. 五类数据的常见消息类型依次为 Image、______、Odometry、______、BatteryState。  
   **答案：`sensor_msgs/msg/Imu`；`sensor_msgs/msg/JointState`。**
3. 某接口没有提供电池订阅，但任务要求每 1 秒检查一次电量；你会选轮询还是订阅？写出选择依据。若接口提供订阅且要求尽快响应，你会如何调整？  
   **答案：题设接口无订阅时选轮询；提供订阅且要求低延迟时可选订阅，同时考虑退订、资源与实现可靠性。**

课堂操作另查：四个快照接口运行过、时间戳记录过、订阅已退订；不以订阅条数作为统一标准答案。

## 七、安全与设备准备

- 本课不发送运动或动作指令。机器人保持坐姿、趴姿或准备模式（PREP）站姿。
- 拖动或姿态变化须由教师确认支撑面和空间；小幅、缓慢、不抬离支撑面。学生不尝试抬起、推倒或改变关节姿势。
- 关节名称以实际输出为准；不依据猜测名称调用控制接口。
- 前置：U1 四课、U2-L1；设备、网络和数据接口已由教师课前检查。
