# U1 教学设计草案：人形机器人初探与运动控制

> **用途**：验证 U1 四课分节合理性，评估每课 45 分钟容量是否充实。
> **基于**：X课程大纲-v4 §U1 + Phase 1 notebook（L1~L4 已完成实验代码）
> **课时**：每课 45 分钟
> **活动形式标记**：📺导入  📖讲授  💻coding  🎮手柄/GUI  👁观察/测量  💬讨论  ✏️创意/展示  📝评价
> **结构决策**：步态切换由 L4 移至 L3（步态与速度同属"运动控制"，L3 主题统一；L4 改聚焦"头部/角度/动作表达"）。若后续认为步态应回 L4，L3 去掉步态段、L4 去掉手柄回读段即可。

---

## L1：具身智能概览 + 连接 K1

### 课时目标
1. 了解具身智能的概念、发展历程（人形机器人主线）与当前研究重心
2. 认识 BoosterStudio 工具、K1 网络连接原理，能完成配网与连接
3. 能通过 SDK 连接 K1，读取机器人身份与结构信息

### 45 分钟时间轴

| 时间    | 环节        | 形式       | 内容                                                                                                            |
| ----- | --------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| 0-04  | 📺 导入     | 视频+提问    | 播放人形机器人应用短片（展厅迎宾/足球/搬运）。提问：这些机器人"智能"在哪里？引出"具身智能 = AI + 物理身体"                                                  |
| 04-13 | 📖 讲授     | 讲解+时间线   | **具身智能发展（人形机器人主线）**：早期遥控/预设动作 → 算法控制 → 深度学习 → 大模型+具身智能；以 Boston Dynamics、Tesla Optimus、Booster Robot(加速进化)为节点 |
| 13-21 | 📖 讲授     | 讲解+名词卡片  | **当前研究重心（前沿科普 + 贴近应用的平衡）**：<br>① **前沿名词科普**：VLN（视觉语言导航，让人机听懂"去那边把杯子拿来"）、VLA（视觉-语言-动作模型，端到端把"看+说"变成"动"）、世界模型（让机器人在脑内模拟"如果我这么动会怎样"）。这些是当前研究热点，先建立认知，不求深究。<br>② **更贴近高职学生可触达的方向**：机器人操作（抓取/装配等灵巧作业）、运动控制（平衡行走/全身协调）、手眼协调（视觉闭环引导动作）。这些与后续课程（感知、视觉引导、动作示教）直接相关，是同学们真正能动手实践的范围。<br>③ **平衡设计**：前沿名词负责"开眼界、知方向"，应用方向负责"落地、能上手"——一节课两种口味都要有。 |
| 21-29 | 📖 讲授     | 讲解+演示    | **BoosterStudio 与 K1 网络连接**：K1 是网络设备，SDK 通过 IP:端口通信；介绍 BoosterStudio 工具界面；配网与查看 IP 的方法                        |
| 29-37 | 🎮 手柄/GUI | 实操       | **使用 BoosterStudio 连接机器人**：开机 → 配网 → 查看 IP → Studio 连接 → 观察实时画面（关节/相机/状态）                                     |
| 37-44 | 💻 coding | notebook | 运行 L1 notebook：SDK 连接 → 打印 robot_info → list_joints() → list_actions() → get_mode + get_battery               |
| 44-45 | 📝 评价     | 个人       | 学习评价 3 题 + 小结：认识了 K1 的"身份证""身体清单"和连接工具                                                                        |

### 容量评估
- **coding 约 7 分钟**（只读操作，不涉及运动）
- **非 coding 约 38 分钟**：导入 4 + 讲授 21 + GUI 实操 8 + 评价 5
- **充实度**：✅ 充实。第一节课以"认知+工具"为主，coding 虽轻但合理；具身智能发展+研究重心（前沿科普+贴近应用平衡）+Studio 连接共同撑满
- **风险**：内容为前半段偏讲授，用短片、时间线、名词卡片、实物演示打断节奏
- **平衡设计**：研究重心一节刻意做了"双口味"——VLN/VLA/世界模型负责开眼界，机器人操作/运动控制/手眼协调负责能落地，避免只灌前沿名词或只讲工具两种极端

## L2：运行模式与安全（多方法切换）

### 课时目标
1. 理解 damping/prepare/walk 三种模式的物理含义与切换约束
2. 能分别用 Studio 按钮、手柄、SDK 程序三种方式切换模式，体会各自特点
3. 建立操作安全意识（STAND 确认、严禁 walk→damping）

### 45 分钟时间轴

| 时间    | 环节        | 形式       | 内容                                                                                                  |
| ----- | --------- | -------- | --------------------------------------------------------------------------------------------------- |
| 0-05  | 📺 导入     | 回顾+演示    | 回顾 L1：已能连接读取信息。用 Studio 按钮演示 damping→prepare→拉起→walk，学生观察姿态变化                                       |
| 05-12 | 📖 讲授     | 讲解+体感    | **三种模式详解**：damping（软态/开机默认/无法站立）、prepare（可拉起到 STAND）、walk（动态平衡/可走）。让学生触摸 damping vs prepare 下关节阻力差异 |
| 12-22 | 🎮 手柄/GUI | 实操       | **方法① Studio 按钮**：完成 damping→prepare→（拉起）→walk→prepare→坐下→damping 全流程，体会物理感受                        |
| 22-30 | 🎮 手柄     | 实操       | **方法② 手柄**：用手柄上的模式键/Stand 键完成同样的切换序列，对比与按钮的差异                                                       |
| 30-38 | 💻 coding | notebook | **方法③ SDK 程序**：运行 L2 notebook 趴姿切换（prepare↔damping）+ 行走安全路径（**教师监督下**逐步执行）                          |
| 38-42 | 💬 讨论     | 分组       | 三种切换方式对比：各在什么场景用？程序控制相对按钮/手柄的优势？（可自动化、可与动作串联、可嵌入条件）                                                 |
| 42-45 | 📝 评价     | 个人       | 学习评价 3 题 + 小结：模式是安全的基础，下节课让机器人真正走起来                                                                 |

### 容量评估
- **coding 约 8 分钟**（趴姿切换 + 行走路径监督下运行）
- **非 coding 约 37 分钟**：导入 5 + 讲授+体感 7 + 按钮 10 + 手柄 8 + 讨论 4 + 评价 3
- **充实度**：✅ 充实。"三种方法反复切换同一组模式"是本课核心，体感+对比+讨论层层递进，45 分钟饱满
- **风险**：按钮/手柄需多组轮流（受机器人数量限制），可设观察组轮换

## L3：基本运动控制（坐标系 + 手柄 + 速度 + 步态）

### 课时目标
1. 理解机器人坐标系（x 前/y 左/z 上）和速度指令（vx/vy/vyaw）
2. 能通过手柄和 SDK 两种方式控制运动，理解开环控制与偏差
3. 体验不同步态（default/soccer）对运动的影响

### 45 分钟时间轴

| 时间 | 环节 | 形式 | 内容 |
|------|------|------|------|
| 0-05 | 📺 导入 | 回顾+提问 | 回顾 L2：已能进入 walk 模式。让机器人走一步，提问：它怎么知道"前方"是哪？ |
| 05-13 | 📖 讲授 | 讲解+身体演示 | **坐标系**：x 前/y 左/z 上。学生站起来用身体表示三轴。vx 正=前进、vy 正=左移、vyaw 正=左转。**开环**概念：发指令不管结果，会有偏差 |
| 13-22 | 🎮 手柄 | 实操+引出 | **手柄控制机器人**：学生用手柄让机器人前进/后退/转向。提问：手柄按一下，机器人为什么动？——手柄的控制是如何实现的？（底层也是发速度指令） |
| 22-28 | 📖 讲授 | 讲解 | **引出 SDK**：手柄底层发送速度指令给机器人；我们直接写程序发同样指令，更可控、可记录、可组合 |
| 28-34 | 💻 coding | notebook | 运行 L3 notebook：坐标系复习 → 模式确认（prepare→walk 多 cell）→ 前进/后退/左转实验（**监督下**轮流） |
| 34-39 | 💻 coding | notebook | **步态切换**：切 soccer 走一段，切回 default 走一段，观察差异（步幅、稳定性、速度） |
| 39-43 | 👁 观察/测量 | 小组 | **开环偏差测量**：前进 0.5m/s×2s（理论 1m），量实际位移记偏差（简短，换方向可课后） |
| 43-45 | 📝 评价 | 个人 | 学习评价 3 题 + 小结：开环有偏差，U4 会学闭环修正 |

### 容量评估
- **coding 约 11 分钟**（速度 + 步态）
- **非 coding 约 34 分钟**：导入 5 + 讲授 16 + 手柄 9 + 测量 4 + 评价 2
- **充实度**：✅ 充实。坐标系→手柄(前置)→SDK 递进自然；步态是新增亮点
- **风险**：内容偏多，偏差测量需简短；若超时，测量可设为课后任务

## L4：头部、角度与预定义动作

### 课时目标
1. 理解头部俯仰角（pitch）/偏航角（yaw）与电机角度概念，能用程序控制头部
2. 能通过手柄+程序回读，探究关节角度与运动的关系（与头部控制共用同一知识点，连续深入）
3. 能调用预定义动作库（do_action），体会"单关节角度控制"与"组合动作表达"的对照

### 45 分钟时间轴

| 时间    | 环节         | 形式       | 内容                                                                                      |
| ----- | ---------- | -------- | --------------------------------------------------------------------------------------- |
| 0-03  | 📺 导入      | 回顾+提问    | 回顾 L3：已能让机器人走、换步态。提问：机器人除了"走"，还能怎么表达自己？——转头看、点头、做动作（呼应头部与角度）                        |
| 03-12 | 📖 讲授      | 讲解+演示    | **头部控制详解**：pitch 俯仰角（正=低头）、yaw 偏航角（正=左转）；**电机角度概念**（关节由电机驱动，角度即关节位置）；仅 walk 下有效（舵机上电锁定） |
| 12-20 | 💻 coding  | notebook | 头部控制：低头/转头/回正（set_head_angle，多 cell 安全路径，**监督下**）——用代码直接"驱动电机到某个角度"                          |
| 20-29 | 🎮 手柄 + 💻 | 探究       | **手柄控制 + 角度程序回读**：用手柄转动头部/做动作，同时用 get_joint_states() 回读各关节角度，观察"手柄操作 → 电机角度变化"的对应关系。与上一环节共用同一知识点（电机角度），连续深入 |
| 29-34 | 💬 讨论      | 分组       | 角度回读有什么用？（动作复现、状态监测、为 U4 闭环打基础）；为什么"读角度"是闭环控制的起点                                   |
| 34-42 | 💻 coding  | notebook | **预定义动作（动作表达收尾）**：依次调用 list_actions() 前 3 个动作（do_action），观察每个动作效果——这是"组合好的动作表达"，与前面"单关节角度控制"形成对照 |
| 42-45 | 📝 评价      | 个人       | 学习评价 3 题 + U1 单元总结：从连接到运动到表达，U1 建立"开环操作"基础；U2 学感知系统                                     |

### 容量评估
- **coding 约 16 分钟**（头部 + 回读 + 动作）
- **非 coding 约 29 分钟**：导入 3 + 讲授 9 + 手柄回读 9 + 讨论 5 + 评价 3
- **充实度**：✅ 充实。顺序修正后：**角度主题连续**（头部控制 → 手柄+角度回读 → 讨论回读用途），最后以预定义动作作"动作表达"独立收尾，逻辑顺畅不割裂
- **风险**：时间偏紧，回读探究可设为"演示为主，运行可选"

## U1 四课分节合理性总评

### 容量对比

| 课 | coding | 非 coding | 充实度 | 判断 |
|---|---|---|---|---|
| L1 | ~7min (16%) | ~38min (84%) | ✅ 充实 | 认知+工具主导，coding 轻但合理（第一节课） |
| L2 | ~8min (18%) | ~37min (82%) | ✅ 充实 | 三方法切换+体感+对比，45 分钟饱满 |
| L3 | ~11min (24%) | ~34min (76%) | ✅ 充实 | 坐标系→手柄→SDK 递进，步态是亮点 |
| L4 | ~16min (36%) | ~29min (64%) | ✅ 充实 | 头部角度+动作+回读，coding 占比最高 |

### 分节结论
- **4 课分节合理**，无需合并或拆分
- **coding 占比递增**（L1→L4: 16%→36%），符合"先认识后操作"的学习曲线
- **每课都有不可替代的非 coding 活动**：L1 具身智能发展+Studio 连接、L2 三方法模式切换体感、L3 手柄前置+开环测量、L4 角度回读探究
- **结构决策**：步态由 L4 移至 L3，使 L3=运动控制（速度+步态）、L4=头部/角度/动作表达；L4 新增手柄+角度回读填补内容
- **U1→U2 衔接清晰**：开环操作（U1）→ 感知系统（U2）→ 闭环控制（U4）
