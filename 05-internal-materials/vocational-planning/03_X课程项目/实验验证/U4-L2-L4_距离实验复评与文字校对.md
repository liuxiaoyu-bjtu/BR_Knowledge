## 一、现稿核查：问题在哪里

### 1. 计算之后没有及时发生实际运动

当前L2共41格。STEP 02（第10格）用假设数值计算计划行进量和剩余量；STEP 03（第18格）实际上是取图标定。用户所说“只计算”的问题对应当前STEP 02，可能是课内编号更新所致。

实际行走在第五节STEP 07、08（第30、32格），第三节误差讲解之前没有运动观察。**全课已有行走代码，但“计算→走起来→测量差异→解释偏差”的学习次序没有接上。** 当前先讲漂移、再讲视觉、最后才运动，学生需要到后面才找到前面结论的实验证据。

建议把第一段实际行走及卷尺记录放到计算之后，先获得一次读数与实测差异，再讨论误差。没有明显差异时，也应如实记录；不能为证明“漂移”要求学生必须测出偏差。

### 2. STEP 09实际使用的是高度比例

第34格的输入与处理如下：

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| `start_gap_compare` | 第二次起步时输入的卷尺间距 | 作为已知起始条件 |
| `x_stop` | 停稳后里程计x分量 | 与起步间距相减，推算剩余间距 |
| `h_ratio_1m2` | 1.2米处标定的框高占比 | 作为视觉换算的参照 |
| `h_ratio_now` | 停稳后新图像的框高占比 | 用于当前视觉估距 |
| `actual_gap_after` | 停稳后卷尺间距 | 核对两项估计 |

`distance_est = 1.2 * h_ratio_1m2 / h_ratio_now`使用高度占比，没有使用面积。当前框高增大，估计距离减小，**公式的变化方向符合近大远小**。它不控制运动，只计算停靠后的两项估计与卷尺差值。

设固定目标的框高为h、距离为d，在完整目标、相同成像条件的近似模型中，h与1/d成正比。因此：

```
高度换算：d ≈ d0 × h0/h
面积换算：d ≈ d0 × √(A0/A)
```

采用占比也有相同关系，前提是图像和拍摄条件一致。面积随距离近似平方反比变化，不能把高度公式中的h直接换成面积A。

**更大的问题是适用条件。** 1.2米处若头或脚被裁切，当前框与标定框不再对应相同身体范围；框高可能接近画面高度而失去距离分辨力。改用面积也不能恢复画面外的信息。检测器还可能给出截断或不稳定的框，不能假定它会精确补出完整身体。

另有一项跨实验变化：第四节允许坐姿取图，第五节实际站立行走。相机高度、俯仰和透视关系可能改变；若标定姿态与停靠取图姿态不同，不能直接比较。本轮已在文字中补充这些检查和重新标定要求，代码没有自动识别裁切或拒绝无效框。

### 3. 里程计何时有用

来宾站定、起步间距d_start已知、机器人基本直行时，可计算：

```
计划行进量 = d_start − 目标间距
剩余间距估计 = d_start − 里程计前向位移估计
```

这是受控课堂场景，起步间距由卷尺提供。现稿有这个输入，不能说其距离控制在已知起点条件下没有意义。明显转弯时，x分量只是参考坐标某一方向的位置变化，不能当作整段路程；来宾移动也会破坏原来的推算。

如果想实现“起始间距未知，也能走到来宾前1.2米”，单靠里程计不足以完成任务。需要先获得可靠的目标间距，或在已标定且有效的视野内持续判断视觉距离。**已知起步间距的演示与未知间距的自主接近，应在任务要求中分别说明。**

## 二、SDK能怎样控制行走距离

本次访问了官方SDK概述、运动控制分类、高级任务分类、快照接口及相关页面，保存了页面正文和链接记录。文档公开的基础运动接口中，没有直接接收“向前走0.8米”的距离命令。

| 接口 | 官方说明 | 适合本课的用途 |
| --- | --- | --- |
| `set_velocity(vx, vy, vyaw)` | `walk`模式下发送机身坐标系平面速度；线速度m/s，角速度rad/s；返回`None` | 发起前进或发送零速度 |
| `get_odom()` | 返回最近一帧`OdomState`；数据未准备好可能抛`DataNotReadyError` | 读取位置估计，判断是否接近计划位移 |
| `reset_odom(x=0, y=0, theta=0)` | 重设里程计参考位姿；要求`walk`模式；指定位姿参数自v1.2.0支持 | 起步前清零，不是移动到坐标或返回原点 |

两种实验要分清：

1. **固定速度、固定时长**：发送速度，等待指定时间，再发送零速度。`v×t`是计划值，不能保证实际走了该距离。
2. **按里程计估计位移停止**：循环取里程计，达到目标读数后发送零速度。它能按估计值控制一段位移，是否接近实际目标仍需卷尺核对。

现稿STEP 07、08属于第二种，可复用其思路作为前移的行走实验。建议代码调整时同时加入有界运行时间和`try/finally`中的零速度指令，再读取停稳后的实际终点数据。`finally`用于程序正常异常/中断路径的清理，不能代替机器人硬件保护或教师人工中止。现有200轮上限不是固定时长，当前末行的x也可能是最后一次发速度前的读数。

不建议引入示教轨迹回放或导航框架来完成这段距离实验；它们不等于一个简单的“距离参数”，也会增加当前课程的前置知识。

官方来源：

- [set_velocity](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/motion-control-apis/set-velocity/)
- [get_odom](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/sensor-and-state-snapshot-apis/get-odom/)
- [reset_odom](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/motion-control-apis/reset-odom/)
- [运动控制分类](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/motion-control-apis/overview/)

## 三、两种策略的比较与推荐

| 比较项 | 策略1：位移与框变化联合推算 | 策略2：独立核对与标定 |
| --- | --- | --- |
| 里程计实验 | 卷尺测位移，尝试修正读数 | 卷尺测位移，记录偏差及重复性 |
| 视觉实验 | 依赖前后两次框变化及已知行进量 | 直接用卷尺距离建立框大小对应 |
| 误差关系 | 里程计位移误差会进入视觉推算，框变化小还会放大误差 | 两组实验可独立检查，便于找到差异来源 |
| 学生负担 | 需理解两次观察、比例消元及有效条件 | 能直接看到已知距离、读数、差值的关系 |
| 与接待任务的联系 | 可探索起始距离未知时的距离推算，但条件严格 | 已知起步间距可控制行进；有效视觉标定可供后续触发或距离核查 |
| 本课定位 | 教师可选拓展，需另行验证 | 推荐主线 |

### 策略1有可行的数学依据，但不宜先做通用修正

同一静止目标、前后都完整可见、相机沿视线直行且姿态基本不变时，前后框高分别为h_far、h_near，实际前进位移为s，可近似得到：

```
接近后的距离 ≈ s × h_far / (h_near − h_far)
接近前的距离 ≈ s × h_near / (h_near − h_far)
```

若改用面积，应先把A开平方，再使用对应的比例关系。这里的s如果来自有偏差的里程计，推算距离也会带入该偏差。前后框高差很小时，分母很小，框抖动会显著影响结果；目标裁切、相机俯仰或来宾改变姿态还会破坏假设。

“实际位移÷里程计位移”可以是某组实验的比例观察，但单次差值可能来自起停、姿态、地面或测量方法，未必是稳定比例误差。要把它用于修正，需要同条件重复测量，再用未参与求系数的数据检查效果。当前高职入门课以识别误差和核查条件为宜，不把求一个系数写成解决漂移。

### 推荐方案：策略2主线，加一次有条件的联合核查

1. **真实行走**：先按固定时长走一小段，比较计划值、里程计前向位移与卷尺实际位移；再按里程计目标位移停止，比较实际结果。教师确认距离与速度，先短距离、低速。
2. **解释偏差**：明确计划值、估计值、实测值三种数据来源。相同条件重复，观察差值是否稳定；不要求必须出现漂移。
3. **静态视觉标定**：保持同一来宾、同一拍摄姿态，用卷尺设置多个距离。记录框高占比、框面积占比和身体是否完整可见；使用其中一组标定，另一组检查。先确定实际可用距离范围，不能预设1.2米一定能全身成像。
4. **连接到接待任务**：在起步间距已测、目标静止的条件下，用里程计控制行进。若终点视觉标定有效，再比较视觉间距估计与卷尺结果；无效则记录无效原因，不计算一个看似精确的米数。

保留1.2米作为任务目标间距没有问题，但目标值与传感器能否有效测量是两个条件。如果1.2米处完整框不可得，本轮不建议为了保留公式而自动改用半身框或面积。应先观察1.2米实图：确认是否有稳定、可区分的图像特征，再决定采用经检验的经验对应，还是把视觉距离实验放在更远的有效范围；近处停靠继续使用已知起步间距与里程计，并由卷尺验收。

### “回到原位”的范围

里程计位置与朝向可以为返回设计提供参照，但不会自行规划路线或避障。沿途多次`reset_odom()`还会改变参考原点；当前程序没有自动返回功能。L2不宜把返回写成已实现产出，课堂重复实验仍由教师协助恢复标记起点。

## 四、U4-L3与U7-L1是否重复

| 维度 | U4-L3现稿 | U7-L1现稿 |
| --- | --- | --- |
| 学习问题 | 反馈怎样改变下一条运动指令 | 数据持续到来时，怎样接收、记录与比较时间 |
| 取数方式 | 主循环调用`get_image/get_odom/get_imu`读取最近缓存 | 注册三路`subscribe_*`回调，结束时退订 |
| 图像用途 | 检测来宾，计算方向偏差，调整角速度 | 计数并记录图像时间戳，不作目标检测控制 |
| 里程计用途 | 估计行进进度，决定前进或停止 | 计数并记录时间戳 |
| IMU用途 | z轴角速度与参考值比较，演示停止分支 | 计数并记录时间戳 |
| 学生记录 | 程序结束原因、停靠间距与误差 | 接收到的条数、接收速率估计、末次时间戳差 |
| 未实现内容 | 无统一定位、无移动目标距离控制 | 无三路同步配对、无运动、无定位融合 |

**三类数据相同，学习任务不同，保留两课有合理性。** L3应重点讲“读数影响哪个动作”，U7-L1应重点讲“这些读数何时到达、是否来自相近时刻”。L3不展开订阅队列和线程，U7-L1不重复设计走近控制。

U7-L1导入“前面六单元数据一路一路用”与L3联合取数不符；把末次时间差观察写成数据对齐也过强。这两项已列入[U7审核](U7_文字表达与阅读衔接审核.md)，本次未改U7。时间戳是否同一基准仍需核实，不能把“比了时间差”写成完成融合。

L3标题“跟住来宾”也会让学生期待跟随移动的人；当前实验是静止来宾接近。建议后续统一改为“反馈引导的接近（闭环与视觉伺服）”或“边看边调整方向”，本轮保留课名并在导入解释实际任务，未改文件名和课程标题体系。

## 七、下一轮真机确认需要记录什么

1. 机器人SDK版本、场地、速度、卷尺参考点和相机姿态。
2. 同条件多次小段直行的计划值、里程计停稳后位移、卷尺位移；说明测的是前向位移还是路径长度。
3. 1.2米及较远距离处的实际图像，标记身体是否完整、检测框是否被裁切；记录框高/面积占比及重复取图波动。标定数据与检查数据分开。
4. 接近实验的起步间距、程序结束原因、最终卷尺间距及是否停稳；不要求结果必须偏差明显或闭环必须优于开环。
5. L3/L4正常转向时IMU角速度的表现；示例分支是否触发与安全状态分开记录。
6. 致意任务成功、失败或取消时的返回状态及实际动作，确认流程不会把失败记录为成功。
