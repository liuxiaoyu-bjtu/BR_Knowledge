## 3. SDK依据与不能省略的坐标问题

本轮读取官方文档并保存正文。主SDK资料用于导航，最终接口含义以本次官方正文核对：

| 依据 | 已核实内容 |
| --- | --- |
| [管理器概览](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/automatic-soccer-kick-manager/overview/) | 绑定机器人、start、方向力度、持续球位、stop；T2暂不支持 |
| [update_ball](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/automatic-soccer-kick-manager/update-ball/) | 当前机器人坐标，x前正、y左正，单位米；返回None |
| [update_command](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/automatic-soccer-kick-manager/update-command/) | direction为当前机身相对yaw、rad；power范围1～10；返回None |
| [stop](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/automatic-soccer-kick-manager/stop/) | 关闭控制并清空球位置和踢球指令 |
| [检测](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/vision-and-speech/detection/detect/)及[检测结果](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/common-data-types/sensor-and-state-data/detection-result/) | soccer示例Ball类别；检测输入需数组/图像等；distance_m等扩展字段可为None，不能假定可直接取得球位 |
| [图像订阅](https://docs.booster.tech/zh-CN/docs/developer-guide/booster-os-python-sdk/booster-robot-client-reference/sensor-subscription-apis/subscribe-image/) | queue_size=0不设上限，有限队列按overflow处理；回调收到AnyImage |

原始正文见[任务资料](../../../../99-task-contexts/20261028-U7U8-v5重构/sdk-evidence/README.md)。一次猜测的SensorSubscription链接返回官网首页，未作为证据；未以第三方RoboCup示例中的伪接口替代SDK。

**坐标方案是课程附件提供的近似标定，不是官方自动定位能力。** 用同一球在已知(x,y)点取得(u,v)，拟合固定视角下的投影近似；至少四个不共线标定点，加至少三个独立核对点。学生学习输入输出、坐标意义、误差及适用条件，矩阵求解留在附件。球框下缘并非精确地面接触点，球形与检测框偏差会进入误差；不能把拟合点上的误差当作独立验证。

足球步态改变相机姿态时，这种静态映射可能不适用。本版明确要求教师额外核查动态条件和可用范围；不满足时停留在静态定位，不能为了完成踢球任务删除检查。后续若实测表明动态误差不可接受，应更换为经验证的定位来源后再定稿，这属于P1真机验证要解决的问题。

**时间与退出**：本地取图前计时可限制本次调用和计算过慢的情况，不能测得完整源数据年龄。源时间戳相同则拒绝反复下发旧球位；时间戳变了也不代表已证明端到端延迟满足控制要求。六秒窗口按循环检查，不是SDK阻塞时仍能强制抢占的硬期限；接口未返回期间仍依靠现场保护和按钮处置。stop返回、任务取消与物理成功分别记录。

## 6. 确认①设计审阅清单

1. U7各课新知和任务是否合理分配；L1无需线程前置，L3静止实验是否足以说明并发。
2. 融合、多模态、联合观察的定义是否适合学生；是否保留技术区别而未要求实现融合算法。
3. 地面位置近似标定是否接受作为当前课堂定位方案；教师能否提供标定与动态核查，是否需要实测后调整来源。
4. 自动踢球课程的范围是否适合本机和学生：坐标、四个控制接口、有限窗口、丢球与退出；不承诺完整比赛策略。
5. U8导览的定点基础方案和选做移动、踢球有限尝试是否符合委托；二选一的评价能否使用同样的工程证据。
6. 四课项目材料是否完整、跨课文件是否友好；参考代码与学生需要自主完成的部分是否恰当。
7. 45分钟与设备轮换是否可行，尤其L2教师预标定、L4两类片段验证及U8展演组数。
