## 一、本机核查结论（为什么真机验证要由用户执行）

WorkBuddy 所在 Windows 环境里装的 `boosteros` 是**残缺包**：`site-packages/boosteros` 下只有 8 个 `__init__.py` 壳文件，`robots/booster/` 与 `types/` 引用的实现文件全部缺失。实测：


另外该包 METADATA 自己写明 `Operating System :: POSIX :: Linux`、`Requires-Python >=3.10`；知识库 `ros2-sdk.md` 的示例也基于 ROS2 Humble。**所以本机既跑不了 boosteros，也连不上机器人。**

结论：P2 的「设计」部分在这里做，「真机跑通」由用户在机器人上执行探针脚本完成。这是本项目 P2 的实际形态——与 U1/U2 时期的做法一致（实测数据都由用户提供，例如 544×448、nv12、bgr8、mono16 那批）。

### 3.2 实验代码设计（第四节的五步）

**步骤 ① 连接与取帧**（运行类）

```python
from boosteros.robots.booster import BoosterRobot
from boosteros.brain import Detection

robot = BoosterRobot()
print("已连接：", robot.robot_info.model, robot.robot_info.serial_number)

img = robot.get_image(img_type="rgb")
print("图像尺寸：", img.width, "x", img.height)
```

要点：本节所有步骤**复用同一个 `img` 对象**，不再重新取帧。这样同一组数字从头贯穿到尾，结果可复现，对照阈值差异时也不会因画面变化而失真。

**步骤 ② 调检测、打印结果**（运行类）

```python
detector = Detection(model="default")

results = detector.detect(img)
print("检测到", len(results), "个目标")
for r in results:
    print(r.class_name, round(r.confidence, 2))
    print("  框：", r.bbox.x, r.bbox.y, r.bbox.width, r.bbox.height)
    print("  中心：", r.bbox.center_x, r.bbox.center_y)
```

**步骤 ③ 画框**（运行类）

```python
detector.plot(img, results)
```

要点：`Image` 对象自带 `_repr_html_`，在 Jupyter 里直接输出即显示图像，不用另存文件。这一步的功能与第四节的 Studio 观察是**两件事**：这里画的是"这张图加上了框"，第四节看到的是"画面在动、框跟着动"。两者都保留。

**步骤 ④ 发布话题**（运行类）——整条 Studio 观察链的前置

```python
import json
import rclpy
from std_msgs.msg import String

node = rclpy.create_node("vision_detection_publisher")
pub = node.create_publisher(String, "/vision_detection/ball", 10)


def publish_detection(image):
    results = detector.detect(image)

    if results:
        r = results[0]
        payload = {
            "image_width": image.width,
            "image_height": image.height,
            "detected": True,
            "bbox_xyxy": [r.bbox.x, r.bbox.y,
                          r.bbox.x + r.bbox.width,
                          r.bbox.y + r.bbox.height],
            "x": int(r.bbox.center_x),
            "y": int(r.bbox.center_y),
            "label": r.class_name,
            "conf": round(float(r.confidence), 2),
        }
    else:
        payload = {
            "image_width": image.width,
            "image_height": image.height,
            "detected": False,
            "x": image.width // 2,
            "y": image.height // 2,
        }

    msg = String()
    msg.data = json.dumps(payload)
    pub.publish(msg)


subscription = robot.subscribe_image(publish_detection, overflow="drop_oldest")
```

要点：
- 话题名沿用 `/vision_detection/ball`（用户 2026-09-16 确认）。
- 消息类型必须是 `std_msgs/String`，内容是 **JSON 字符串**——图层脚本第一件事就是 `json.loads(msg.data)`。
- 用**订阅式**（`subscribe_image`）而不是循环取帧，话题上才会持续有数据。U3-L1 已教过 `subscribe_image` 与 `unsubscribe()`，这里只是把回调里的动作从"存帧"换成"检测 + 发布"。
- `overflow="drop_oldest"`：检测比取帧慢，队列满时丢旧帧，避免积压。
- 收尾 `subscription.unsubscribe()`。

**步骤 ⑤ 贴图层脚本**（附件）

图层脚本**以附件形式提供**，不进 notebook 正文。notebook 里只留一句任务描述，说明贴到哪里、贴什么；课上按未来 PPT 的指引操作。三件要落实的事：
1. 附件有独立存放位置 + 清单登记 → 已定：`notebooks/U3-L2_图层脚本.md` + `notebooks/_外挂附件清单.md`（见 7.2）；
2. notebook 的任务描述与 P5/P6 的 PPT 指引**口径一致**（同一句话，两处引用同一个附件名）→ 4.5 已写明附件名，P5/P6 沿用；
3. 附件脚本的字段约定与上面的 payload **对齐** → 附件里的字段表已按此写好，脚本本体待 payload 定案后填。

### 3.3 一个还没定的设计选择：单目标还是多目标

通用模型一帧会出多个目标，而参考脚本的 payload 是**单目标扁平结构**。两条路：

| 方案 | 做法 | 附件脚本改多少 | 前提 |
|---|---|---|---|
| **甲（低风险）** | 每个目标发一条消息，payload 保持扁平的 `detected` / `bbox_xyxy` / `x` / `y`，只加 `label` / `conf` | 几乎不用改，只把标签文字从 `dx=…` 换成 `类别 + 置信度` | **重绘必须会清空上一帧**，否则多个框会叠在一起 |
| **乙（更严谨）** | payload 改成 `detections: [ {label, conf, bbox_xyxy}, … ]` | 要改成循环画多个框 | 无 |

**甲和乙的取舍卡在一个待验证项上**：图层脚本每次回调重绘时，会不会清掉上一帧画的东西。会清空 → 甲可用；不清空 → 只能走乙（或者只发置信度最高的那一个）。

探针里把 payload 写成了单目标+`label`/`conf`（即方案甲），因为它改动最小。

### 4.2 实验代码设计

**环节二**（运行类）

```python
for conf in (0.3, 0.5, 0.7):
    results = detector.detect(img, confidence=conf)
    print("阈值", conf, "->", len(results), "个目标")
    for r in results:
        print("   ", r.class_name, round(r.confidence, 2))
```

要点：`img` 沿用 U3-L2 那一帧。`detect()` 的 `confidence` 参数默认 0.5，这里显式给三档，对照才成立。

**环节三**（运行类）

```python
for r in results:
    print(r.class_name,
          "中心横向比例：", round(r.bbox.center_x / img.width, 2))
    print("框高占比：", round(r.bbox.height / img.height, 2))
```

要点：归一化的意义是"换分辨率这个数不变"。可以在课堂上把同一张图缩放到两个尺寸再各算一次，用数据说明这一点（缩放宽高即可，不必真的换相机）。

**环节四**（填空类）——三种挑法

给学生留出判断条件的空位，让他们补完：

```python
best = None
for r in results:
    if best is None or ____:      # 学生补：比什么？
        best = r
print("挑出来的：", best.class_name)

biggest = None
for r in results:
    if biggest is None or ____:
        biggest = r
print("框最大的：", biggest.class_name)
```

三种挑法分别比：置信度、框面积、框中心离画面中心的距离。最后一种需要一个额外变量记住当前最小距离，是本节最容易出错的地方，建议保留**运行类**给一个已写好的版本做对照。

| 环节 | 内容 | 实验类型 |

| 四、封装成函数 | 一次调用拿到结果 | 填空类（或自主编写类） |
| 五、主动感知 | 纯讲解：本课不让它动，运动归 U4 | 无 |
| 六、观察与记录 / 七、扩展阅读 | — | 非代码 |

### 5.2 实验代码设计

**环节二、三**（运行类）——先不封装，把两个判断分开写清楚

```python
ratio = r.bbox.center_x / img.width
if ratio < 1 / 3:
    print("偏左")
elif ratio > 2 / 3:
    print("偏右")
else:
    print("居中")
```

```python
height_ratio = r.bbox.height / img.height
if height_ratio > 0.5:
    print("近")
elif height_ratio > 0.25:
    print("中")
else:
    print("远")
```

边界值取法：本设计用 `< 1/3` 判偏左、`> 2/3` 判偏右，所以恰好等于 1/3 时归为居中。这个取法要在课上明说，否则学生会问"正好在三分之一线上算哪边"。

**环节四**（填空类或自主编写类）——封装

```python
def where(r, img_w):
    ratio = r.bbox.center_x / img_w
    if ratio < 1 / 3:
        return "偏左"
    if ratio > 2 / 3:
        return "偏右"
    return "居中"


def how_far(r, img_h):
    ratio = r.bbox.height / img_h
    if ratio > 0.5:
        return "近"
    if ratio > 0.25:
        return "中"
    return "远"
```

```python
for r in results:
    print(r.class_name, where(r, img.width), how_far(r, img.height),
          round(r.confidence, 2))
```

> **关于「不定义辅助函数」的说明**：规则 §2 第 1 条禁止的是 `print_section` 这类只为排版服务的辅助函数。本节定义 `where()` / `how_far()` 是**本课的学习目标本身**（大纲 U3-L4 编程线写明"坐标-比例换算、函数封装"），不受该条限制。

**环节五**不做代码演示：`set_head_angle()` 属运动控制且要求 walk 模式，本课不进 walk，运动归 U4。这一点在正文里讲清即可。

### 7.3 方案甲 / 乙是什么

指的是**发布端每帧发几条消息、payload 长什么样**，直接决定图层脚本改多少：

- **方案甲（单目标扁平结构）**：一帧里每个目标各发一条消息，payload 保持参考脚本原本的扁平字段（`detected` / `bbox_xyxy` / `x` / `y`），只补上 `label` / `conf`。图层脚本几乎不用改，只要把标签文字从 `dx=…` 换成「类别 + 置信度」。
- **方案乙（多目标列表）**：一帧只发一条消息，payload 改成 `detections: [ {label, conf, bbox_xyxy}, … ]`，一帧里所有目标装在一个数组里。图层脚本必须改成循环画多个框。

取舍点不在"哪个好看"，而在一个待验证事实：**图层脚本每次回调重绘时，会不会清掉上一帧画的东西**。

- 会清空 → 甲可用（每帧的多条消息各自画一个框，第二帧把第一帧的擦掉，不残留）。
- 不清空 → 甲会把多帧的框叠在一起，只能用乙，或者只发置信度最高的那一个。

探针 `_probe_L10_pub.py` 里 payload 写的是方案甲（改动最小）。等 "重绘是否清空上一帧" 的验证结果出来再定案。

**2026-09-23 补充**：方案甲 / 乙的分歧点**只影响附件《U3-L2_图层脚本》**，不影响 notebook 4.4 的发布代码——4.4 发的是「检测到的那一个目标」的扁平 payload（甲的形状），若最终改用乙，需要改的是**附件脚本**与 4.4 的 payload 结构两处。所以 4.4 的 notebook 代码格现在就可以上真机跑，甲 / 乙的定案可以晚于本次验证。

### 7.4 环节四新增图像级 `locate()`（2026-09-23，P2 落地时补）

U3-L4 的 5.2 只给了 `where(r, img_w)` 与 `how_far(r, img_h)` 两个内层判断。但**课程目标第 3 条**写的是「能把『取图 → 检测 → 筛选 → 方位判断』**封装成一个函数**，调用一次就拿到方位与远近的结果」，4.2 的正文也写明「输入是一张图像，输出是一条结构化信息」——两处都指向**图像级**函数，内层判断满足不了。

故 P2 落地时在 4.3 补了：

```python
def locate(image, confidence=0.5):
    found = detector.detect(image, confidence=confidence)
    if not found:
        return None
    best = found[0]
    for r in found:
        if r.confidence > best.confidence:
            best = r
    return {"类别": best.class_name, "方位": where(best, image.width),
            "远近": how_far(best, image.height), "置信度": round(best.confidence, 2)}
```

它同时兑现了 4.2 的三条正文：输入是图、输出含置信度、没有目标时返回 `None` 而不是报错。**待真机核对**：目标在画面正中 / 边角时的方位输出是否与人眼一致。

## 八、附录：图层脚本基线（内部材料，勿直接发放）

⚠️ **这段代码是按用户此前提供的脚本逐行记录重建的，不是原文复制**。放在这里作内部基线，用来对齐字段与推敲甲/乙两种改法；**不要**直接拷进学生附件，正式脚本须以用户原文为准。

```python
import json


@on_message(topic="/vision_detection/ball", anti_flicker=False)
def on_ball(msg):
    data = json.loads(msg.data)

    img_w = data.get("image_width", 0)
    img_h = data.get("image_height", 0)
    if img_w <= 0 or img_h <= 0:
        return

    img_cx = img_w // 2
    img_cy = img_h // 2

    # 画面中心参考线（黄）+ 加粗十字臂
    draw2d.line(0, img_cy, img_w, img_cy).stroke_color("#FFD400").stroke_width(1)
    draw2d.line(img_cx - 22, img_cy, img_cx + 22, img_cy).stroke_color("#FFD400").stroke_width(3)
    draw2d.line(img_cx, img_cy - 22, img_cx, img_cy + 22).stroke_color("#FFD400").stroke_width(3)

    if not data.get("detected", False):
        print("未检测到目标")
        return

    xmin, ymin, xmax, ymax = data["bbox_xyxy"]
    cx = int(data["x"])
    cy = int(data["y"])
    dx = cx - img_cx
    dy = cy - img_cy

    # 检测框（绿）
    draw2d.box(xmin, ymin, xmax, ymax).stroke_color("#00FF66").stroke_width(2)
    # 画面中心 → 目标中心（青）
    draw2d.line(img_cx, img_cy, cx, cy).stroke_color("#00D9FF").stroke_width(2)
    # 目标中心（红）：圆点 + 7×7 方框凑出加粗标记
    draw2d.circle(cx, cy, 5).fill_color("#FF2D2D").stroke_color("#FF2D2D")
    draw2d.box(cx - 3, cy - 3, cx + 3, cy + 3).stroke_color("#FF2D2D").stroke_width(3)

    # 标签：先放一个 8×8 小方框，再把文字挂在它上面（label 挂在图形对象上）
    label_x = (img_cx + cx) // 2
    label_y = (img_cy + cy) // 2
    draw2d.box(label_x - 4, label_y - 4, label_x + 4, label_y + 4) \
        .stroke_color("#00D9FF").stroke_width(1) \
        .label(f"{data.get('label', '')} {data.get('conf', '')}")
```

**重建稿里仍然是推断、待真机核对的四处**：

| 位置 | 推断 | 为什么不确定 |
|---|---|---|
| `draw2d.line(img_cx, img_cy - 22, img_cx, img_cy + 22)` | 竖臂与横臂对称 | 逐行记录里只明确记了横臂那条 |
| `label_y = (img_cy + cy) // 2` | 标签取画面中心与目标中心的中点 | 记录里出现了 `label_y` 变量但没记公式 |
| `.label(f"{…} {…}")` | 文字换成「类别 + 置信度」 | 原文是 `dx=…, dy=…`；要显示类别与置信度必改这一处 |
| 函数名 `on_ball` | 回调函数名不影响注册 | 记录里未记函数名 |

**甲 / 乙在脚本上分别要改什么**：

- 甲：几乎不用改，只把 `.label(...)` 的内容换成类别 + 置信度——但前提是"重绘会清空上一帧"，否则一帧里多个目标的多条消息会把框叠起来。
- 乙：payload 变成 `detections: [...]` 后，从 `xmin, ymin, xmax, ymax = data["bbox_xyxy"]` 往下的一整段（画框、画中心点、画标签）都要套进一层 `for det in data["detections"]:` 循环，参考线与画面中心那条线留在循环外。
