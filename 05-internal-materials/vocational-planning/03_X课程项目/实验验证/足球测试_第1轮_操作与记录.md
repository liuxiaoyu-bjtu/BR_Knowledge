## 1. 本轮怎么做

1. 在实际教学使用的Python环境打开配套Notebook，从STEP 01开始逐格运行，不使用“全部运行”。
2. 按下面七步操作。只有STEP 01的环境备注、STEP 02的相机ID、STEP 04的足球类别名可能需要填写；其他代码先原样运行。
3. 代码自动保存图像、检测字段、逐次采样记录和统计。你只填写本文件第4部分的现场记录，并粘贴结果文件夹路径。
4. 任一步报错或看不到球，就停在该步，运行STEP 07保存已有记录；把未做步骤写“未执行”。不必为凑齐20张反复改参数，也不需要先解决报错再交记录。
5. 完成本轮后等待我审读；先不运行U7-L2的试踢、标定或管理器代码。

下表为用户实际记录，日期2026-10-30；原始数据已回读，助手结论见第5部分。

## 2. 准备与摆放

- 使用已经连接、测试过的K1及教学Python环境，按既有流程让机器人固定、保持静止；结束其他Notebook中仍在运行的任务。
- 场地放一只足球，尽量位于画面中央、完整可见、无遮挡；无需卷尺测距，也不调整头部或切换模式。
- 移走足球只在静止状态进行。有球/无球采样期间，保持机器人、头部、光照和背景不变。
- 这份代码仅取图、检测与存文件，不创建踢球管理器，不发运动或模式指令。

### 本轮阈值与代码一一对应

以下是本轮静止观察的初步检查标准，用来决定下一轮安排，**不代表SDK官方性能指标，也不代表可以启动踢球**。参数已经写在STEP 01，先使用默认值。若确需修改，保存本轮结果后新开一轮，不覆盖旧记录。

| 检查项 | 本轮默认值 | 对应代码/如何判定 |
| --- | --- | --- |
| 检测置信度筛选 | `CONFIDENCE = 0.4` | 传入`detector.detect(..., confidence=CONFIDENCE)`；这是筛选参数，不是定位精度 |
| 每种场景采样量 | `SAMPLE_COUNT = 20` | 只计源时间戳有效、递增、成功完成检测的新图像；同一旧图不重复计数 |
| 最多取图次数 | `MAX_ATTEMPTS = 60` | 超过就结束并报“采样不足”；不要把缺少的样本补0。SDK调用内部等待时，60次不代表固定秒数 |
| 有球场景返回足球类检测 | `MIN_BALL_FRAMES = 18` | 成功采满20张且至少18张返回指定球类；程序给“达到本轮标准/未达到”。还需人工看框是否圈中真球 |
| 无球场景返回足球类检测 | `MAX_FALSE_FRAMES = 0` | 成功采满20张且0张返回指定球类；有任何误检就记录对应图片 |
| 调用异常/源戳倒退 | 0次 | 出现就标“需复核”；不绕过源戳检查、不继续靠旧图采样 |
| `distance_m`是否有数据 | 暂不设米制误差阈值 | 只统计“检测到球的帧中，有几帧距离为有限正数”，并保存原值。全部为`None`也属于有效调查结果 |
| 检测耗时 | 本轮只记录，不判通过 | 程序显示最小/中位/最大耗时；它不等于图像从拍摄到现在的完整延迟 |

本轮不计算像素到米，不设球位误差、深度单位或踢球力度阈值。这些需要根据实际返回数据及下一轮目标再安排，不能让你先猜数值。
