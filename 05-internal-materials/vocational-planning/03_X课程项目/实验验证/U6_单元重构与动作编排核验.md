## 1. 调整判断

原L2止于录制、保存和读回，缺少实际回放验证。原L3主要回放轨迹、复用U1的内置动作，其独立课时目标不足。把回放并入L2后，学生可以在本课发现停顿、节奏或首尾姿态的问题，并改录比较。原L4仅排列内置动作，没有整合本单元的创作材料。

现行L1的代码读取预录轨迹信息，尚不执行回放；但这不改变原L3内容薄、与前课重复较多的判断。本轮保留L1用户精修稿，以新L3承接其中的Booster Train参考动作跟踪。

| 课程 | 本课新增的学习任务 | 主要成果 | 与其他课的分工 |
| --- | --- | --- | --- |
| L1 动作的来源 | 比较动作依据及策略形成方式 | 概念比较、轨迹信息读取 | 保留现稿，提供知识基础 |
| L2 动作录制与回放 | 自己录制、保存、读回、实际回放；只改一个因素再比较 | 两版`.btraj`、回放状态与观察 | 完成本地采集与再现，不称为新策略训练 |
| L3 视频动作训练（动作工坊） | 检查视频、创建训练任务、解释三阶段、比较结果、提出调整 | 视频、任务记录、结果对照、第二版方案 | 学生通过产品使用训练流程，不要求编写深度学习或强化学习算法 |
| L4 动作编排 | 面向场景设计3～5步作品，混合执行录制轨迹与内置动作，试演改进 | 素材表、脚本、日志与修改记录 | 综合活动；动作工坊片段按实际可用接口接入 |

## 3. 录制动作和内置动作能否联合编排

**正式SDK支持按顺序混合调用两类动作。**录制文件先通过`TrajectoryData.load()`读取，再交给`execute_trajectory()`；内置动作由`list_actions()`取真实ID，再交给`do_action()`。两者均返回任务句柄，采用相同的等待与成功判断。

这不意味着有一个自动混合文件的接口，也不意味着同时启动。每一步只有等待返回`SUCCEEDED`时，才启动下一步（成功状态已是终态）；`done()`用于重跑前核对旧句柄；`FAILED`、`CANCELLED`及超时仍未结束均停止后续启动。`wait(timeout=...)`的超时本身不会取消动作。

L4先检查全部素材，再开放试演。检查失败时`plan_ready`保持False，不执行部分清单；修改清单后按步骤重新检查。旧句柄未结束时拒绝重跑；其他运动占用交SDK拒绝调用，由一处`except RuntimeError`提示并退出。取消清单签名、全局变量查询、lambda筛选、enumerate编号及计时，日志改为来源/素材/结果三列。模拟只核验程序分支，不代替真机。

**仍需真机验证的条件**：当前机型和固件下所选内置动作可用；轨迹与机型匹配；退出示教后能够回放；轨迹→内置、内置→轨迹均可顺序执行；首尾姿态适合过渡、动作间能够站稳。任务成功只说明SDK执行结果，不能代替观察。

## 4. 一课时的实施安排建议

以下按45分钟、小组轮换设备估算，供后续教学设计使用，未提前登记P3完成。教师应先完成账号、连接、样例及素材准备，避免把准备耗时当学习活动。代码中的保护检查可以由教师提供，学生重点修改文件名、版本和动作清单，并解释与目标直接相关的接口和判断。

### L2：两版轨迹的录制与回放

| 时间 | 活动 | 学习证据 |
| --- | --- | --- |
| 0～6分钟 | 确认动作方案、首尾姿态和允许示教部位，理解记录与回放的差别 | 三段动作草图、预期停顿 |
| 6～17分钟 | 录制v1、保存、读回核对并在教师确认后回放 | 文件、字段与任务状态 |
| 17～23分钟 | 对照设计，找停顿、节奏或姿态问题 | 一项具体观察 |
| 23～35分钟 | 只改一个因素，录制v2、保存读回并回放 | 第二版文件及同口径观察 |
| 35～41分钟 | 比较两版；解释文件核对、执行成功、动作合意的差别 | 比较表与解释 |
| 41～45分钟 | 任务与设备收尾、学习评价 | 实际终态、个人记录 |

每组由示教、键盘、观察记录等角色协作，按设备数轮换。设备不足时先使用教师两版样例做观察，个人或本组未完成的操作另排补做；不把观看样例记为本人完成录制。

### L3：视频动作训练

| 时间 | 活动 | 学习证据 |
| --- | --- | --- |
| 0～7分钟 | 结合L1与L2解释骨架、重定向、训练的输入输出 | 流程及与直接回放的差异 |
| 7～16分钟 | 设计、拍摄并检查视频，必要时改拍 | 视频检查表、版本与理由 |
| 16～23分钟 | 创建训练任务，核对机型和提交条件 | 任务名、提交时间、可见标识 |
| 23～34分钟 | 本组结果可用时观察本组；仍处理中则对照教师已完成样例 | 起始/关键/结束对照，明确素材来源 |
| 34～41分钟 | 根据证据提出第二版方案，说明预期观察 | 一项调整及其判断方法 |
| 41～45分钟 | 解释训练结束条件、交付与补查安排 | 任务状态、课后补查项 |

训练等待不算独立学习活动，也不承诺当堂完成。本课可先提交本组任务，并用已完成样例学习分析；本组结果按约定补查。真机部署是有条件的观察，不作为每组本节必须完成的目标；第二次训练也不作45分钟硬性要求。

### L4：动作编排综合实践

| 时间 | 活动 | 学习证据 |
| --- | --- | --- |
| 0～8分钟 | 选择场景、拟定3～5步脚本及素材来源 | 作品表，待接入片段单列 |
| 8～16分钟 | 核对文件、ID和单项验证结果，检查相邻姿态 | 素材与衔接检查 |
| 16～27分钟 | 运行基础混合编排，观察并读取日志 | 至少两类素材的实际执行记录 |
| 27～36分钟 | 调整顺序、素材或录制动作的一项要素；重新检查再试演 | 版本与复测记录 |
| 36～41分钟 | 小组说明程序结果及现场效果 | 有依据的修改解释 |
| 41～45分钟 | 设备收尾、提交作品材料 | 文件、日志、未执行与待验证项 |

课前必须有经验证的轨迹和内置动作；本课不再从零录制一段复杂动作。动作工坊接口确认前，基础程序覆盖录制轨迹和内置动作，完整作品可另列工坊片段。不能把独立Studio演示说成SDK连续编排成功。
