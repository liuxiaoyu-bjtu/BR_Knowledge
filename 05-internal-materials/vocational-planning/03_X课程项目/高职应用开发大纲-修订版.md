## 一、课程定位

| 项目 | 内容 |
|---|---|
| 课程名称 | 具身智能应用开发 |
| 适用对象 | 职业院校机器人/人工智能/自动化/智能制造等相关专业，二年级下学期或三年级上学期 |
| 课程性质 | 专业核心课 |
| 先修要求 | 完成「K1 机器人基础」（32 课时）或具备同等 Python 编程 + 机器人基础操作能力 |
| 总课时 | **32 课时**（16 次课 × 2 课时/次，每次课 90 分钟） |
| 学分 | 2 学分（按 16 课时/学分，教职成〔2019〕13 号） |
| 教学载体 | 加速进化 Booster K1 人形机器人 |
| 教学定位 | **应用开发**——会调用、会集成、会调试、会部署，不以算法推导为核心 |

### 能力定位

本课程聚焦具身智能应用开发方向，培养学生在真实机器人平台上完成「感知→判断→控制→执行」完整闭环的工程能力。学生毕业后能够：

1. 基于机器人 SDK 完成视觉感知、运动控制、语音交互等模块的二次开发
2. 理解并操作「示教采集→数据转换→训练→部署」的动作学习链路
3. 设计并实现一个完整的具身智能场景应用（视觉踢球为核心载体）
4. 具备将 AI 大模型（LLM）能力集成到机器人交互场景的工程思维

### 模块 1：视觉输入与基础调试（3 课时）

#### 3.1.1 定位与衔接

- **前置**: K1 机器人基础（SDK 连接、基本运动）
- **后置**: 为模块 2 的 YOLO 检测提供图像数据流基础
- **角色**: 入门模块——建立「机器人能看见」的认知

#### 3.1.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解 ROS2 图像话题（`sensor_msgs/Image`）的概念和元信息字段；理解 RGB 图像与深度图的区别 |
| **技能** | 能够订阅相机话题并获取实时图像；能够保存 RGB 图像和深度图；能够在图像上绘制辅助线/框 |
| **素养** | 建立「先看数据再写代码」的调试习惯——拿到一个新传感器先检查话题和元信息 |

#### 3.1.3 重点与难点

| 重点 | 难点 |
|---|---|
| 图像话题订阅与元信息检查 | 深度图编码格式理解（16UC1 → 米制转换） |
| RGB 图像采集与保存 | — |
| OpenCV 基础绘图（标注辅助线） | — |

> 本模块内容偏薄，3 课时即可覆盖。不与模块 2 合并是为了保持教学节奏的清晰分段——先「会看」再「会判断」。

#### 3.1.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | 实验来源 |
|---|---|---|---|---|
| 1 | 机器人视觉初探 | 相机话题订阅、`sensor_msgs/Image` 元信息（宽/高/编码/帧率）、RGB 与深度图区别 | `camera_topic_inspector.py`：检查话题、打印元信息 | Ch10 |
| 2 | 图像采集与保存 | RGB 图像采集保存、深度图采集与米制转换、伪彩色深度图 | `rgb_image_capture.py` + `depth_image_capture.py`：采集并保存图片 | Ch10 |
| 3 | 视觉调试工具 | OpenCV 绘图（中心线、辅助框、文字标注）、实时显示（可选） | 在采集脚本基础上添加 `cv2.line()` / `cv2.putText()` 标注 | Ch10 扩展 |

#### 3.1.5 主要产出

- 学生采集的 RGB/深度图样本（用于后续模块 2 的标注练习）
- 带辅助线标注的调试图片

### 模块 2：目标检测与方位判断（6 课时）

#### 3.2.1 定位与衔接

- **前置**: 模块 1（图像数据流）
- **后置**: 为模块 3 的运动控制提供目标方位信息
- **角色**: 核心模块——本课程最重的技术模块，建立「感知→判断」能力

#### 3.2.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解 YOLO 目标检测的基本概念（类别、置信度、检测框）；理解 bbox 坐标含义和归一化偏差量 `norm=(error_x, error_y)` |
| **技能** | 能够启动 YOLO 检测节点并订阅检测结果；能够根据置信度筛选有效检测；能够从 bbox 判断目标方位（左/中/右）和远近（大/中/小） |
| **素养** | 理解「置信度阈值调参」的工程意义——平衡漏检和误检 |

#### 3.2.3 重点与难点

| 重点 | 难点 |
|---|---|
| 检测结果 JSON 结构解析 | 理解 `norm` 归一化偏差的含义——不是像素偏移，是归一化到 [-1, 1] 的比例量 |
| 置信度筛选与多目标场景处理 | 多目标时如何选择「最可能的目标」（最高置信度 vs 最大 bbox） |
| bbox → 方位/远近的启发式判断规则 | 远近判断的边界阈值设定（多大算「近」、多小算「远」） |

> **设计决策**: 不引入单目几何定位（相机内参、像素反投影、射线-地面求交）。高职层面用 bbox 启发式判断即可完成「感知→控制」闭环。`norm=(error_x, error_y)` 直接驱动控制，不需要知道「球在基座坐标系下 (1.2m, 0.3m)」，只需要知道「球在画面偏左 30%，离我很近」。

#### 3.2.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | 实验来源 |
|---|---|---|---|---|
| 1 | YOLO 检测入门 | 目标检测概念（不涉及训练）、YOLO 节点启动、检测结果话题订阅 | 启动 `soccer_ball_detector.py`，用 `print_soccer_detection.py` 打印检测结果 | Ch11 |
| 2 | 检测结果深度解析 | JSON 字段详解（class_name, confidence, bbox, norm）、置信度含义、bbox 四个坐标 | 逐字段解释检测输出，手工标注 bbox 在图像上的位置 | Ch11 |
| 3 | 置信度筛选与多目标 | 置信度阈值调参实验、多目标检测场景、选择策略（最高置信度/最大 bbox） | 放多个球/物体，调整阈值，观察检测结果变化 | Ch11 扩展 |
| 4 | 方位判断：左/中/右 | bbox 中心点 x 坐标 → 归一化到画面比例 → 三段式判断 | 移动足球位置（左/中/右），实时输出判断结果 | Ch11 扩展 |
| 5 | 远近判断：大/中/小 | bbox 面积 → 归一化到画面比例 → 三段式判断 | 移动足球距离（近/中/远），观察 bbox 大小变化 | Ch11 扩展 |
| 6 | 检测+判断整合 | 将方位和远近判断整合为统一函数，输出结构化判断语句 | 实时输出"足球在**左侧**，距离**较远**"格式的判断 | 综合实验 |

#### 3.2.5 主要产出

- 检测+判断整合脚本（输出结构化方位/远近信息）
- 不同置信度阈值下的检测效果对比记录
- 方位/远近判断规则的参数配置文档

### 模块 3：目标驱动运动控制（4 课时）

#### 3.3.1 定位与衔接

- **前置**: 模块 2（检测+方位判断）
- **后置**: 为模块 4 的状态机提供基础运动控制能力
- **角色**: 闭环模块——第一次实现「感知→控制」的完整闭环

#### 3.3.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解 `Move(vx, vy, vyaw)` 速度控制模型；理解「偏差→速度」的映射关系；理解停稳条件（距离阈值 + 迟滞） |
| **技能** | 能够根据目标方位计算运动速度；能够实现追球→减速→停稳的完整流程；能够处理目标丢失场景 |
| **素养** | 建立「参数调优」的工程意识——`stop_dist`、`vx_limit`、迟滞量需要根据实际环境调试 |

#### 3.3.3 重点与难点

| 重点 | 难点 |
|---|---|
| 检测→控制的闭环逻辑（连续循环） | 迟滞停稳的设计原理——为什么需要「进入阈值」和「退出阈值」不同 |
| 距离-速度映射（远快近慢） | 速度参数的安全边界——`vx_limit` 不能超过 K1 最大安全速度 |
| 目标丢失时的安全处理 | — |

#### 3.3.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | 实验来源 |
|---|---|---|---|---|
| 1 | 从检测到运动 | `norm=(error_x, error_y)` → `Move(vx, vy, vyaw)` 的映射逻辑、P 控制器简化版 | 仿真：固定目标坐标 → 机器人转向对准 → 前进 | Ch14 简化 |
| 2 | 追球控制策略 | 距离-速度分段映射（chase_slow_dist 慢速区 vs 全速区）、角度修正 | 真机：启动检测→定位→追球，观察机器人追踪足球 | Ch14 |
| 3 | 停稳逻辑与参数调优 | 停稳条件（`stop_dist=0.78m`）、迟滞（`hysteresis=0.22m`）、停稳确认时长 | 调参实验：改变 stop_dist/hysteresis，对比停稳效果 | Ch14 |
| 4 | 目标丢失与异常处理 | LOST 状态：目标丢失后停止/搜索策略、安全停止 | 模拟目标丢失场景（遮挡足球），验证安全停止行为 | Ch14 扩展 |

#### 3.3.5 主要产出

- 追球控制脚本（含参数配置文件）
- 参数调优实验记录（不同 stop_dist/hysteresis 的效果对比）
- 目标丢失安全测试报告

### 模块 4：状态机与任务流程（4 课时）

#### 3.4.1 定位与衔接

- **前置**: 模块 3（基础运动控制）
- **后置**: 为模块 7 综合项目提供行为架构能力
- **角色**: 架构模块——从「单次动作」升级到「多状态行为系统」

#### 3.4.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解有限状态机（FSM）的概念——状态、转移条件、动作；理解为什么机器人需要状态机（不能同时追球和踢球） |
| **技能** | 能够设计三态 FSM（SEARCH → CHASE → HOLD）；能够用 Python 枚举/字典实现 FSM；能够画出状态转移图 |
| **素养** | 建立「先画状态图再写代码」的行为设计习惯 |

> **设计决策**: 使用 FSM 而非行为树（BT）。BT 是工训课 Ch15 的内容，需要理解 Sequence/Selector/Fallback 等组合节点概念，对高职而言偏深。FSM 用 if-else + 枚举即可实现，三态足够覆盖追球→停稳→搜索的需求。

#### 3.4.3 重点与难点

| 重点 | 难点 |
|---|---|
| FSM 三态设计与转移条件 | 状态转移条件的「边界模糊」问题——什么情况下从 CHASE 切到 HOLD（距离 + 时间双重条件） |
| 用 Python 实现 FSM（枚举 + 状态循环） | 状态机调试——如何观察当前状态和转移时机 |
| 状态转移图绘制（流程图工具） | — |

#### 3.4.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | 实验来源 |
|---|---|---|---|---|
| 1 | 为什么需要状态机 | 单循环的问题（无法区分追球/停稳/搜索）、FSM 概念引入、三态设计 | 观察无状态机的追球行为：到达目标后持续微调（抖动问题） | Ch13 概念 |
| 2 | FSM 实现 | Python 枚举定义状态、状态转移条件表、主循环结构 | 编码实现三态 FSM（SEARCH→CHASE→HOLD），在仿真中验证 | Ch13 |
| 3 | 搜索状态设计 | SEARCH 状态：头部搜索（yaw 扫描）+ 身体搜索（原地旋转） | 真机实验：遮挡足球→触发搜索→发现足球→切回 CHASE | Ch13 |
| 4 | 状态机调试与优化 | 状态转移日志、转移条件参数调优、状态机可视化 | 添加状态日志输出，画完整状态转移图并标注转移条件 | Ch13 扩展 |

#### 3.4.5 主要产出

- 三态 FSM 控制脚本
- 状态转移图（含转移条件标注）
- 状态切换日志样例

### 模块 5：语音交互与多模态 Agent（4 课时）

#### 3.5.1 定位与衔接

- **前置**: 模块 1-2（视觉基础，用于多模态联动）
- **后置**: 为模块 7 综合项目提供语音交互/Agent 能力
- **角色**: 智能模块——从「会动的机器人」升级到「能对话的智能体」

#### 3.5.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解 LLM（大语言模型）的基本概念和调用方式；理解 Agent 人设的概念和工程实现（`system_prompt`）；理解 ASR→LLM→TTS 语音交互闭环 |
| **技能** | 能够调用 `robot.chat()` 进行文本对话；能够设计并配置 `ChatConfig(system_prompt=...)` 改变机器人人设；能够实现语音问→机器人语音答的完整闭环；能够实现简单的视觉+语音联动（看到人→打招呼） |
| **素养** | 理解「人设即产品」——同样的大模型，不同的 system_prompt 创造出完全不同的用户体验 |

#### 3.5.3 重点与难点

| 重点 | 难点 |
|---|---|
| LLM 概念（不涉及 Transformer/注意力机制） | system_prompt 的设计方法——身份/语气/知识域/行为约束四要素 |
| `ChatConfig(system_prompt=...)` 人设实验 | ASR→LLM→TTS 链路的延迟理解和调试 |
| 语音交互闭环（ASR→LLM→TTS） | — |

> **设计决策**: 聚焦 LLM 调用 + Agent 人设 + 语音闭环，不涉及语音信号处理（FFT/频谱）和 TTS 引擎原理。4 课时足够建立「调用→配置→闭环→联动」的完整认知。

#### 3.5.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | 实验来源 |
|---|---|---|---|---|
| 1 | LLM 基础认知 | 大语言模型是什么（类比例子）、能做什么、SDK 怎么调用 | `robot.chat("你好")` → 观察回复；`robot.chat("请用一句话介绍什么是具身智能")` → 理解知识问答 | 豆包 SDK |
| 2 | Agent 人设设计 | `system_prompt` 的作用、人设四要素（身份/语气/知识域/行为约束）、`ChatConfig` 配置 | 设计 3 种人设（足球解说员/迎宾员/科普老师），对比同一问题的不同回复 | 豆包 SDK |
| 3 | 语音交互闭环 | ASR（语音→文本）→ LLM（理解+生成）→ TTS（文本→语音）、`Speech.recognize_stream()` 流式识别 | 实现"语音问→机器人语音答"完整闭环 | 豆包 SDK |
| 4 | 多模态 Agent 实践 | 视觉+语音联动：检测到人→转向面向人→用设定人设打招呼→进入对话 | 迎宾 Agent：检测到人脸→"你好，我是 K1 迎宾员，有什么可以帮你？" | 豆包 SDK + 模块 2 检测 |

#### 3.5.5 主要产出

- 3 种不同人设的 `ChatConfig` 配置文件和对比报告
- 语音交互闭环脚本
- 迎宾 Agent 演示脚本

### 模块 6：动作模仿与数据迁移（6 课时）

#### 3.6.1 定位与衔接

- **前置**: K1 机器人基础（零力矩模式、关节运动）
- **后置**: 为模块 7 综合项目提供动作展示能力（自选方向 C）
- **角色**: 进阶模块——本课程最长的独立模块，建立「数据驱动行为」的认知

#### 3.6.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解动作数据的生命周期（示教→CSV→NPZ→训练→模型→部署）；理解示教（人类演示）与模仿学习的基本概念；理解训练的作用（从示教数据中学习运动策略） |
| **技能** | 能够使用 SDK 示教接口完成动作录制；能够查看和理解 CSV/NPZ 数据结构；能够在教师演示下理解训练流程；能够完成 MuJoCo 仿真验证和真机部署 |
| **素养** | 理解「数据质量决定模型效果」——示教动作的好坏直接影响机器人最终表现 |

#### 3.6.3 重点与难点

| 重点 | 难点 |
|---|---|
| 示教采集操作（零力矩拖拽→录制→保存） | 理解 NPZ 数据结构（为什么需要 NPZ 而不是直接用 CSV） |
| CSV/NPZ 数据结构理解 | 训练流程理解（学生不需要独立训练，但需要理解输入/输出/参数） |
| MuJoCo 验证 + 真机部署链路 | — |

> **GPU 策略**: 6 课时中仅第 3 课时（训练流程理解）需要 GPU 环境，采用**教师演示**模式——教师在 GPU 工作站上运行 `train.py --max_iterations 10`（几分钟完成），学生观察日志输出和 TensorBoard 曲线。其余 5 课时全部 CPU 可完成。

#### 3.6.4 课时与内容安排

| 课时 | 主题 | 核心内容 | 实验/活动 | GPU | 实验来源 |
|---|---|---|---|---|---|
| 1 | 示教采集体验 | 零力矩模式、拖拽录制、保存动作文件 | 学生在 K1 真机上拖拽录制一个挥手/点头动作，保存为 CSV | ❌ | Ch05 |
| 2 | 动作数据理解 | CSV 结构（帧数、关节数、帧率）、NPZ 结构（内部字段）、`inspect_motion_data.py` | 用脚本分析自己录制的 CSV 数据：多少帧？多长时间？哪些关节？ | ❌ | Ch06 |
| 3 | BeyondMimic 训练流程 | 训练环境、`train.py` 命令行参数（task/device/headless/max_iterations）、日志/TensorBoard | **教师演示**：`train.py --max_iterations 10`，学生观察训练日志和奖励曲线 | ✅ 教师机 | Ch07 |
| 4 | 模型导出与 MuJoCo 验证 | checkpoint→TorchScript 导出、MuJoCo 仿真验证、`deploy.py --mujoco --device cpu` | 使用预训练 MJ 模型，在 MuJoCo 中验证动作效果 | ❌ | Ch08 |
| 5 | K1 真机部署 | `deploy.py` 真机部署命令、安全注意事项、对比示教原始动作 vs 策略执行效果 | 将 MJ 模型部署到 K1 真机，观察机器人执行舞蹈动作 | ❌ | Ch08 |
| 6 | 综合调试与总结 | 完整链路回顾（示教→数据→训练→导出→验证→部署）、链路各环节的常见问题 | 分组讨论：如果部署效果不好，可能是什么环节出了问题？ | ❌ | Ch09 概念 |

#### 3.6.5 主要产出

- 学生录制的示教 CSV 文件
- 动作数据结构分析报告
- 训练流程观察笔记
- MuJoCo 验证截图 + 真机部署视频片段

### 模块 7：综合项目开发与展示（5 课时）

#### 3.7.1 定位与衔接

- **前置**: 模块 1-6（全部核心能力）
- **后置**: 课程终结性评价
- **角色**: 整合模块——将所有模块的能力串联为完整项目

#### 3.7.2 教学目标

| 类型 | 目标 |
|---|---|
| **知识** | 理解具身智能系统的架构分层（感知层→判断层→控制层→执行层） |
| **技能** | 能够将检测+定位+控制+状态机模块集成为完整系统；能够在真机环境下调试和优化参数；能够展示和讲解自己的项目 |
| **素养** | 建立「系统工程」思维——不只看单个模块，而是看整个链路是否通畅 |

#### 3.7.3 项目结构

**所有学生完成视觉踢球基础版（课时 1-3），课时 4-5 按兴趣方向分流：**

```
综合项目（5 课时）
├── 课时 1：项目启动 — 任务拆解、架构设计、模块分工
├── 课时 2：感知链路集成 — 检测+定位+判断联调
├── 课时 3：控制链路集成 — 追球+停稳+状态机联调 + 真机调试
├── 课时 4：自选方向扩展（三选一）
│   ├── 方向 A — 踢球增强：加入 VisualKick 踢球接口
│   ├── 方向 B — 语音 Agent：加入迎宾/解说人设
│   └── 方向 C — 动作展示：调用预训练模型展示模仿动作
└── 课时 5：项目展示 + 评价
```

#### 3.7.4 重点与难点

| 重点 | 难点 |
|---|---|
| 多模块联调的接口对接 | 真机环境下的时序问题（检测频率 vs 控制频率不匹配） |
| 真机安全调试规范 | 参数从仿真到真机的迁移（仿真参数在真机上可能不适用） |
| 项目展示与答辩 | — |

#### 3.7.5 评价方案

| 评价维度 | 权重 | 评价标准 |
|---|---|---|
| 感知链路 | 25% | 相机→检测→定位链路正常，检测准确率和定位判断合理 |
| 控制逻辑 | 25% | 追球策略有效，停稳条件合理，状态切换正确 |
| 调试与参数优化 | 20% | 关键参数有调优记录，能解释参数选择的原因 |
| 项目文档与展示 | 20% | 流程图清晰、参数记录完整、演示视频、答辩表达 |
| 扩展创新（自选方向） | 10% | 自选方向功能完成度和创新性 |

#### 3.7.6 主要产出

- 项目任务分配表和系统架构图
- 联调通过的完整系统代码
- 真机演示视频
- 项目文档（含流程图、参数记录、问题与解决方案）

## 四、模块衔接逻辑

### 4.1 衔接设计原则

每个模块的结束为下一模块的起点提供明确的输入：

| 衔接点 | 上游产出 | 下游使用 |
|---|---|---|
| M1→M2 | 相机话题订阅能力、RGB/深度图采集能力 | M2 直接使用图像数据流订阅 YOLO 检测结果 |
| M2→M3 | 结构化方位/远近判断输出（"足球在左侧，较远"） | M3 的 `Move(vx, vy, vyaw)` 直接消费方位信息 |
| M3→M4 | 基础追球控制（单循环） | M4 将单循环改造为三态 FSM，增加 SEARCH 和 HOLD |
| M4→M7 | 三态 FSM 控制脚本 | M7 综合项目将 FSM 作为行为架构基础 |
| M5→M7 | 语音交互闭环、Agent 人设配置 | M7 自选方向 B 调用语音能力实现迎宾/解说 Agent |
| M6→M7 | 动作部署链路、预训练模型 | M7 自选方向 C 调用动作模型展示模仿动作 |

### 4.2 衔接课时的教学处理

每个模块的第一课时前 5 分钟用于「衔接回顾」：快速回顾上一模块的关键产出，明确本节课将如何使用这些产出。每个模块的最后一课时后 5 分钟用于「衔接预告」：预告下一模块将要解决的问题，建立期待。

## 五、实验环境与设备要求

| 类别 | 要求 |
|---|---|
| 机器人 | 加速进化 Booster K1（建议 2-3 人/台） |
| 学生电脑 | x86 笔记本/台式机，Ubuntu 22.04 + Python 3.11，能连接 K1 WiFi |
| 软件 | BoosterOS SDK V1.0、ROS2 Humble、OpenCV、YOLO 检测节点 |
| 网络 | 学生电脑与 K1 在同一局域网 |
| 足球 | 标准足球（用于检测和追球实验） |
| GPU 工作站（教师） | NVIDIA GPU + CUDA + Isaac Lab（仅模块 6 第 3 课时教师演示用） |
| 安全设备 | 紧急停止按钮（STAND）、防护垫（追球实验时围在 K1 周围） |

### 安全规范

1. K1 运动实验时，学生必须站在机器人侧后方，不得站在正前方
2. 追球实验前确认场地无障碍物，地面平整
3. 每次真机实验前先执行 `robot.stand()` 确认机器人响应正常
4. 出现异常立即按下紧急停止按钮或调用 `robot.stand()`
5. 零力矩拖拽示教时，需扶稳机器人或使用支架
