# X课程 PPT 制作与图示验收规范

## 1. 适用范围

本规范补充 `02_共创规则与上下文/notebook开发规则.md` §8.11–§8.12，用于 X 课程 U2 起的 P6 制作与验收。U1 已完成并经用户审查的课件保持原样；本规范不要求回改 U1。

U1 是视觉基线，不是逐页模板。后续课件延续 U1 的画布、标题层级、白底、字体、页码、教学体例配色和代码页风格；页面结构根据本页要教的内容选择。不得为了追求变化而任意换色或堆装饰，也不要求每页都用同一种左右分栏版式。

## 2. 内容控制

- P6 的内容依据是已确认的 P5 大纲；Notebook、教学设计和已核实的一手资料用于校对事实、代码、操作和安全信息。
- PPT 制作者可以调整同一页内的信息排列、图文比例和版面表达，精简重复措辞后应保持信息等价。概念名称、代码、接口名、数值、条件、结论、操作要求、评价标准和安全信息必须保留；标记为逐字使用的内容原样使用。跨页移动、拆并页或改变页序，须先回填 P5 的页面对应关系；涉及教学内容或已确认页数、顺序的变更，取得确认后再制作。
- 发现内容缺失、冲突或需要新增教学信息时，先回到 P5 修订并取得确认，再继续 P6。不得用图示、案例或讲者备注悄悄补入未经确认的课程内容。
- 页标题和正文应让学生直接读懂；素材来源、版本、待补项目等制作信息不放进学生正文，可放在备注或制作台账。

## 3. 版式按信息关系选择

版式由信息之间的关系决定。以下是选择依据，不是必须逐项使用的模板清单：

| 信息关系 | 优先考虑的表达 | 核查重点 |
|---|---|---|
| 步骤、状态变化、因果链 | 流程图、时间线、阶段序列 | 箭头方向、先后与条件是否准确 |
| 部件层级、系统组成、软硬件关系 | 分层结构图、树状图、系统框图 | 节点归属、层级和接口是否准确 |
| 多方案或多概念辨析 | 对照表、并列流程、同尺度示意 | 比较维度对等，不能把不同层次硬并列 |
| 机器人本体、关节、传感器、接口位置 | 实物照片标注、结构示意图 | 标注指向真实部件，照片型号与课程对象一致 |
| 软件或 BoosterStudio 操作 | 对应版本的实际截图、编号步骤 | 截图与真实界面一致，操作顺序可复现 |
| 代码、输入输出、调试 | 代码片段配运行结果或关键状态 | 代码与 Notebook 对应，不伪造运行结果 |
| 数据、测量、实验结果 | 原始数据表、坐标图或比较图 | 单位、坐标、样本范围和来源齐全 |
| 课堂提问、练习、总结 | 留白明确的问题页、任务页或归纳图 | 学生要做什么、依据什么判断清楚 |

图形用于解释结构、关系或变化。若删去图形后信息仍一样清楚，且图形没有增加辨析价值，应优先简化页面。卡片、图标和装饰不能代替有明确含义的图示。

### 3.1 固定规则与可调整项

| 层次 | 保持不变 | 允许调整 |
|---|---|---|
| 教学内容 | 已确认 P5 的页面任务、必含信息、事实、条件、比较维度与关系；Notebook 对应代码 | 同页内的信息等价表述、图解方式、重点标注 |
| U1 视觉基线 | 16:9 白底、微软雅黑、章节标签/主标题/副标题层级、页码、教学体例配色、浅底深字代码风格；具体参数见配色规范和开发规则 | 正文区的结构、图文比例、对象尺寸与分组、关系线走向、留白 |
| 版式参考 | 内容需要的可读性与完整性 | U1 样页和参考库的构图可改；55%/45% 等比例只作起点，按实际内容调整 |
| 图像与图示 | 真实对象、来源、技术关系、关键标注、必要裁切范围和授权条件 | 不损害上述信息的裁切、重排、放大与标注位置 |

后续逐课积累已验收的参考页即可，不要求先制作完整模板库。参考页需注明适合表达的内容关系和使用限制。连续页面可以沿用构图，例如比较同一组实验结果；只有重复版式妨碍理解时才调整，不设置版式数量或装饰数量指标。

## 4. 图示和素材

- **实物优先用真实素材**：涉及 K1、部件、传感器、BoosterStudio、APP 或实验现象时，优先使用本课程对应设备与软件版本的实拍、录屏截图或官方资料图。泛化图库图不能冒充课程中的真实设备或界面。
- **概念图明确其性质**：真实照片难以表达原理时，可以用原创结构图或概念示意图；图注标明“示意图”或“概念示意”，不能让学生误认为照片记录了真实实验或产品结构。
- **不虚构证据**：不伪造软件界面、运行输出、实验数据、产品细节和引用来源。无法取得必要素材时，在审查稿中注明缺项和所需素材；该页不能以“已完成”状态通过确认⑥。
- **引用可追溯**：外部图片、截图、数据和图表记录发布方/作者、原始链接或文件、版本/发布日期、许可或使用依据、PPT 页码及裁切或改绘说明。公开展示前核对授权范围。官方资料也需记录具体文档或页面，不能只写“网络”。
- **生成式素材**：仅用于不承载事实证据的概念表达；台账标记为生成素材及使用工具。不得将生成图作为真实产品照、实验结果、软件截图或未经核实的结构依据。
- **图形质量**：流程、架构、对照、标注图优先用可编辑的 PPT 原生形状或矢量图。检查箭头起止、连接关系、单位、图例、标注落点、缩放清晰度和色彩对比；避免截图文字模糊或图形被裁切。

每课保留轻量素材台账，至少记录：页码、素材用途、来源/作者、版本或日期、授权状态、处理方式、核验人或核验状态。学生页按需要放简短来源注，完整出处可集中放在课末来源页；来源页不能替代素材台账。

需要在使用页署名的素材，应按其许可条件在使用页保留署名；不得统一移到课末。作者、来源、许可、技术适用性分开核查。标为“用户提供”或“官方发布”，均不代表授权与版本已经核验。

### 4.1 关键图示的制作说明

流程、架构、数据流、实物标注和实验结果等关键图示，在现有 P5 配图说明中补齐以下信息；若 P5 已有充分说明，直接引用，避免另写一份重复文档。

| 字段 | 应写清的内容 |
|---|---|
| 页面任务与内容定位 | 对应 P5 页号/条目，学生看图后要能辨认、比较或解释什么 |
| 图中对象 | 必须出现的节点、部件、状态、数据及准确名称 |
| 对象之间的关系 | 箭头表示调用、数据传递、先后还是控制；标出方向、条件和起止点；并列不画成因果，层级不画成时间线 |
| 必留信息 | 接口名、单位、坐标、前提、限制、安全要求和技术来源定位；关键标签不能只留在备注里 |
| 素材与呈现 | 真实照片/截图/测量结果/原创示意的选择；对应型号或软件版本；需保留的标注区域；是否要求对象可编辑 |
| 核验方式 | 用哪份已核实资料、Notebook 单元或实拍核对；尚缺什么，谁确认或当前核验状态 |

技术事实优先取自知识库内已同步的一手资料。若公开图库只提供泛化场景照，可作场景说明，不能据此判断机器人内部结构、接口位置或软件能力。技术图中的视觉关系也属于教学内容，不能由绘图工具自行补全。

流程节点、文字、连接线和标注优先保留为可编辑对象并按含义分组。SVG 便于保留矢量清晰度，但整张 SVG 插入 PPT 不等于节点与文字已原生可编辑；最终应在 PowerPoint 中抽查选取、文字修改及连线调整。需要可更新数据的统计图/表时，优先使用原生图表/表格，不能仅以“图形可选中”判定达标。

## 5. P6 制作与验收

在现有 P5→P6 和确认⑥流程内完成以下检查，不增加确认闸门：

1. **制作前**：核对 P5 确认状态，记录其文件和版本，列出各页必须出现的内容、代码/数据/安全要求、所需真实素材及来源状态。逐页标出 P5 定位；代码再标 Notebook 标题或单元编号，外部技术事实补具体资料定位。
2. **排版时**：根据页面任务和内容关系选择版式，再填入已确认内容与可核验素材。首批 3–5 页选取实际存在的典型页型，内部检查字体、标题层级、代码、长标签和关键图示；发现共性问题先修正生成方法，再扩展余页。这是 P6 内部检查，不增加用户确认闸门。
3. **密度处理**：内容过密影响投影阅读时，先重组正文区或移除无用装饰；仍需拆页时按 §2 回填 P5 并确认相关变更，不靠持续缩小字号塞入。
4. **交审前逐页核对**：内容与 P5 一致；代码与 Notebook 一致；操作和界面对应真实流程；图示关系与事实相符；图片清晰、比例合适、来源及授权状态已记录。图中没有出现的条件、对象或关系不能用“页面美观”判为通过。
5. **成品检查**：导出最终 PPTX 后逐页渲染检查排版、裁切、错位、文字溢出和清晰度；同时核对文字提取、页数、页面顺序、链接/媒体、可编辑性和正常打开情况。技术检查、内容核对、视觉检查分别记录结果；工具未覆盖或未实际执行的项目写明未验证。修改后重检受影响页面，公共组件变更要覆盖其使用页。
6. **确认⑥**：交付可授课版本，清除占位内容、临时标注、虚构输出和缺失引用。若关键实拍或界面素材受现场条件限制，明确列为审查稿，在替换、复核后再申请确认⑥。

每课在原有交付记录中附简短检查表即可，记录“页号—P5 定位—内容核对—图示/来源核对—视觉检查—问题及状态”。不要求额外维护一套重复台账。P6 检查所需的临时渲染图不替代 P7，面向学生的全课程 PDF 仍在课程完成后统一导出。

版式库可以从已验收页面中归纳，逐步扩展到流程、结构、对照、实物标注、软件操作、代码结果和任务评价等类型。复用的是栅格、字号、间距、标题和组件的视觉规则；每页仍按实际内容确定表达，不复制无关内容或装饰。

## 6. 与 PPT Master 的关系

### 6.1 本次核验范围

2026-10-20 根据用户提供的项目地址核对官方 README、生成流程、模板创建、页面执行、可视化参考和网络图片署名规则。仓库基准为提交 `c350bc31e6d43b7bcf5234183d650ba8f9f4c9d7`，技能入口版本标记为 `6.7.2`。本节结论基于文档与流程规则阅读，未安装或运行该工具，未开展与 U1 同源内容的生成对照；示例站只核对项目说明，不据此宣称课件质量已验证。

PPT Master 是在 Agent 环境中执行的 PPT 制作工作流，覆盖内容分析、设计规范、页面制作、质量检查和原生 PPTX 输出。此前将它概括为一般自动排版工具的判断不充分，以本次核验为准。

### 6.2 可借鉴的方法及课程侧处理

| 官方资料中的做法 | X 课程的采用方式 |
|---|---|
| 将内容、对象关系、字体和配色等约束与构图参考分开；页面制作者负责最终表达 | 按 §2、§3.1 固定内容与 U1 视觉规则，放开正文区构图；用户确认的内容限制优先于工具默认改写权限 |
| 用页面任务决定信息层级和对象组合，参考图表不锁定最终构图 | 按 §3 选版式；U1 样页供参考，不要求后续单元复制同样的页序和图文比例 |
| 模板区分 Brand、Style、Layout、Deck，分别复用身份、表达方法、结构和完整应用系统 | 先提取 U1 的视觉参数及代表性页型。若以后接入工具，再按所需保留范围选择模板路线；本次不创建或注册 PPT Master 模板 |
| 内容事实可关联来源标识，保持标签、数值、单位、层级与关系，禁止用模板样例替代实际内容 | 将 P5 条目、Notebook 单元和技术资料定位写入制作记录；不要求现有课程先转换为工具专用 JSON |
| 网络图片记录来源与许可，按许可在使用页署名；缺必需素材时阻止正式导出 | 采用 §4 的素材台账，并增加设备型号、软件版本和技术适用性核验；“用户提供”素材也检查授权状态 |
| 生成中有早期检查、最终检查和导出检查；原生对象可继续编辑 | 采用 §5 的代表页内部检查与成品检查，并保留逐页视觉审查和教学核对；不能以导出成功取代上述检查 |

这些方法对我们的 P6 有参考价值。教学设计与实验验证仍按 P1–P5 执行；PPT Master 的完整规划流程与课程审核职责不同，不能据此判定哪套流程全面更科学。对我们的目标，采用现有内容确认流程并补强视觉生产与检查更合适。

### 6.3 需要保留的差异

- 官方默认生成路线包含设计确认与质量检查，并非无审核的一键流程。课程采用既有确认①–⑥，不平行增加一套确认程序；快速路线也不作为绕过课程审核的入口。
- 官方生成流程将逐页视觉回看列为按需触发；X 课程按 §5 保持逐页渲染检查。自动检查不能确认技术图的含义、截图真实性及课堂投影效果。
- SVG 转原生 PPTX 属于可选的后续实现路线，本次保留现有生成方式。官方自由设计和仅风格复用路线默认是页面本地对象；真正的母版/布局继承依赖结构化路线，不能混称为同一种模板复用。
- 官方图表/表格的原生数据对象输出需显式选择 `--native-charts-and-tables`；默认可编辑形状不等于带数据的原生图表。以后试用时应分别检查文字、节点、连线、图表数据和表格单元。
- 插画、纹理、动画和特殊造型按教学需要使用，不为展示工具能力设置配额。真实产品、界面和实验结果遵守 §4；生成式图片仅限标明性质的概念表达。

### 6.4 后续试用的条件

若决定试用工具，应在某课 P5 已确认、允许进入 P6 后，用同一份已确认内容选择 3–5 页，覆盖该课实际需要的知识图解、操作截图、代码结果或任务评价。保留 U1 视觉规则，对照内容遗漏与新增、图示关系、素材真实性与授权、投影可读性、可编辑性和返工用时。记录缺陷及修订量，不以“看起来更精美”或单一综合分数决定采用。

本次仅更新规范，未启动 U2 或其他单元的 P6，也未修改 U1 成品。
