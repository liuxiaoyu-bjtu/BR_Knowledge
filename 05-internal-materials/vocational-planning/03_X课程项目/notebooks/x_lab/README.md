## 这些文件与SDK的关系

`x_lab`是课程编写的普通Python文件夹，提供可以打开阅读的辅助函数。SDK负责取图、检测、语音、动作和踢球控制；附件把球坐标近似计算和重复使用的调用整理在一起。它不替代SDK，无需安装同名网络包。文件夹名可以理解为本课程的实验代码，函数名不是SDK新增接口。

U7学习这些技术怎样工作，U8把它们用于本组需求。U8的程序保存在`u8_team.py`，Notebook负责逐格加载、测试、记录；本组不必把已经重复核对的等待和收尾代码抄到每个函数里，但应能找到实际SDK调用、解释输入输出与退出条件。

## 放置文件

把`x_lab/`、各课Notebook和`u8_team_template.py`放在同一工作目录。不需要安装本文件夹，Notebook中的Python可以直接导入。

```text
notebooks/
├── U7-L2_足球定位与自动踢球.ipynb
├── U7-L3_多线程协作.ipynb
├── U7-L4_多模态流程衔接.ipynb
├── U8-L2_分主题开发模板.ipynb
├── U8-L3_联调模板.ipynb
├── u8_team_template.py
└── x_lab/
    ├── __init__.py
    ├── ball_position.py
    └── flows.py
```

| 文件 | 提供什么 | 在哪里学习和使用 |
| --- | --- | --- |
| ball_position.py | 按实测对应点建立球位置近似映射；检查分辨率、范围及独立误差 | U7-L2标定、核对；U7-L4和踢球项目复用 |
| flows.py | 检测、有限文本播报、致意、短时踢球及资源收尾的局部参考 | U7-L3/L4、U8-L2/L3 |
| ../u8_team_template.py | 本组程序起点，包含参数、步骤和普通函数 | U8-L2首次复制为u8_team.py，后续保留本组修改 |

## 按课程打开和阅读

| 课程 | 打开哪里 | 重点读什么 |
| --- | --- | --- |
| U7-L2 | `ball_position.py` | `select_ball`筛类别，`ball_pixel`取框下缘中点；`build_calibration`用实测点建换算，`pixel_to_robot`检查范围再估计，`verify_calibration`用独立点核对 |
| U7-L3 | `flows.py`的`new_session`、`say` | session只是保存资源的字典；合成、取得音频、播放的SDK调用，以及保存句柄的位置 |
| U7-L4 | `flows.py`的观察、致意和试踢函数 | 返回原因如何交给外层判断，任务句柄与管理器分别怎样退出 |
| U8-L2 | 本组`u8_team.py` | 配置→`validate`→`observe/introduce/act`→`run_project`；先读主流程的四次调用，再改本组函数 |
| U8-L3/L4 | 继续使用本组同一文件 | 版本、问题修改、日志与现场证据，不重新复制模板 |

`run_project()`按“观察→介绍→再观察→行为”明确写出调用，前一步返回“完成”才继续。`STEPS`是这份基础顺序的核对表；增减或改变流程时，要一起修改主流程、配置检查、接口和用例。介绍、行为的独立测试调用本组函数，避免测试了附件默认实现，却没有测试本组改动。

`session`不是语音chat会话。它保存本程序的机器人/语音对象、音频句柄、动作句柄和踢球管理器，以及最近观测等记录。`idle(session)`只检查这个字典中的资源，不代表其他连接或Notebook都已退出。

## 修改、保存和加载

1. 从本组目录打开U8-L2，运行STEP 01，首次复制模板为`u8_team.py`。
2. 在文件列表或代码编辑器打开本组文件，按L1需求修改配置和函数，递增`VERSION`并保存。
3. 回Notebook运行加载格，核对打印版本、主题和问题列表；后续修改也须保存后reload。已有任务时先收尾，不能运行中重载。
4. 按观察、介绍、行为、整体的顺序测试；把程序结果与现场表现分开写入记录。
5. 保留本组文件、依赖和归档版本，下一课直接加载；重启内核不会自动取消机器人任务。

出现`No module named x_lab`或`u8_team`时，检查`Path.cwd()`和文件层级：Notebook、`u8_team.py`与`x_lab/`应在同一目录，`__init__.py`保留在文件夹内。语法错误看报错文件和行号，修改保存再加载，不重新复制覆盖本组工作。

这些文件是课程附件，函数名称不属于BoosterOS SDK。可打开查看其中的真实SDK调用。图像推理和机器人调用还需课程中已经使用的`boosteros`及视觉依赖；标定计算使用NumPy。导入附件不会连接机器人，也不会发运动指令。

`ball_calibration.json`由本机实际标定与独立核对生成，不能借用其他机器或姿态的数据。球框下缘中点与地面位置之间是近似关系；头部、站姿、分辨率、球型和地面变化会影响结果。附件没有补偿动态姿态，静态验证不能替代足球步态下的验证。

`u8_team.py`、标定文件、JSON日志和视频是本组产物，按Notebook要求保存。重新复制模板会丢掉本组修改，因此代码先检查文件是否已存在。

JSON日志保存版本、每步原因和任务状态；现场声音、动作、球去向与人工停稳检查还需表格或视频。完成一条日志并不自动证明需求已经满足。
