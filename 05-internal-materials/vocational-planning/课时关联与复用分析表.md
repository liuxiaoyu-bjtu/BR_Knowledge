| 2 | 检测结果深度解析 | **清华工训课 Ch11** §11.3、§11.5（检测结果字段详解、JSON 结构）; 实验代码 `soccer_detection_utils.py`（JSON 封装逻辑） | 🟡 中等改编 | ① JSON 检测结果字段详解：`class_name`（类别名）、`confidence`（置信度）、`bbox`（四坐标检测框）、`norm`（归一化偏差量）; ② bbox 坐标含义：`(x_min, y_min, x_max, y_max)` 在图像像素坐标系中的位置; ③ 置信度的含义——模型对检测结果的确信程度（0~1） | 逐字段解读检测输出；在采集的图像上手绘 bbox 位置（手工标注），建立"检测框在画面哪里"的直观认知 |

| 4 | 方位判断：左/中/右 | **清华工训课 Ch12** §12.1-12.2（图像坐标与机器人坐标，但不深入单目几何）; 此为高职简化版——仅用 bbox 启发式判断，不使用相机模型 | 🔴 重写/新建 | ① bbox 中心点 x 坐标 → 归一化到画面宽度比例; ② 三段式方位判断规则：`x_ratio < 0.35` → 左侧、`0.35~0.65` → 中间、`> 0.65` → 右侧; ③ 方位判断的边界模糊问题——阈值的选择影响判断稳定性 | 将足球放在机器人前方不同位置（左/中/右），实时输出方位判断结果；记录边界位置（球在左中交界处）的判断波动 |
| 5 | 远近判断：大/中/小 | **清华工训课 Ch12** 扩展（原课使用深度球面拟合/单目几何计算距离，此为高职简化版——仅用 bbox 面积启发式判断） | 🔴 重写/新建 | ① bbox 面积 → 归一化到画面面积比例; ② 三段式远近判断规则：`area_ratio > 0.15` → 近、`0.05~0.15` → 中、`< 0.05` → 远; ③ 远近判断的局限性——足球角度（正面/侧面）会影响 bbox 面积 | 将足球放在不同距离（0.5m/1.0m/1.5m/2.0m），观察 bbox 面积变化；记录远近判断的准确率 |
| 6 | 检测+判断整合 | 综合实验（无直接对应章节，整合模块 2 全部技能）; 参考 **清华工训课 Ch12** §12.7（定位结果与控制输入）的输出格式 | 🟡 中等改编 | ① 将方位判断和远近判断整合为统一函数，输出结构化语句（如"足球在**左侧**，距离**较远**"）; ② 判断结果的置信度标注——当 bbox 面积处于阈值边界时标注"判断不确定" | 编写整合脚本，实时输出结构化方位/远近判断；测试不同位置/距离组合（9 种场景 = 3 方位 × 3 远近），记录判断准确率 |

**模块 2 小结**：6 课时中 1 课时直接复用（Ch11 检测入门），3 课时中等改编（Ch11 扩展 + 整合），2 课时重写新建（方位/远近的 bbox 启发式判断——这是高职课程相比清华工训课的最大简化创新）。整体复用度约 40%，但这是**主动简化**而非被动缺乏。

## 模块 3：目标驱动运动控制（4 课时）

| 课时 | 主题 | 关联已有课程/内容 | 调整程度 | 知识概念 | 实践/实操 |
|---|---|---|---|---|---|
| 1 | 从检测到运动 | **清华工训课 Ch14** §14.1-14.3（追球控制任务、足球位置输入、距离误差与角度误差）; 实验代码 `stable_chase_controller.py`（核心控制逻辑）; **L4 通识课 L8**「感知驱动闭环」（人脸检测触发挥手——相同的"感知→行动"模式） | 🟡 中等改编 | ① `norm=(error_x, error_y)` → `Move(vx, vy, vyaw)` 的映射逻辑：水平偏差 → 转向速度（vyaw），垂直偏差 → 前进速度（vx）; ② P 控制器简化版——比例控制（不引入 I/D 项），`vyaw = Kp * error_x`; ③ K1 运动控制接口：`robot.move(vx, vy, vyaw)` 各参数含义和安全范围 | 仿真实验：给定固定目标坐标（不接真实检测），验证机器人能否转向对准并前进 |
| 2 | 追球控制策略 | **清华工训课 Ch14** §14.4（速度控制与停稳）; 实验代码 `chase_control_utils.py`（减速系数计算） | 🟡 中等改编 | ① 距离-速度分段映射策略：`chase_slow_dist`（慢速区）vs 全速区，远快近慢; ② 角度修正——边前进边转向的复合运动; ③ 速度参数安全边界：`vx_limit` 不超过 K1 最大安全速度 | 真机实验：启动检测节点 → 定位 → 追球，观察机器人追踪足球的行为（能否追上、是否跑偏） |
| 3 | 停稳逻辑与参数调优 | **清华工训课 Ch14** §14.4-14.5（停稳条件、迟滞设计）; 核心参数：`stop_dist=0.78m`、`chase_slow_dist=1.35m`、`hysteresis=0.22m` | 🟢 直接复用 | ① 停稳条件设计：距离阈值（`stop_dist`）+ 确认时长（连续 N 帧满足条件才判定停稳）; ② 迟滞（Hysteresis）设计原理：进入阈值 ≠ 退出阈值，防止边界抖动——为什么需要"进入阈值 0.78m"和"退出阈值 0.78+0.22=1.00m"不同; ③ 参数调优方法论：一次只改一个参数，记录效果对比 | 调参实验：分别改变 `stop_dist`（0.5/0.78/1.0m）和 `hysteresis`（0.1/0.22/0.4m），每组测 3 次追球→停稳，对比停稳精度和稳定性 |
| 4 | 目标丢失与异常处理 | **清华工训课 Ch14** 扩展（原课侧重正常追球流程，异常处理非独立课时）; 参考 **L4 通识课 L13**「稳态跟随与丢失处理」的异常行为设计思路 | 🔴 重写/新建 | ① LOST 状态：目标丢失的定义（连续 N 帧无有效检测）; ② 丢失后的安全策略：立即停止（优先安全）→ 头部搜索 → 身体搜索; ③ 工程中的异常处理原则——宁可停下来也不要乱动 | 模拟目标丢失场景：用挡板遮挡足球 → 观察机器人是否安全停止 → 移除挡板 → 观察是否恢复追球 |

**模块 3 小结**：4 课时中 1 课时直接复用（停稳参数），2 课时中等改编（检测→运动映射、追球策略简化），1 课时重写新建（异常处理独立成课）。整体复用度约 55%。Ch14 的 `stable_chase_controller.py` 是核心复用代码，但高职层面去掉了空间定位依赖（norm 直接驱动而非 (x,y,z) 坐标）。

## 模块 4：状态机与任务流程（4 课时）

| 课时 | 主题 | 关联已有课程/内容 | 调整程度 | 知识概念 | 实践/实操 |
|---|---|---|---|---|---|
| 1 | 为什么需要状态机 | **清华工训课 Ch13** §13.1-13.2（行为状态、FSM 概念）; **L4 通识课 L13**「稳态跟随与丢失处理」（三态切换的直观体验） | 🟡 中等改编 | ① 单循环控制的问题：无法区分"正在追球"和"已经停稳"——到达目标后持续微调（抖动问题）; ② 有限状态机（FSM）的基本概念：状态（State）、转移条件（Transition）、动作（Action）; ③ 本课程三态设计：SEARCH（搜索足球）→ CHASE（追球）→ HOLD（停稳等待） | 观察无状态机的追球行为：到达停稳位置后机器人持续微调（抖动），对比有状态机的效果——理解 FSM 解决什么问题 |
| 2 | FSM 实现 | **清华工训课 Ch13** §13.3-13.5（TRACK/FIND/SCAN 状态切换、程序案例）; 实验代码 `ball_search_fsm_controller.py`（三态 FSM 参考） | 🟡 中等改编 | ① Python 枚举（Enum）定义状态; ② 状态转移条件表（当前状态 + 条件 → 下一状态）; ③ FSM 主循环结构：`while True: 感知 → 判断转移 → 执行动作 → sleep` | 编码实现三态 FSM（SEARCH→CHASE→HOLD），在仿真中验证状态切换逻辑正确 |
| 3 | 搜索状态设计 | **清华工训课 Ch13** §13.4-13.6（丢球搜索逻辑、头部扫描 + 身体搜索）; 实验代码 `football_tracking_utils.py`（头部控制 + 身体原地搜索） | 🟡 中等改编 | ① SEARCH 状态的两种搜索策略：头部搜索（yaw 扫描，不动身体）vs 身体搜索（原地旋转，带动相机）; ② 搜索参数：扫描范围（yaw ±60°）、扫描速度（角速度）、搜索超时（多久放弃）; ③ 搜索优先级：先头后身——头部搜索省电且安全 | 真机实验：遮挡足球 → 触发 SEARCH 状态 → 观察头部扫描行为 → 仍找不到 → 触发身体旋转搜索 → 发现足球 → 切回 CHASE |
| 4 | 状态机调试与优化 | **清华工训课 Ch13** 扩展（原课无独立调试课时）; 参考 **清华工训课 Ch17** §17.4（系统联调方法） | 🔴 重写/新建 | ① 状态转移日志——在每个转移点打印 `[时间] 状态A → 状态B，原因：xxx`; ② 转移条件参数调优：搜索超时、停稳确认帧数、丢失判定帧数; ③ 状态转移图的可视化绘制（流程图工具或手绘） | 添加状态日志输出，运行完整追球流程，收集状态切换日志；画完整状态转移图并标注每个转移条件的具体参数值 |

**模块 4 小结**：4 课时中 3 课时中等改编（Ch13 FSM 核心内容简化——去掉 BT 扩展，聚焦三态 if-else），1 课时重写新建（调试方法独立成课）。整体复用度约 55%。关键差异：清华 Ch13 的 FSM 是 ROS2 多节点架构（detector + FSM controller 分离），高职层面可简化为单脚本 FSM。

| 课时 | 主题 | 关联已有课程/内容 | 调整程度 | 知识概念 | 实践/实操 |
|---|---|---|---|---|---|
| 1 | LLM 基础认知 | **豆包集成文档** §一~三（概述、技术架构、快速开始）; **BoosterOS SDK V1.0** `robot.chat()` 接口; **L4 通识课 L4**「让 K1 开口说话」（语音+动作的脚本化表演——最早的"对话"体验） | 🔴 重写/新建 | ① 大语言模型（LLM）是什么——能理解自然语言并生成回复的 AI 模型（类比例子：像一个读过很多书的对话伙伴）; ② LLM 能做什么：知识问答、代码生成、角色扮演、翻译……; ③ SDK 调用方式：`robot.chat(prompt)` 一行代码即可对话; ④ 本课不涉及 Transformer/注意力机制等底层原理 | `robot.chat("你好")` → 观察回复；`robot.chat("请用一句话介绍什么是具身智能")` → 理解 LLM 的知识问答能力；尝试不同问题类型（知识/创作/闲聊） |
| 2 | Agent 人设设计 | **豆包集成文档** §四（教学应用场景——不同场景下的对话风格）; **BoosterOS SDK V1.0** `ChatConfig(system_prompt=...)` 接口; **L4 通识课 L4** 的人设概念（让 K1 扮演不同角色） | 🔴 重写/新建 | ① Agent 人设的概念——同一个大模型，不同的 system_prompt 创造完全不同的用户体验; ② 人设四要素设计法：**身份**（你是谁）、**语气**（怎么说话）、**知识域**（懂什么）、**行为约束**（不能做什么）; ③ `ChatConfig(system_prompt=...)` 的工程实现——一行配置改变机器人人格 | 设计 3 种人设的 `ChatConfig`：① 足球解说员（激情/专业/术语）; ② 迎宾员（礼貌/引导/克制）; ③ 科普老师（易懂/举例/鼓励提问）; 用同一问题（如"介绍一下你自己"）测试 3 种人设，对比回复差异 |

**模块 5 小结**：4 课时全部为 🔴 重写/新建。这是高职课程中**原创度最高**的模块——豆包集成文档和 SDK 提供底层 API，但 4 课时的教学内容（LLM 认知→人设设计→语音闭环→多模态 Agent）是全新编排。L4 通识课 L4/L8 提供了部分概念铺垫但深度和结构完全不同。整体复用度约 15%（仅 API 调用层面）。
