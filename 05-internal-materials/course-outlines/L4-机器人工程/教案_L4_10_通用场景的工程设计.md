|**知识与技能**|1\. 理解机器人视觉应用的通用闭环结构 ——「图像话题 → 检测节点 → 结果话题 → 行为节点 → 机器人反馈」，认识到「视觉算法可换、系统结构不变」。<br>2\. 掌握「场景设计三问」—— 看什么 / 什么时候触发 / 做什么；能用三问描述任意一个机器人应用场景。<br>3\. 理解颜色识别的核心：BGR 与 HSV 的差异、为什么用 H 阈值筛颜色、6 步处理流水线（BGR→HSV→mask→去噪→最大块→发布）。<br>4\. 理解形状识别的核心：灰度→模糊→Canny 边缘→轮廓→多边形近似；掌握三条判定规则：circularity \> 0\.83 且 vertices ≥ 6 判圆，vertices == 4 且 0\.90 ≤ aspect\_ratio ≤ 1\.10 判方，否则判长方形。<br>5\. 理解模板匹配的核心：matchTemplate 用一张参考图在画面中搜索最相似位置，相似度 ≥ threshold \(本课 0\.65\) 即认为找到；理解参数 template\_path / template\_name / threshold 的作用。<br>6\. 能在第 9 课 python\_demo\_pkg 的基础上，看懂本课新增的 6 个 \.py 节点（color/shape/template × detector \+ tts\_speak）\+ 3 个 launch \+ templates/ 目录。<br>7\. 掌握「检测节点 vs 行为节点」职责分离设计：检测节点只发布 String 结果话题、行为节点只订阅结果并调用 TTS；理解 cooldown\_sec 防止刷屏的工程价值。<br>8\. 知道如何从零创建一个 ROS2 功能包模板 —— ros2 pkg create 命令、自动生成的目录骨架、手动需要添加的内容（节点 / launch / templates / setup\.py 修改）；本课老师已完成，学生看懂全过程即可。<br>9\. 能完成 4 个实践：查看功能包结构 → 运行颜色场景 → 运行形状场景 → 运行模板匹配场景；能用「错误现象 → 沿链路定位 → 排查命令」三步法自主调试。<br>10\. 理解「好的机器人场景设计」5 条标准（闭环完整 / 运行稳定 / 逻辑清晰 / 可一键启动 / 可扩展），完成从「程序思维」到「系统思维」的认知转变。||
|**过程与方法**|1\. 通过「回到第 8/9 课闭环 — 如果检测对象变了，系统要不要重写」的反思导入，建立「换场景不换结构」的认知主线。<br>2\. 通过「设计三问」表格把抽象的「场景设计」变成可操作的方法论 —— 学生面对任何新场景都能套用。<br>3\. 通过三种算法的「原理 → 流水线 → 关键代码 → 对比表」四段式讲解，建立对颜色 / 形状 / 模板各自适用场景的工程判断力。<br>4\. 通过「检测节点 \+ 行为节点」职责分离的拆解，让学生体会到 ROS2 工程化设计中「节点单一职责」的重要性。<br>5\. 通过「老师课前做了什么 \+ 你需要知道什么」的双栏对比，让学生看懂功能包创建的完整过程，但不必占用课堂时间动手。<br>6\. 通过 4 个递进实践（看结构 → 跑颜色 → 跑形状 → 跑模板）\+ 同样的 launch 命令模式，让学生亲身体验「换算法 / 不换工作流」。<br>7\. 通过「错误现象 → 沿链路定位 → 排查命令」三栏表，建立场景系统的故障诊断方法。<br>8\. 通过「好设计 5 标准 \+ 程序思维 vs 系统思维」收束，让学生意识到本课的真正升级是「从写程序进入设计系统」。||
|**情感态度与价值观**|1\. 体会「一个想法 → 一个可运行系统」的工程乐趣 —— 设计三问让学生意识到「自己也可以设计机器人应用」。<br>2\. 体会模块化、可复用设计的优雅 —— 同一套闭环骨架可以承载完全不同的视觉任务。<br>3\. 通过职责分离原则建立工程审美 ——「检测只看 / 行为只听 / 各司其职」是大型机器人系统的共同设计语言。<br>4\. 在「程序思维 → 系统思维」的转变中体会到：写出一个能跑的功能是起点，让多个功能稳定协作才是工程目标。||
