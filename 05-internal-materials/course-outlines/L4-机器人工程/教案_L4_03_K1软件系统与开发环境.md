|**教学目标**|||
|**知识与技能**|1\. 理解 K1 是一台运行 Ubuntu 操作系统的机器人电脑，建立「控制 K1 = 两台电脑通信」的认知模型。<br>2\. 了解 K1 软件栈的四层结构：Ubuntu 操作系统 / ROS2 通信框架 / Booster SDK·API / 学生程序代码，能说明每一层的角色与上下层关系。<br>3\. 理解 SSH 是远程登录 Linux 设备的加密协议，掌握 ssh 用户名@IP 命令格式以及 booster / 123456 / 192\.168\.10\.102 三个必备信息。<br>4\. 区分 K1 的有线与无线两种网络连接方式，知道有线适用于首次配置与排查、无线适用于日常课堂开发。<br>5\. 掌握 Linux 终端的三个基础命令：pwd（查看当前路径）、ls（列出当前目录内容）、cd（切换目录），并知道更多命令可借助大语言模型自学。<br>6\. 了解 Booster Studio 是把 SSH 连接、终端、Notebook、状态监控打包为图形化界面的开发工具。<br>7\. 完成「登录 → 选择 K1 → 打开 Notebook → 粘贴点头代码 → 运行」的完整开发链路操作，让 K1 完成一次连续点头动作。||
|**过程与方法**|1\. 通过对照「看得见的硬件 \(第 2 课\)」与「看不见的软件 \(第 3 课\)」，把硬件认知延伸到软件认知。<br>2\. 通过「机器人 = 一台带行动能力的 Linux 电脑」这一类比，建立后续学习所需的核心心智模型。<br>3\. 通过教师演示与小组协作，完成开发链路的端到端操作，体验「代码 → API → 控制 → 硬件反馈」的因果传递。<br>4\. 通过课堂连续提问、思考题与故障排查练习，培养面对工程链路问题时的分层定位思维。||
|**情感态度与价值观**|1\. 形成「机器人控制 = 软件 \+ 硬件协同」的整体认识，认识到代码是控制机器人的根本入口。<br>2\. 在第一次让 K1 通过代码做出动作的体验中，建立对编程与机器人控制的兴趣与成就感。<br>3\. 在故障排查环节中形成「按层定位、由近及远」的工程思维，习惯用「检查 → 推理 → 验证」处理异常。<br>4\. 借助大语言模型自学 Linux 命令的过程中，形成主动求知与持续学习的习惯。||
|**教学重点**|1\. K1 软件栈四层结构与各层角色的认知建立。<br>2\. SSH 命令格式与 IP / 用户名 / 密码三要素的对应关系。<br>3\. Booster Studio 的实操闭环：登录 → 选 K1 → Notebook → 粘贴 → 运行 → 看反馈。||
|**教学难点**|1\. 理解「在自己电脑点击运行，K1 会做出动作」背后的链路——这是学生最容易停留在「魔法」直觉的地方。<br>2\. 理解 Booster Studio 与 SSH 的关系——「图形化界面」与「底层加密通道」是同一件事的两种呈现。<br>3\. 出现连接失败时按层定位（网络 / IP / 账号 / 设备 / 代码）的工程化排查思路。||

|**环节二  K1 软件系统的四层结构   【时长：7 分钟  ·  对应 PPT P6 – P9】**<br>**1\. 软件栈总览 \(约 2 分钟\)：**<br>翻到 PPT 第 6 页，展示四层栈图：从下到上是 Ubuntu / ROS2 / Booster SDK·API / 学生程序代码。每讲一层都用「这一层做什么、上下层之间什么关系」两个问题引导学生思考。<br>**2\. Ubuntu 介绍 \(约 1\.5 分钟\)：**<br>翻到 PPT 第 7 页，给出操作系统的定义：「介于硬件与应用程序之间的软件层」。用熟悉的设备类比——<br>**手机 = iOS / Android  ·  PC = Windows / macOS  ·  K1 = Ubuntu Linux**<br>强调一句：「学生通过 SSH 登录 K1 后，进入的就是这套 Ubuntu 系统的命令行。」<br>**3\. ROS2 占位介绍 \(约 1\.5 分钟\)：**<br>翻到 PPT 第 8 页，用「机器人内部的微信群」做类比——多个模块 \(相机/运动/语音/状态\) 通过 ROS2 这条公共信息总线互相发消息。<br>强调：「本课只需了解 ROS2 在软件栈中的位置；节点、话题、服务等机制留到第 5 课展开。」<br>**4\. SDK / API 与调用流程 \(约 2 分钟\)：**<br>翻到 PPT 第 9 页，先区分 SDK 与 API——<br>**SDK = 一整套接口集合 \(工具箱\)  ·  API = 一个具体可调用的功能**<br>举例：Booster SDK 包含运动 / 视觉 / 音频等子模块的接口；其中 RotateHead\(\) 就是一个具体 API。<br>然后展示一条 API 调用的完整流程：学生代码 → SDK·API → K1 控制服务 → 硬件驱动 → 物理动作。让学生记住：**「学生代码不是直接驱动电机，而是通过接口告诉控制系统该做什么。」**||**活动二**<br>1\. 跟随教师识别软件栈四层结构。<br>2\. 用类比的方式记住 Ubuntu = K1 的操作系统、ROS2 = 机器人内部的微信群。<br>3\. 区分 SDK 与 API 两个名词。<br>4\. 听讲并理解一条 API 调用的传递路径。<br><br>**学生产出**<br>·  在学习单上画出软件栈四层堆叠图：<br>**Ubuntu → ROS2 → SDK·API → 学生代码**<br>·  写出一句话：「学生代码通过 SDK·API 让 K1 产生反馈。」|
|**设计意图  **<br>软件栈是抽象概念，对零基础学生而言不易直接接受。本环节用「类比 \+ 占位」两个手段：类比把抽象概念落到学生熟悉的设备 \(手机/PC\)；占位则把暂时不展开的部分 \(ROS2 节点机制\) 明确告知「这里有，但等下节课再展开」，避免学生因听不懂而产生学习挫败感。<br>SDK / API 的区分是后续课程反复用到的概念。本课先建立「SDK = 工具箱、API = 一把工具」的直观印象，第 4 课进入具体 API 调用时学生就能顺接上来。<br>一条 API 调用的传递流程是「代码控制硬件」这一抽象关系的具象化。学生通过这张图能回答课末思考题「为什么我点击运行 K1 会动？」|||
|**环节三  建立连接  ·  SSH 与 Linux 命令   【时长：8 分钟  ·  对应 PPT P10 – P13】**<br>**1\. SSH 概念 \(约 2 分钟\)：**<br>翻到 PPT 第 10 页，给出 SSH 的定义：「Secure Shell，远程登录 Linux 设备的加密协议」。指出 SSH 三个核心特性——<br>① 加密传输 \(避免被网络窃听\)  ·  ② 身份验证 \(用户名 \+ 密码\)  ·  ③ 跨平台 \(Windows / Mac / Linux 都能用\)<br>展示命令格式：**ssh 用户名@机器人IP**<br>K1 实际命令示例：**ssh booster@192\.168\.10\.102 \(默认密码 123456\)**<br>强调：「IP 在第 2 课 App 配网后已经显示出来；用户名 booster、密码 123456 是 K1 的默认值。」<br>**2\. 有线 vs 无线连接 \(约 1\.5 分钟\)：**<br>翻到 PPT 第 11 页，对照展示两种连接方式——<br>有线：用网线直接接到 K1 网口，IP 默认 192\.168\.10\.102；适用于首次配置与故障排查。<br>无线：通过 Wi\-Fi 接入同一路由器，IP 由路由器分配；适用于日常课堂开发。<br>强调：「连接成功后 SSH 命令格式相同——只是 IP 地址不同。」<br>**3\. Linux 终端与三个基础命令 \(约 3\.5 分钟\)：**<br>翻到 PPT 第 12 页，先展示 SSH 登录后的终端窗口截图，让学生认识提示符 booster@k1:\~$ 的各部分含义——用户名 / 主机名 / 当前路径 / 提示符。<br>然后逐一介绍三个基础命令：<br>① **pwd**  Print Working Directory  ·  「我现在在哪个目录？」<br>② **ls**   List  ·  「这个目录里有什么？」<br>③ **cd**   Change Directory  ·  「去其他目录」<br>用「路径 = 大楼，目录 = 房间」的类比帮学生建立直观印象。<br>最后明确：**「Linux 还有几百个命令，本课不展开。请用大语言模型 \(ChatGPT / Claude / 豆包等\) 自学，并写进作业。」**<br>**4\. 连接成功的三步检查 \(约 1 分钟\)：**<br>翻到 PPT 第 13 页，给出三步验证流程——<br>① 网络是否通：**ping 192\.168\.10\.102 **（看到 reply 即通）<br>② SSH 是否能登录：**ssh booster@192\.168\.10\.102 **（出现 Password 即可）<br>③ 命令能否执行：**hostname **（返回 k1 即说明已在 K1 上运行）<br>强调：「三步全部成功，才能进入下一阶段使用 Booster Studio。」||**活动三**<br>1\. 听讲 SSH 的概念与命令格式，记下 booster / 123456 / 192\.168\.10\.102 三个必备信息。<br>2\. 在心里区分有线连接与无线连接的不同适用场景。<br>3\. 默念三个基础命令：pwd / ls / cd 及其含义。<br>4\. 跟教师过一遍连接成功的三步检查流程。<br><br>**学生产出**<br>·  在学习单上写出 SSH 命令模板：<br>**ssh 用户名@IP地址**<br>·  写出三个 Linux 命令的中文含义：<br>**pwd → 我在哪？  ls → 有什么？  cd → 去哪？**|
|**设计意图  **<br>SSH 是机器人开发中最重要的远程入口。本环节强调让学生记住命令格式和三个必备信息 \(用户名 / 密码 / IP\)，是为了让他们在课后自学或做作业时能独立尝试连接。<br>Linux 命令是开发能力的基础。本课只讲 pwd / ls / cd 三个最基础的命令是策略性选择——这三个能让学生「在终端里走起来」，足以建立对 Linux 的初步直觉。更多命令以「LLM 自学 \+ 作业反馈」方式吸收，既给了学生主动求知的入口，也降低了课堂时间压力。<br>连接成功的三步检查是工程实践中标准的诊断思路。课堂上养成这种习惯，比硬记命令本身更重要——这是后续所有课程做实机调试时都会反复用到的方法。|||
|**环节四  Booster Studio 实践   【时长：15 分钟  ·  对应 PPT P14 – P21】**<br>**1\. Studio 与 SSH 的关系 \(约 1 分钟\)：**<br>翻到 PPT 第 14 页，明确告诉学生：**「Booster Studio 把 SSH 连接 \+ 终端 \+ Notebook \+ 状态监控全部打包到一个图形界面。背后还是 SSH 那套通信，只是不用手动敲命令。」**<br>Studio 集成的四件能力：连接管理 / 状态监控 / Notebook / 终端入口。<br>**2\. 安装 \+ 登录 \+ 选择 K1 \(约 2 分钟\)：**<br>翻到 PPT 第 15 – 17 页，依次说明：下载安装包 → 运行向导 → 启动软件 → 输入账号密码登录 → 在设备列表中找到本组的 K1 → 点击连接。<br>强调：「教室里多组同时使用时，务必核对设备名称或编号，避免连接到其他组的 K1。」<br>**3\. 连接成功页面识别 \(约 1 分钟\)：**<br>翻到 PPT 第 18 页，让学生记住三个识别要点：状态指示「已连接 / 在线」、机器人信息显示 \(名称 / IP / 电量\)、功能区入口由灰色变为可点击。<br>要求每组：「连接成功后立刻截图保存当前界面，作为提交物之一。」<br>**4\. 打开 Notebook \(约 1 分钟\)：**<br>翻到 PPT 第 19 页，引导学生在主界面找到 Notebook 入口，新建一个 Notebook，识别三大区域：代码输入区 \(Cell\)、运行按钮、结果输出区。<br>简要说明：「Notebook 与 Python 编程入门课用过的 Jupyter 风格一致——一段 Cell 是一段独立可运行的代码。」<br>**5\. 真机演示 \+ 学生上手 \(约 10 分钟\)：**<br>翻到 PPT 第 20 页，展示完整的点头代码 \(33 行\)。教师在自己的 Studio 中先完整演示一次完整流程：<br>Step A: 把代码全选复制 → 粘贴到 Notebook 代码区。<br>Step B: 讲解代码结构 \(不深入\)：导入 SDK → 初始化 → 进入行走模式 → 头部连续 3 次低头/抬头 → 复位。<br>Step C: 点击运行 \(或按 Shift \+ Enter\)。<br>Step D: 观察 K1 反馈——头部上下点头 3 次 \+ 视觉画面同步变化。<br>翻到 PPT 第 21 页，让学生分组实操，按照同样四步执行。教师巡视 4 个组，重点观察：<br>· 是否在运行前确认机器人周围 1\.5 m 内空旷？<br>· 机器人是否正确进入行走模式？<br>· Notebook 的输出区是否有 Error 信息？<br>任何错误都引导学生用 PPT 第 22 页的故障排查表自行定位。||**活动四**<br>1\. 听讲并明确 Studio 与 SSH 的关系 \(Studio 是 SSH 的图形化封装\)。<br>2\. 跟随教师演示完成登录、选择 K1、识别连接成功页面、打开 Notebook 四步操作。<br>3\. 三人一组分工：操作员 \(拿键盘鼠标\)、观察员 \(盯着 K1 状态\)、记录员 \(拍视频或截图\)。<br>4\. 完整执行：粘贴代码 → 点击运行 → 观察 K1 点头反馈。<br>5\. 出现错误时用故障排查表自行定位并解决。<br><br>**学生产出**<br>·  连接成功界面截图。<br>·  Notebook 运行结果截图 \(含输出区\)。<br>·  K1 点头视频 \(3 秒以上\)。<br><br>**验收标准 \(每组\)**<br>①  连接到本组 K1 \(不是其他组\)；<br>②  Notebook 输出区无 Error；<br>③  K1 头部完成连续 3 次低头 / 抬头；<br>④  视觉画面随头部同步变化。|
|**设计意图  **<br>本环节是本课的实操高潮，占用近三分之一的课时是合理的——学生第一次让 K1 通过代码做出动作，是建立对编程与机器人控制兴趣最重要的一刻。<br>把 Studio 与 SSH 的关系明确告知学生，是为了避免学生认为「学了 SSH 又学 Studio 是不是浪费」——让他们看到 Studio 就是 SSH 的图形化封装，认知是连贯的。<br>教师先完整演示再让学生上手，是为了让学生先建立「正确的肌肉记忆」——避免凭印象操作而踩坑。三人小组分工避免「一人独占」，让每位学生都能从不同视角参与。<br>验收标准用具体客观目标 \(无 Error / 3 次点头 / 视觉同步\) 替代主观判断，让验收过程客观可量化。|||
|**环节五  故障排查  ·  小组提交   【时长：4 分钟  ·  对应 PPT P22】**<br>**1\. 故障排查表讲解 \(约 2 分钟\)：**<br>翻到 PPT 第 22 页，过一遍 6 类常见问题及定位方法——<br>· 网络不通  →  检查同一 Wi\-Fi 网段<br>· IP 错误  →  核对教师提供的 IP<br>· 登录失败  →  检查账号 / 密码 / 网络<br>· 找不到本组 K1  →  确认 K1 已开机 / 已联网<br>· 代码运行无反馈  →  确认连接的是本组 / 在正确 Notebook / 已点击运行<br>· 代码报错  →  查看 Traceback \(通常是模式未切换或参数错误\)<br>强调通用原则：**「按层定位、由近及远——先确认网络通，再 SSH，再 Studio，最后看代码。」**<br>**2\. 小组提交收尾 \(约 2 分钟\)：**<br>各组把连接成功截图、Notebook 运行截图、K1 点头视频整理后发给教师 \(微信群、Teams 或 U 盘均可，按教师课前约定方式\)。<br>教师快速点评本节课实操情况：哪几组顺利、哪几组卡在哪一层、原因是什么。||**活动五**<br>1\. 跟随教师过一遍故障排查表 6 类问题。<br>2\. 整理本组的三类提交物。<br>3\. 听教师点评，了解其他组遇到的问题。<br><br>**学生产出**<br>·  按教师约定方式提交本组的连接截图 \+ Notebook 截图 \+ K1 视频。<br>·  在学习单上记录本组遇到的至少 1 个问题与解决方法。|
|**设计意图  **<br>故障排查表的目的不是让学生背下来，而是让学生在第一次遇到机器人系统出错时有一个「可以查的清单」——这是工程意识的起点。<br>「按层定位」是后续所有课程做实机调试的核心方法。本课通过一次小型故障排查，把这种思维种到学生意识里。<br>公开点评其他组的问题与解决方法，能让一个组的失败成为全班的财富。|||
|**环节六  课程总结  ·  链路回顾  ·  下节预告   【时长：3 分钟  ·  对应 PPT P23 – P24】**<br>**1\. 完整链路回顾 \(约 1 分钟\)：**<br>翻到 PPT 第 23 页，展示上半区的完整链路图 \(Windows → Studio → Notebook → SSH → Ubuntu → ROS2/SDK → K1 反馈\)。指着每个节点回顾刚才完成的过程：**「这就是你刚才完成的从代码到 K1 反馈的整条路径——每一步都对应今天讲过的一个概念。」**<br>**2\. 总结六条 \+ 思考题四道 \(约 1 分钟\)：**<br>展示下半区的总结 \(六条核心结论\) 与思考题 \(四道\)。重点抛出第一道思考题：**「为什么在自己电脑上点击运行，K1 会做出动作？」**<br>告知学生这是课后作业的核心问题，下节课课前提问。<br>**3\. 下节预告 \+ 课后作业 \(约 1 分钟\)：**<br>翻到 PPT 第 24 页，预告第 4 课《机器人说话功能与 API 调用》：<br>· 调用机器人「说话」\(TTS\)<br>· 调用基础动作 API \(挥手 / 鞠躬 / 起身\)<br>· 组合「说一句 → 等一下 → 做一个动作」的节奏<br>布置 4 道课后作业 \(PPT 第 24 页右栏\)：<br>**① 手绘开发链路图  ·  ② 一句话解释 5 个名词  ·  ③ 整理本组截图与记录  ·  ④ 用 LLM 自学 5 个 Linux 命令**||**活动六**<br>1\. 跟随教师对照链路图回顾刚才完成的整条路径。<br>2\. 听讲六条总结与四道思考题。<br>3\. 记录四道课后作业的具体要求。<br><br>**学生产出**<br>·  在笔记或学习单上抄录四道课后作业。|
|**设计意图  **<br>链路图作为「代码运行后的总结」是本课最重要的复习时刻——前面 35 分钟所有的知识点 \(软件栈、SSH、Studio、Notebook、SDK·API\) 都能在这张图里找到对应位置。这种「学完之后再回看一次完整路径」的设计能极大强化整体认知。<br>第一道思考题「为什么点击运行 K1 会动？」是本课认知是否到位的考核。学生若能用「软件栈 \+ 网络 \+ SDK」完整回答，说明本课目标达成。<br>课后作业第 4 题「LLM 自学 Linux 命令」是本课与下节课之间的连接桥——既补足了课堂没展开的 Linux 知识，也培养了学生主动求知的习惯。|||
