|**教学目标**|||
|**知识与技能**|1\. 理解「感知 → 决策 → 动作」闭环结构 —— 把第 11 课的 JSON 输出转换成 K1 头部动作。<br>2\. 会解析 /vision\_detection/ball 的 JSON 字符串，读取本课需要的 5 个字段（x / y / conf / detected / stale）。<br>3\. 理解图像坐标系：左上角为 \(0, 0\)、x 向右、y 向下；这与数学课本的笛卡尔坐标不同。<br>4\. 掌握偏差计算 dx\_norm = \(x − CX\) / CX 与 dy\_norm = \(y − CY\) / CY，理解归一化的工程价值（与分辨率无关）。<br>5\. 理解头部坐标系的方向定义：yaw 向左为正、pitch 向下为正；理解 yaw\_delta = − yaw\_gain × dx\_norm 中负号的几何含义。<br>6\. 会调用 client\.RotateHead\(pitch, yaw\) 控制头部，理解 clamp 限幅（yaw ±0\.785 rad / pitch −0\.30 \~ 1\.00）的安全意义。<br>7\. 理解死区（deadband\_x/y = 0\.06）和低通滤波（smooth\_alpha = 0\.35）对控制稳定性的作用。<br>8\. 理解 on\_timer 定时器机制：lost\_timeout\_sec = 1\.0 秒后丢球，头部回到 base\_pitch 默认位置。<br>9\. 能完成 4 个实践：确认 JSON 输出 → 启动头部跟随 → 调死区 3 档 → 调 smooth\_alpha 3 档；理解灵敏度 vs 稳定性的工程权衡。<br>10\. 明确本课边界：只做像素偏差 → 头部角度（不做三维坐标变换 / 不做主动找球扫描 / 不走 / 不踢）。||
|**过程与方法**|1\. 通过「Lesson 11 看见球 → Lesson 12 看向球」的承接，让学生直观看到本课作为「第一个动作闭环」的位置。<br>2\. 通过图像坐标系大图 \+ 4 象限示意 \+ 五个球位置示意，让学生在图像层「看到」偏差的几何含义。<br>3\. 通过「图像坐标 vs 头部 yaw vs 头部 pitch」三栏对比图（俯视 \+ 侧视）建立方向定义的视觉记忆。<br>4\. 通过「球在左 → dx \< 0 → 头应左转 → yaw 应增大」四段因果链，让学生「自己推导」出负号。<br>5\. 通过曲线对比（抖动 vs 平滑）、扇形图（yaw 限幅）、时间轴（on\_timer 丢球回正）三类示意，把抽象数字变成可视化概念。<br>6\. 通过 4 个实践（确认输入 → 跑跟随 → 调死区 → 调 alpha），让学生自己感受参数对动作的影响，而不是讲解。<br>7\. 通过排查表的 6 行典型故障（含「头部反方向转」「长时间丢球未回正」），建立闭环排查方法。||
|**情感态度与价值观**|1\. 完成「机器人看见我 → 跟着我转头」的第一次真正具身智能体验，建立成就感。<br>2\. 通过「负号源自坐标系方向差」的推导，体会工程中「细节决定成败」 —— 数学和工程的微小差异会带来完全相反的行为。<br>3\. 通过「死区 \+ 平滑 \+ 限幅」三层稳定性设计，理解工程师不只考虑「能动」，还要考虑「稳、安全、可控」。<br>4\. 通过本课的「单一职责」边界（只做跟随），体会模块化设计哲学 —— 不贪多，做扎实。||
|**教学重点**|1\. 像素偏差公式 dx\_norm / dy\_norm 与归一化的工程价值。<br>2\. 图像坐标 vs 头部 yaw/pitch 的方向定义对比（必须用图示讲）。<br>3\. yaw 负号的几何来源（球在左 → dx\<0 → yaw 应增大 → 需要负号翻转）。<br>4\. on\_ball 7 步流水线 \+ on\_timer 丢球回正机制。<br>5\. 死区 / 平滑 / 限幅 三个稳定性设计 \+ 默认参数值。<br>6\. 本课和 Lesson 13（主动找球）/ Lesson 14（坐标变换）的明确边界。||
|**教学难点**|1\. 图像 y 向下、头部 pitch 向下为正 —— 巧合一致，学生不会注意；但 yaw 「向左为正」与图像 x 「向右增大」的方向不一致是本课最容易讲错的点。<br>2\. 「负号」对学生来说是抽象概念，必须通过 PPT P11 的四段因果链图（场景 → 图像 → 头部 → yaw）让学生「自己推出来」。<br>3\. 死区 vs 平滑两个稳定性设计学生容易混淆 —— 死区是「小偏差直接清零」，平滑是「滤波后的偏差」；要用 PPT P12 的两栏图（死区数轴 \+ 平滑曲线对比）区分。<br>4\. on\_timer 定时器和 on\_ball 回调是「并行运行」的两条线 —— 学生本能以为只有 on\_ball 一条流程。要用 PPT P13 \+ P18 的两个图强调并行性。<br>5\. 「检测到球但头部反方向转」的现象，学生本能怀疑是检测错了。要让学生明白这是 yaw 符号问题，对照 P11 的图自查。||

  本课闭环:
    /vision\_detection/ball  →  head\_follow\_ball\_node
    →  RotateHead\(pitch, yaw\)  →  K1 头部

  ┌──────────────────────────────────────────────┐
  │  方向定义  \(本课最容易讲错\)                            │
  │                                                      │
  │  图像坐标:   x → 右       y → 下                     │
  │  头部 yaw:   向左为正  \(左转 yaw 增大\)                │
  │  头部 pitch: 向下为正  \(低头 pitch 增大\)               │
  └──────────────────────────────────────────────┘

  核心公式:
    CX = image\_w / 2 ,   CY = image\_h / 2
    dx\_norm = \(x \- CX\) / CX
    dy\_norm = \(y \- CY\) / CY
    yaw\_delta   = \- yaw\_gain   \* smooth\_dx  ★
    pitch\_delta = \+ pitch\_gain \* smooth\_dy

  ★ 为什么 yaw 有负号:
    球在左 → dx\<0   →  头应左转  →  yaw 应增大
    需要负号翻转: \-dx \> 0

  5 个函数:
    init\_sdk\(\)        SDK 初始化
    parse\_payload\(\)   JSON → 字典
    on\_ball\(\)         事件驱动 \(来一帧球就跑一次\)
    rotate\_head\(\)     限幅 \+ 节流 \+ 下发命令
    on\_timer\(\)        定时器 \(100ms,  丢球回正\)

  关键参数:
    min\_conf = 0\.50              ·  conf 过滤
    base\_pitch = 0\.60            ·  默认低头看球
    yaw\_gain = 0\.18, pitch\_gain = 0\.14
    deadband = 0\.06              ·  死区
    smooth\_alpha = 0\.35          ·  低通滤波
    command\_interval = 0\.08      ·  命令节流
    lost\_timeout\_sec = 1\.0       ·  丢球判定
    yaw ∈ ± 0\.785 \(±45°\)         ·  限幅
    pitch ∈ \-0\.30 \~ \+1\.00        ·  限幅

  4 个实践:
    1\. 确认 /vision\_detection/ball
    2\. 启动头部跟随 \(两终端\)
    3\. 调 deadband \(0\.03/0\.06/0\.10\)
    4\. 调 smooth\_alpha \(0\.20/0\.35/0\.50\)
