|**教学目标**|||
|**知识与技能**|1\. 理解 ROS2 功能包 Package 的定义、构成与作用，能区分 Workspace / Package / Node / Launch 四级概念。<br>2\. 读得懂 Python 类型功能包的标准目录结构：内层 Python 模块目录 / launch 目录 / models 目录 / setup\.py / package\.xml 各自的作用。<br>3\. 会写 setup\.py 的 console\_scripts —— 把 Python 文件声明为 ROS2 可执行节点；理解「可执行名 / 模块名 / 文件名 / main 入口」四字段对应关系。<br>4\. 会写 setup\.py 的 data\_files —— 把 launch 文件与 models 资源声明为安装目标，理解 get\_package\_share\_directory\(\) 找文件的逻辑。<br>5\. 理解 colcon build / source install/setup\.bash / ros2 run / ros2 launch 四条命令的工作流，理解为什么改了 setup\.py / launch / 模型后都要重新 build。<br>6\. 会写两节点 launch 文件：理解 LaunchDescription / Node / generate\_launch\_description\(\) 的角色，会配置 package / executable / name / output 四个 Node 参数。<br>7\. 一条 ros2 launch 命令拉起「人脸检测 \+ 挥手」闭环系统，会用 ros2 topic / ros2 service / ros2 node list 做运行前后体检。<br>8\. 理解日志机制（get\_logger\(\)\.info/warn/error）在多节点系统中的作用，掌握节流打印模式（如 frame\_count % 15 == 0）。<br>9\. 知道 Ctrl \+ C 是系统的正常收尾方式，理解工程化系统不只要会启动、也要会安全结束。<br>10\. 能对照「错误现象 → 原因 → 排查命令」表自主定位四类典型故障（包/executable/launch/不挥手）。||
|**过程与方法**|1\. 通过「回到第 8 课 —— 能跑但 3 个终端、顺序敏感」的反思导入，建立「能跑 ≠ 工程化」的认知张力。<br>2\. 通过散文件运行的「启动复杂 / 顺序敏感 / 不利维护」三大问题分析，让学生体会到工程化的必要性。<br>3\. 通过「五个可」目标（可组织 / 可构建 / 可启动 / 可观察 / 可复用）建立工程化的具体内涵，避免空谈。<br>4\. 通过功能包目录树 → setup\.py → launch 文件 → 命令工作流的层层剥洋葱式讲解，让学生看见 ROS2 系统的完整工程骨架。<br>5\. 通过三个填空式练习（补全 console\_scripts / 补全 launch executable / 结构判断），让学生主动复现关键写法。<br>6\. 通过「错误现象 → 原因 → 排查命令」速查表的对照演练，建立故障定位的工程方法，而非靠运气试错。<br>7\. 通过 A/B/C 三选一挑战任务（从零创建包 / 加 TTS 第三节点 / 故障演练修复），允许学生按兴趣与能力分层延伸。||
|**情感态度与价值观**|1\. 体会「单一入口」的工程价值——一条 ros2 launch 替代三个终端的纠结，建立对优雅设计的审美。<br>2\. 通过日志机制建立「系统状态要可观察」的工程价值观，理解可观测性是真实机器人项目的基本素养。<br>3\. 通过收尾环节（Ctrl \+ C 的意义）建立「负责任的程序员」意识——不仅要会启动，也要会安全结束。<br>4\. 通过「整包拷过去就能跑」的可复用目标，建立模块化、可移植的工程审美，为后续走向大型机器人系统打底。||
|**教学重点**|1\. setup\.py 的 console\_scripts 与 data\_files —— 这是功能包能否被 ros2 run / ros2 launch 找到的关键。<br>2\. launch 文件的核心结构 —— LaunchDescription / Node / generate\_launch\_description\(\) \+ 四个 Node 参数（package / executable / name / output）。<br>3\. colcon build → source install/setup\.bash → ros2 run / ros2 launch 的标准工作流；理解为什么每次改完都要重新 build \+ source。<br>4\. 日志机制的三个级别（info / warn / error） \+ 节流打印模式，建立多节点系统的可观察性。<br>5\. 四类典型错误的现象\-原因\-命令对照表，让学生有能力自主定位 90% 的常见问题。||
|**教学难点**|1\. 「setup\.py 的 console\_scripts 名字 = launch 的 executable 名字 = ros2 run 时敲的名字」三处必须完全一致 —— 学生经常对不上号。<br>2\. 「外层 package 同名 vs 内层 Python 模块同名」的目录套娃结构 —— 学生第一次接触会觉得「为什么要两层重名」。<br>3\. 「每次改 setup\.py / launch / models 都必须 colcon build」—— 学生容易忘记，导致改了不生效。<br>4\. 「每个新终端都要 source」—— 学生开新终端忘了 source，会得到 Package not found 错误，但不知道为什么。<br>5\. 「为什么不用绝对路径直接写模型路径？」—— 需要从「工程化、可移植、跨机器」角度反复强调 get\_package\_share\_directory\(\) 的价值。<br>6\. 「launch 起来了但机器人不挥手」属于多节点协作问题 —— 不是 launch 错，是底层服务/相机话题没准备好；学生容易把这种现象归因为 launch 错误。||

|**设计意图  **<br>用「回到第 8 课」的真实痛点切入，避免空谈工程化。学生有第 8 课的亲身体验，「三个终端顺序不能错」是切肤之痛，很容易接受「需要更好的组织方式」这一动机。<br>「五个可」不是修辞，是后续每一页都对应一个「可」（可组织对应目录结构、可构建对应 colcon、可启动对应 launch、可观察对应日志、可复用对应 get\_package\_share\_directory）。这一页是后续 17 页的总纲。|||
|**环节二  读懂功能包模板  ·  目录 / setup\.py / launch   【时长：10 分钟  ·  对应 PPT P7 – P11】**<br>**1\. Python 功能包目录结构（约 2 分钟）：**<br>翻到 PPT 第 7 页。逐行带读左侧目录树，对照右侧「各层含义」表。重点强调：<br>· 外层 python\_demo\_pkg/ 是「功能包根目录」，**    内层同名 python\_demo\_pkg/ 才是 Python 模块代码目录 —— 节点 \.py 放这里。**<br>· launch/ 放 launch 文件，models/ 放模型资源，package\.xml 是依赖清单，setup\.py 是节点入口声明。<br>**2\. setup\.py 之 console\_scripts（约 3 分钟）：**<br>翻到 PPT 第 8 页。先读左侧完整 setup\.py 模板，定位 entry\_points → console\_scripts。然后右侧拆解一行：<br>**'face\_detector\_publish = python\_demo\_pkg\.face\_detector\_publish:main'**<br>按 ①②③④ 讲清楚：①ros2 run 时的可执行名 / ②Python 模块包名 / ③节点文件名（不带 \.py）/ ④入口函数 main。<br>强调：**「①、③、④ 三个名字必须和后面 launch 文件、setup\.py 互相对得上 —— 这是本课最常见的错误源。」**<br>**3\. 模型文件入包 \+ get\_package\_share\_directory（约 2 分钟）：**<br>翻到 PPT 第 9 页。左上对比绝对路径的问题：「写死 /usr/share/opencv4/\.\.\. 在课堂机能跑，换到机器人 NX 路径就不在了。」<br>左下展示工程化做法：**get\_package\_share\_directory\('python\_demo\_pkg'\)**，让程序自己去问 ROS2「这个包装在哪儿」。<br>右侧明确「为什么要这么做」—— 跨机器可移植 / 整包拷过去就能跑 / 不依赖绝对路径。<br>**4\. setup\.py 之 data\_files（约 1\.5 分钟）：**<br>翻到 PPT 第 10 页。左侧完整 setup\.py 中 data\_files 列表。带读两行关键：<br>\(os\.path\.join\('share', package\_name, 'launch'\), glob\('launch/\*\.py'\)\),<br>\(os\.path\.join\('share', package\_name, 'models'\), glob\('models/\*\.xml'\)\),<br>解释：colcon build 会把这些文件从源码目录复制到 install/\.\.\./share/\.\.\. 目录，**get\_package\_share\_directory\(\) 就是去这个目录找文件。**<br>**5\. launch 文件核心结构（约 1\.5 分钟）：**<br>翻到 PPT 第 11 页。左侧 launch 文件模板，重点指出三个固定结构：<br>· **import：LaunchDescription \+ Node**<br>· **固定入口函数 generate\_launch\_description\(\)**<br>· **Node\(\.\.\.\) 的四个参数：package / executable / name / output**<br>特别强调：**「executable='face\_detector\_publish' 必须和 setup\.py 的 console\_scripts 左边名字完全一致 —— 不一致就是错误 \#2。」**||· 学生在自己的 python\_demo\_pkg/ 目录中对照 PPT 找 7 个关键路径，圈出来确认每个文件的角色。<br>· 学生抄写 console\_scripts 一行的四字段对应关系。<br>· 学生在 Notebook 中查看 setup\.py 当前的 data\_files，对照 PPT 说出每一行是装哪类资源。<br>· 学生跟着 PPT 自读 launch 文件模板，画出「Node 的 4 个参数」结构图。|
|**设计意图  **<br>这一段是本课的「内核」—— 学生第一次接触 ROS2 工程化的标准模板。一定要让学生「看见」目录结构、「读懂」setup\.py、「认识」launch 文件，而不是死记。<br>特别强调「三处名字要一致」（console\_scripts 名 / launch executable / ros2 run 时的名字）—— 这是后续 90% 错误的根因。讲到这里就埋下伏笔，到环节五排查表时再回收。<br>get\_package\_share\_directory\(\) 是工程化最优雅的设计之一 —— 让程序自己去问 ROS2 「我这个包装在哪儿」，从此不依赖绝对路径。要让学生体会到这种「问 ROS2」的思维转变。|||
|**环节三  构建与运行  ·  colcon build / source / ros2 run / ros2 launch   【时长：7 分钟  ·  对应 PPT P12 – P14】**<br>**1\. colcon build —— 把功能包「编译」成可运行的样子（约 3 分钟）：**<br>翻到 PPT 第 12 页。左侧讲命令：**cd \~/Workspace \&\& colcon build \-\-packages\-select python\_demo\_pkg**<br>然后讲构建后三文件夹 —— build/ 中间文件 · install/ 安装结果 · log/ 日志。<br>重要强调：**「ROS2 真正运行的不是源码，是 install/ 目录里构建好的副本。」**<br>右侧列出「什么时候必须重新 build」四种情况：改 setup\.py / 改 launch / 加 models / 改 package\.xml。    强调底部红字：「只改节点 \.py 文件原则上也要重新 build。」<br>教师当场演示一次：故意改 setup\.py 不 build，运行 ros2 run 看效果（仍是旧的）。<br>**2\. source —— 让当前终端「认识」新功能包（约 2 分钟）：**<br>翻到 PPT 第 13 页。左侧讲命令：**source install/setup\.bash**<br>示范不 source 直接 ros2 run，看到 Package 'python\_demo\_pkg' not found 报错。<br>**解释 source 的本质 ——「把 install/ 目录下的功能包路径，写进当前 shell 的环境变量。」**<br>右侧三条容易忘的提醒：①每个新终端都要重新 source / ②source 之前一定要 build / ③可以写进 \~/\.bashrc。<br>**3\. ros2 run vs ros2 launch（约 2 分钟）：**<br>翻到 PPT 第 14 页。左右对照讲：<br>· **ros2 run**：单节点测试用，缺点是要开多个终端、顺序要人手控制。<br>· **ros2 launch**：一组节点用，Ctrl \+ C 一次性关掉，方便扩展。<br>**明确本课目标 ——「学生只需要敲一条 ros2 launch，整个闭环系统就跑起来。」**||· 学生在 SSH 终端跟做：cd \~/Workspace → colcon build → 观察输出三行 Summary。<br>· 学生查看 install/ 目录结构，确认看见 python\_demo\_pkg/share/python\_demo\_pkg/\{launch,models\}/ 真的有副本。<br>· 学生故意开一个新终端、不 source，敲 ros2 run，亲眼看到 Package not found 报错，再补 source 解决。<br>· 学生分别敲一次 ros2 run（开两个终端）和一次 ros2 launch（一条命令），亲身体会差别。|
|**设计意图  **<br>这一段是命令行手感训练。让学生「敲过、出错过、修好过」，比反复讲解概念有效十倍。<br>「故意不 build 看效果」「故意不 source 看报错」是关键设计 —— 把后续会犯的错前置展示，等真出错时学生有镜像可对照。<br>ros2 run vs ros2 launch 的对比，是从「单节点思维」走向「系统思维」的关键认知翻转。|||
|**环节四  一键启动闭环 \+ 日志机制   【时长：10 分钟  ·  对应 PPT P15 – P17】**<br>**1\. 一键启动 \+ 预期效果（约 2 分钟）：**<br>翻到 PPT 第 15 页。顶部大命令框：**ros2 launch python\_demo\_pkg two\_nodes\_launch\.py**<br>按 ①②③④ 四张卡片讲预期效果 —— 节点全部启动 / 检测节点订阅图像 / 话题正常发布 / 机器人挥手。<br>底部紫色框：「系统从此有了单一入口。」<br>教师在主控终端一气呵成演示：cd → colcon build → source → ros2 launch，然后让一名学生站到 K1 前 —— K1 看见 → 挥手。<br>**2\. 运行前 / 后的四条体检命令（约 2 分钟）：**<br>翻到 PPT 第 16 页。运行前两条：<br>· **ros2 topic list \| grep boostercamera   →  确认相机话题在**<br>· **ros2 service list \| grep booster\_rpc\_service   →  确认动作服务在**<br>运行后两条：<br>· **ros2 node list   →  自己节点起来了吗**<br>· **ros2 topic echo /vision/face\_detected   →  检测话题有数据吗**<br>强调：**「一键启动很爽，但相机/服务没准备好的话，哪里都不会有错误弹窗 —— 必须靠这 4 条体检。」**<br>**3\. 日志机制 —— 让多节点系统「可观察」（约 4 分钟）：**<br>翻到 PPT 第 17 页。先讲为什么需要日志：「单文件系统靠看效果就知道有没有跑通；多节点系统看不见内部，必须靠日志。」<br>然后讲三个常用日志级别 —— <br>· **info **正常运行：节点启动 / 检测到人脸 / 触发挥手<br>· **warn **可能有问题：暂时没收到图像 / 服务还没准备好<br>· **error **明确错误：Haar 模型加载失败 / 服务调用失败<br>右上展示写法：**self\.get\_logger\(\)\.info\('人脸检测节点已启动'\)**。<br>左下重点强调节流打印：**「30 fps 时全打印会刷屏看不见关键信息 —— 用 frame\_count % 15 == 0 节流。」**<br>**4\. 体验日志：让学生看见系统状态（约 2 分钟）：**<br>教师把 launch 终端的 \[face\_detector\_node\]、\[face\_wave\_node\] 日志逐条解读 ——「节点启动」「订阅成功」「检测到人脸」「调用 service」「挥手完成」。<br>**引导学生注意：「现在系统不是黑箱了 —— 每一步发生了什么，终端都告诉你了。」**||· 学生跟随教师演示，把 ros2 launch 整个流程在自己终端走一遍。<br>· 学生执行 4 条体检命令，把每条命令的输出截图贴到学习单上。<br>· 学生在 launch 终端观察日志输出，标注哪些是 info / warn，思考如果没有日志会有多难调试。<br>· 学生尝试关掉相机节点，再启动 launch，观察 warn 日志怎么提示「暂时没收到图像」。|
|**设计意图  **<br>「一键启动」是本课的高潮 —— 学生第一次体会到「一条命令拉起整个系统」的工程优雅。这一步要让学生有「哇」的感觉。<br>4 条体检命令是为了让学生养成「先检查 → 再启动 → 再验收」的工程习惯，而不是盲目敲命令然后猜「为啥不动」。<br>日志机制是工程化转折课的核心内容之一 —— 从「靠看效果」走向「靠看日志」，这是从单文件思维进入多节点系统思维的必经一步。|||
