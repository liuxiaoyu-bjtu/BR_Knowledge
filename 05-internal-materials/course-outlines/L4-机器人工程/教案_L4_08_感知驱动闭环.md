|**教学目标**|||
|**知识与技能**|1\. 区分人脸检测（Face Detection）与人脸识别（Face Recognition）—— 本课只回答「有没有人」、不回答「这是谁」。<br>2\. 理解人脸检测的两类实现思路：传统视觉特征（Haar / HOG\+SVM）与深度学习（MediaPipe / YOLO\-face / SCRFD），知道各自代表算法与适用场景。<br>3\. 掌握 Haar 级联分类器的三个核心思想：明暗特征（一组矩形「亮\-暗」算子）\+ 多尺度扫描（图像金字塔）\+ 级联筛选（层层快关）。<br>4\. 知道 haarcascade\_frontalface\_default\.xml 模型文件路径策略：优先系统路径 /usr/share/opencv4/haarcascades，找不到则 fallback 到 cv2\.data\.haarcascades。<br>5\. 理解本课的多节点协作闭环：相机节点 → 检测节点（发布 Bool）→ 动作触发节点（订阅 Bool \+ 调用 service）→ K1 挥手。Topic \+ Service 两种通信机制混合使用。<br>6\. 掌握 ROS2 service 调用挥手的 API：api\_id = 2005，body = '\{"hand\_index": 0, "hand\_action": 0\}'。理解 hand\_index/hand\_action 含义。<br>7\. 理解两层稳定性设计：检测端 STABLE\_THRESHOLD（连续 N 帧才发 True）\+ 动作端 COOLDOWN（N 秒内不重复触发）。<br>8\. 能完成 4 个实践：运行检测发布节点 → 命令行验证 Bool 话题 → 修改 STABLE\_THRESHOLD 对比响应速度 → 运行挥手触发节点完成完整闭环。||
|**过程与方法**|1\. 通过「从获取图像到理解图像」的承接，把 Lesson 07 的图像订阅与本课的图像理解串成连贯主线。<br>2\. 通过「检测 ≠ 识别」的对照建立精确概念边界，避免学生错以为本课在做人脸识别。<br>3\. 通过「先提问 → 分析两类方法 → 列举各自算法 → 选 Haar」的认知推进，让学生体会工程选型的思维过程。<br>4\. 通过多节点闭环图建立「分工 \+ 协作」的工程系统观——一个挥手动作背后是 5 个 ROS2 组件在协作。<br>5\. 通过 4 个递进实践（运行 → 观察 → 调参 → 闭环），让学生从「能跑」走到「会调」再到「能闭环」。<br>6\. 通过 STABLE\_THRESHOLD 1/3/5 三种对比，让学生亲身体验「响应速度 vs 稳定性」的工程权衡。||
|**情感态度与价值观**|1\. 在第一次完整体验「机器人看见我 → 主动挥手」时建立强烈的具身智能直觉。<br>2\. 体会工程系统的「闭环之美」—— 多个节点各司其职、通过标准接口协作，比一个大文件干所有事更稳健、更可维护。<br>3\. 通过稳定性设计的引入，理解「真实机器人行为不能被单帧抖动驱动」的工程谦逊。<br>4\. 通过进阶任务（视觉化窗口、语音播报、深度学习替换）的预告，建立「经典算法 → AI 模型」的进阶视野。||
|**教学重点**|1\. Haar 级联分类器的三个核心思想（明暗特征 \+ 多尺度 \+ 级联），以及本课为何选 Haar 而非深度学习。<br>2\. 多节点闭环结构：检测节点（发布 Bool 话题）\+ 动作触发节点（订阅 \+ 调用 service）的协作。<br>3\. api\_id = 2005 挥手服务的调用方式 \+ hand\_index / hand\_action 参数含义。<br>4\. 两层稳定性设计：STABLE\_THRESHOLD 在检测端 \+ COOLDOWN 在动作端。||
|**教学难点**|1\. 区分「检测」与「识别」——很多学生本能把两者混为一谈。<br>2\. 多节点为什么不写成一个大程序？需要从「可复用、可维护、可替换」工程角度反复强调。<br>3\. face\_count 状态机的「连续 N 帧才发 True，一帧 False 立即归零」逻辑——容易让学生误以为是「累计 N 次」。<br>4\. 挥手前的模式前提——假设 K1 已在 Walking 模式；如果学生发现机器人不动，要回到 Lesson 06 流程切模式。<br>5\. Haar 对正脸效果好但对侧脸/光线敏感的工程现实——学生可能因为脸朝侧或光线暗而误判系统坏了。||
