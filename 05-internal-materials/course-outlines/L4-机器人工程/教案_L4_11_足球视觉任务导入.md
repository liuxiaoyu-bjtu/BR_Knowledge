|**知识与技能**|1\. 理解足球检测在 VisualKick 视觉踢球任务中的位置 —— 它是「相机图像 → 检测 → 坐标变换 → 走向 → 踢球」完整闭环的第一颗螺丝。<br>2\. 区分颜色 \+ 形状传统视觉方法和 YOLO 目标检测方法，能从「教学直观性 / 实现复杂度 / 光照鲁棒性 / 可检测类别 / 输出信息 / 后续坐标转换 / 与最终功能包一致性」7 个维度做出权衡。<br>3\. 理解为什么足球任务主线选 YOLO —— 最重要的两点是「输出 bbox 更适合后续坐标变换」和「与最终 k1\_visualkick\_demo 包一致」。<br>4\. 理解目标检测的三个基本问题：有没有目标 / 目标是什么 / 目标在哪里；理解类别 class / 置信度 conf / 边界框 bbox 三个核心输出。<br>5\. 理解 ball\_detection\_node 的 5 步流水线：订阅图像 → ROS Image 转 OpenCV BGR → YOLO 推理 → 类别\+conf\+面积筛选最佳 Ball 框 → 发布 JSON 到 /vision\_detection/ball。<br>6\. 完整掌握 /vision\_detection/ball 发布的 JSON 13 个字段：stamp / frame\_id / image\_width / image\_height / x / y / conf / label / cls\_id / bbox\_xyxy / bbox\_center / detected / stale / age\_sec，并能说出每个字段在后续课程的用途。<br>7\. 理解为什么 bbox 比中心点更重要 —— 足球是贴地物体，bbox 底部更接近真实落地点，为 Lesson 14 坐标变换铺垫。<br>8\. 掌握两个关键调参点：conf\_threshold \(0\.50 默认\) 控制检测严格度；ball\_hold\_sec \(1\.0 秒\) 实现短时保留防止瞬间抖动。<br>9\. 能完成 4 个实践：检查图像话题与模型文件 → 启动 YOLO 检测节点 → 观察 /vision\_detection/ball JSON → 用三档阈值对比检测稳定性。<br>10\. 知道完整 VisualKick Demo 由 3 个节点构成（ball\_detection / find\_ball\_head / ball\_to\_kick），一条 ros2 launch 拉起整个系统。||
|**过程与方法**|1\. 通过「机器人踢球的完整闭环 → 本课在哪一环」反向追溯，让学生从最终目标向上理解第 11 课的边界与定位。<br>2\. 通过「换种检测对象（人脸 / 颜色 / 形状 / 模板 / 足球），系统结构相同 vs 输出要求不同」的对照，承接 Lesson 8\-10 的知识。<br>3\. 通过「颜色方法 4 大局限 \+ 7 维对比表」的工程论证，让学生从「为什么 YOLO 更好」走到「在什么情况下 YOLO 才必须」。<br>4\. 通过「5 步流水线」\+「JSON 13 字段表」\+「bbox 底部 vs 中心」三个层级，让学生从「节点能跑」走到「能读懂它的每个输出」。<br>5\. 通过 4 个递进实践（检查 → 启动 → 观察 → 调参），让学生从「跑通」走到「看懂数据流」再到「会调参数」。<br>6\. 通过课堂最后的「VisualKick Demo 预览」一页，让学生在认知上看到「本课是三节点系统的第一颗螺丝」，激起对后续 4 节课的期待。<br>7\. 通过排查表的最后一条「检测到球但没踢 = 正常的」明确边界，避免学生把「看见」和「能踢」混淆。||
|**情感态度与价值观**|1\. 体会「从传统视觉走向深度学习视觉」的工程转折 —— 算法是工具，选型要看场景。<br>2\. 通过 JSON 结构化输出的设计，建立「话题契约」的工程审美 —— 同一份输出可以服务多个下游节点。<br>3\. 通过「本课只解决一件事，但做好」的边界意识，体会模块化设计的工程价值 —— 不贪多，把每一步做扎实。<br>4\. 通过 VisualKick 系统的整体预览，建立「机器人是一个由若干闭环组成的复杂系统」的认知 —— 看见全景，但聚焦当下。||
|**教学重点**|1\. 通用闭环结构 \+ 本课在 VisualKick 三节点系统中的位置 —— 这是认知主线。<br>2\. 颜色方法 vs YOLO 的 7 维对比表 \+ 选型决策 —— 这是本课工程思维的精华。<br>3\. /vision\_detection/ball 完整 JSON 13 字段 \+ 每个字段的后续用途 —— 数据契约设计。<br>4\. 为什么 bbox 比中心点重要（足球贴地）—— Lesson 14 坐标变换的关键铺垫。<br>5\. conf\_threshold 三档对比 \+ ball\_hold\_sec 的稳定性设计原理。<br>6\. ros2 launch k1\_visualkick\_demo visualkick\_demo\.launch\.py —— 一条命令的工程意义。||
|**教学难点**|1\. 「换场景但 YOLO 的输出更适合足球任务主线」的论证不能空喊 —— 必须落实到 bbox 字段如何被后续坐标转换使用。<br>2\. 「YOLO 是训练好的模型」对学生来说是黑箱概念 —— 不能展开讲深度学习，但要让学生知道「不用手写规则」这个工程意义。<br>3\. 13 字段 JSON 中部分字段对当前课没用（如 stamp / frame\_id / cls\_id），讲到时需要明确「这是为后续课程预留的」，避免学生误以为字段冗余。<br>4\. bbox 底部 vs 中心点的几何概念需要画图说明 —— 学生本能会用中心点，要解释「视觉中心」≠「物理落地点」。<br>5\. ball\_hold\_sec 的短时保留逻辑容易混淆 —— 学生第一次见「物体消失了但话题仍然有数据」的设计，需要画时间轴说明。<br>6\. 「检测到球 ≠ 机器人会踢」是认知边界，要在排查表里明确「这是正常的，不是 bug」。||
