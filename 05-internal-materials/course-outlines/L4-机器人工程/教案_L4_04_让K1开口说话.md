# 教案\_L4\_04\_让K1开口说话

|**适用学段**|高中\(机器人特色校\) / 大学入门||

|**教学目标**|||
|**知识与技能**|1\. 理解 TTS（Text\-to\-Speech，文本转语音）的概念，知道「文字 → 模型 → 音频波形 → 扬声器」这条流水线，建立「字符串能让机器人开口说话」的认知。<br>2\. 知道本课要用到的两个 SDK 客户端：LuiClient（语音能力）与 B1LocoClient（运动能力），理解它们各自管什么、何时用哪一个。<br>3\. 掌握 TTS 完整启动流程的 5 步顺序：客户端 Init → StopTts 清理旧服务 → 设置音频输出与音量 → 用 LuiTtsConfig 指定音色后 StartTts → SendTtsText 发送文字。<br>4\. 理解动作 API 的三大类（执行类 WaveHand / 表演类 WholeBodyDance / 行走类 Move），并知道行走类涉及双足平衡，留到第 6 课用 ROS2 重写时展开。<br>5\. 掌握模式约束：所有动作 API 必须先把 K1 切到 Walking 模式（开机 DAMP → Prepare → Walking）才能生效；持续动作必须 Open / Close 配对（如 WaveHand\.kHandOpen / kHandClose）。<br>6\. 理解 time\.sleep\(\) 的本质不是「暂停代码」，而是「等机器人完成动作」，并能根据动作类型估算合理的等待时长。<br>7\. 能把 SDK 单次调用封装成 say\(\) / wave\_hand\(\) / dance\(\) 三块「行为积木」函数，并按时序组合调用完成一段 30 秒的迎宾展示。||
|**过程与方法**|1\. 通过对照「人类发声链路 vs 机器人发声链路」，把抽象的 TTS 流程具象化。<br>2\. 通过逐步运行 lesson\_04\.ipynb 中预写好的 Cell，体验「读代码 → 跑代码 → 看反馈 → 改参数」的完整循环，进一步熟练第 3 课学到的 Notebook 工具。<br>3\. 通过 4 个递进式实践（说一句话 → 挥一次手 → 跳一段舞 → 自我介绍展示），从「单次 API 调用」过渡到「多 API 时序编排」。<br>4\. 通过函数封装环节，体会「积木式编程」——单次 API 适合调试、函数封装适合组合、组合行为适合展示。<br>5\. 通过课堂故障排查，培养「按现象定位问题层（无声 / 无动作 / 状态错）」的工程思维。||
|**情感态度与价值观**|1\. 在第 3 课「让 K1 点头」的基础上更进一步——本课让 K1 同时具备语音和动作两类能力，学生体会到「机器人的能力是积木，可以越拼越复杂」的工程美感。<br>2\. 通过设计自我介绍展示流程，把对机器人的兴趣从「能跑代码」推进到「能编排出有趣的人机交互」，让学生在课堂上获得展示和被看见的成就感。<br>3\. 在 Open / Close 配对、模式必须切换、time\.sleep 必须给够等约束中，建立「机器人有自己的节奏，代码必须配合机器人」的工程谦逊。<br>4\. 通过强调安全空间与软急停，建立「真机操作 = 物理风险」的安全意识。||
|**教学重点**|1\. TTS 完整 5 步启动流程，特别是 LuiTtsConfig 的音色参数与 StartTts 的顺序不可省略。<br>2\. 动作 API 三大类的区分，以及「模式必须切到 Walking」「Open / Close 必须配对」两条铁律。<br>3\. 函数封装思想——把 SDK 单次调用包装成 say\(\) / wave\_hand\(\) / dance\(\) 三块行为积木，再用积木拼出展示流程。<br>4\. 进一步熟练 Notebook 工具——本课不需要学生从零写代码，重点是读懂、跑通、改参数、看反馈。||
|**教学难点**|1\. 理解「程序执行只用毫秒级，但机器人动作和语音是秒级」——time\.sleep 不是暂停程序，而是给机器人完成动作的时间窗口。<br>2\. 理解「动作 API 的本质不是动画，而是 K1 关节模组按预设轨迹运动」——所以才需要模式约束、安全空间、Open/Close 配对。<br>3\. 区分「单次 API 调用」与「函数封装后的行为积木」两种用法的适用场景——前者适合学习与调试，后者适合组合与展示。<br>4\. 第一次让学生在真机上调用动作 API 时，经常会忘记切模式或忘记配对 Close，需要教师在巡视时提前预警。||
