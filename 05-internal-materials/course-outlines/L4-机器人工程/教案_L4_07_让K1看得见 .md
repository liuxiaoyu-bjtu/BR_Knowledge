|**知识与技能**|1\. 理解机器人视觉的基本流程：相机采集 → ROS2 发布图像话题 → Python 订阅 → OpenCV 转换 → 显示 / 保存。<br>2\. 知道 K1 当前的图像话题 /boostercamera/head/raw/rgb，类型为 sensor\_msgs/msg/Image，编码为 nv12。<br>3\. 认识 sensor\_msgs/msg/Image 消息的核心字段：height / width / encoding / data / step。<br>4\. 区分常见图像编码 \(bgr8 / rgb8 / mono8 / nv12\)，理解 cv\_bridge 自动处理前三者，nv12 需要手动转换。<br>5\. 掌握 NV12 → BGR 的 4 步转换：np\.frombuffer → reshape \(h\*1\.5, w\) → ascontiguousarray → cv2\.cvtColor\(COLOR\_YUV2BGR\_NV12\)。<br>6\. 区分本课两个版本程序的适用场景：实时显示版本（教师演示用，需要 X11）vs 无窗口拍照版本（学生用，跨平台稳定）。<br>7\. 理解 image\_callback「被动触发」机制：ROS2 每收到一帧自动调一次回调，与 Lesson 06 Service「主动调用」形成对比。<br>8\. 能完成 4 个实践任务：检查图像话题、运行无窗口拍照程序、修改保存目录、启用水印保存。||
|**过程与方法**|1\. 通过「从会动到会看」的视觉感知导入，把前 6 课的动作控制视角延展到本课的环境感知视角。<br>2\. 通过 5 段视觉流程图（采集 → 发布 → 订阅 → 转换 → 保存）建立全课主线。<br>3\. 通过两版本程序对比，让学生理解课堂用稳定版本（无窗口）、教师演示用直观版本（实时显示）的工程选择。<br>4\. 通过 NV12 4 步转换的拆解，体验「字节 → 数组 → 内存连续 → cvtColor」的图像数据底层操作。<br>5\. 通过 4 个递进式实践（验证 → 运行 → 改参数 → 启用拓展），让学生从「能用」到「会改」。||
|**情感态度与价值观**|1\. 体会让机器人「看见」是与「能动」同等重要的能力——感知是行动的前提，本课是具身智能闭环的关键起点。<br>2\. 在第一次看到 K1 相机视角时建立「我能从机器人眼里看世界」的成就感与代入感。<br>3\. 通过加水印 \+ 多组目录的设计，培养小组协作意识与产物归属意识。<br>4\. 通过 NV12 这种 K1 特定编码的处理，体会「工程中常常有不完美但要适配」的现实——这是后续 Lesson 11\+ 足球视觉的基本姿态。||
|**教学重点**|1\. 5 段视觉链路：相机 → ROS2 Image → Python 订阅 → OpenCV → 保存。<br>2\. K1 图像话题 /boostercamera/head/raw/rgb \+ 类型 sensor\_msgs/msg/Image \+ 编码 nv12 三件套。<br>3\. NV12 → BGR 的 4 步手动转换核心代码。<br>4\. 两版本程序的适用场景区分。||
|**教学难点**|1\. NV12 编码的 YUV 4:2:0 数据布局——为什么 reshape 成 \(height \* 3 // 2, width\)？<br>2\. image\_callback 是「被动触发」——ROS2 每收到一帧自动调，学生代码不主动「拉」数据。<br>3\. cv\_bridge 与手动 numpy \+ cv2 两种转换方式的分工——常见编码自动处理，nv12 必须手动。<br>4\. OpenCV 用 BGR 不是 RGB——通道顺序差异容易让学生在调色时困惑。<br>5\. Windows \+ VSCode 远程不支持 X11，cv2\.imshow 跑不起来——所以学生用无窗口版本。||

NV12 → BGR 核心代码（约 3 分钟）：**<br>翻到 PPT 第 11 页。在大屏上逐行讲解 ros\_image\_to\_bgr\(\) 函数：<br>Step 1：**np\.frombuffer\(msg\.data, dtype=np\.uint8\)**  把字节流解释为 uint8 数组<br>Step 2：**yuv\.reshape\(\(h\*3//2, w\)\)**  重塑成 NV12 平面布局（Y 平面 \+ UV 交错平面）<br>Step 3：**np\.ascontiguousarray\(yuv\)**  保证内存连续，OpenCV 才能读<br>Step 4：**cv2\.cvtColor\(yuv, COLOR\_YUV2BGR\_NV12\)**  转成 OpenCV 能用的 BGR<br>讲完 4 步后，强调底部一句：**「NV12 比 BGR 节省 1/2 内存，但 OpenCV 不能直接处理 NV12 —— 必须先转 BGR。」**||**活动二**<br>1\. 听讲并理解「图像话题 = 一帧一帧连续流」。<br>2\. 在学习单上抄下 Image 消息的 6 个字段。<br>3\. 区分 OpenCV 与 cv\_bridge 的分工。<br>4\. 在学习单上画 4 种 encoding 卡片，圈出本课用的 nv12。<br>5\. 跟读 NV12 → BGR 的 4 步关键代码（frombuffer / reshape / contiguous / cvtColor）。<br><br>**学生产出**<br>·  学习单上完成 6 字段表 \+ 4 编码对比。<br>·  能默写 NV12 → BGR 的 4 步函数调用顺序。|

|**设计意图  **<br>4 个实践设计成「难度递增」的链路：实践 1 是观察、实践 2 是运行、实践 3 是改参数、实践 4 是启用拓展功能。学生从「看见」走到「改一点」走到「会用拓展」。<br>实践 1 加 hz 命令是本课比之前课程精进的地方——只看 list 不够，必须看到帧率才确认相机在工作。这是工业排查的基本动作。<br>实践 3 改 SAVE\_DIR 看似简单，实际是「程序参数化」的工程思维入门——同一份代码不同小组用不同输出目录，这是大型项目协作的基础。<br>实践 4 启用水印（而不是从零写水印）也是教学策略——课堂时间不允许从零写图像处理代码，但「启用一个拓展功能」体现了「模块化设计」思想：功能放在那里，需要时启用。|||
