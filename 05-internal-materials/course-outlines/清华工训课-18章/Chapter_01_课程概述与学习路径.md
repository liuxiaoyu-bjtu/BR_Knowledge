# Chapter 01｜课程概述与学习路径

## 1\.1 课程定位

《Booster K1 人形机器人应用实践手册》是面向本科院校工程训练中心打造的人形机器人实训课程配套资料。本课程以 Booster K1 人形机器人为实操载体，紧扣“机器人环境感知、任务理解、动作生成、综合项目落地”的核心主线，统筹设置机器人控制、运动动作、环境感知、智能行为开发与整机系统整合等教学模块。

本手册既不是机器人硬件参数说明书，也不是 API 接口使用指南。学生即便掌握单一接口的调用方式，仅能完成简易操作，却难以弄懂整套机器人系统的设计逻辑、各功能模块的协同机制，以及系统故障对应的排查思路。本课程旨在培养学生机器人应用开发核心能力：将具象的机器人实操任务，拆解为一套可解析、可运行、可验证、可调试的标准化工程系统。

本课程面向具备 Python 编程基础的大二到研一阶段学生，学习者无需提前掌握 Linux 基础命令、机器人系统等相关前置知识。后续章节将结合实操任务循序渐进讲解核心专业概念，涵盖 ROS2 第二代机器人操作系统、SDK 软件开发工具包、YOLO 单阶段目标检测算法、Behavior Tree 行为树、MuJoCo 机器人物理仿真引擎，以及 Sim\-to\-Real 仿真虚实迁移技术。

从课程定位而言，Booster K1 不只是一台用于演示的设备，更是一套面向具身智能开发的综合实验平台。具身智能（Embodied Intelligence）的核心内涵，是智能体依托本体结构、各类传感器与执行器，通过与真实环境交互完成指定任务。针对人形机器人，身体结构、视觉感知、动作生成、平衡控制、行为决策五大维度，都会直接决定任务完成质量。因此本课程以真实落地项目为核心载体，引导学习者完整掌握人形机器人任务的拆解、开发实现与效果验证全流程。

本课程核心学习目标分为四项：

1. 理解 Booster K1 人形机器人应用系统的基本构成；

2. 掌握机器人基础控制、动作调用、视觉感知、行为逻辑搭建的开发流程；

3. 理解动作生成、足球任务两大应用主线对应的完整工程开发流程；

4. 能够把多个模块整合成可运行、可展示、可解释的综合项目。

学习者完整研读本手册后，不应仅停留在知晓各类算法、接口名词的层面，更要具备完整的工程思维，能够清晰阐述以下内容：机器人为什么需要这些功能模块；数据在各模块间的传输流转逻辑；代码指令驱动机器人完成对应动作的运行机制；如何通过实验现象判定系统运行状态；系统运行异常时，分层次、分模块的故障排查思路。

## 1\.2 系统任务拆解

在人形机器人应用开发中，一个看似连续的物理动作（例如“看到足球后追过去并踢球”），在底层是由多个独立且高度协作的模块组合而成的闭环系统。

为了规范机器人系统工程开发，本课程将典型的人形机器人应用任务拆解为六类核心能力模块：

|能力模块|工程定位与解决的问题|本课程的具体体现|
|---|---|---|
|控制|实现机器人安全、平稳可控的物理运动|基础运动控制、头部姿态控制、运动速度调节|
|动作|身体高维动作的表示、生成与调用|示教动作、动作数据序列、动作模型训练与部署|
|感知|从传感器原始数据中提取获取环境特征|相机图像采集、基于 YOLO 的目标检测与识别|
|空间理解|将像素级检测结果转换为三维空间坐标表示的位置数据|图像坐标系到相机坐标系、机器人基座坐标系的坐标变换（3D定位）|
|行为决策|根据当前环境状态选择下一步动作|有限状态机、行为树、踢球触发条件判断|
|系统整合|调度多模块协同完成复合任务|自主追球闭环系统、视觉踢球闭环系统、完整项目验收|

在工程落地中，上述模块通常以**ROS2节点（Node）**的形式独立运行。模块之间不直接共享全局变量，而是通过标准的通信接口（Topic / Service）进行数据交互。

这种任务拆解方式具备两个明确的工程意义：

1. **明确数据流向与数据接口标准。**机器人完成复杂任务依赖于完整的数据流闭环，将系统拆解后，每个节点的输入输出格式（接口标准）被清晰定义，使得各模块可以独立开发与测试。以“视觉踢球”为例：

    - **感知节点：**仅负责输出图像中有没有足球，足球在图像中的哪个位置（像素坐标）；

    - **空间理解节点：**将像素组表转化为机器人坐标系下的三维距离

    - **行为决策节点：**根据距离数据判断当前状态（如“寻球中”、“追球中”或“已到达目标位”），并向控制节点下发对应指令；

    - **控制/动作节点：**接收指令并驱动电机完成物理动作。

2. **建立分层排查与故障定位能力。**真实机器人系统的故障通常具有局部性，比如某个模块输出不稳定、某个参数不合适、某个接口数据格式不一致、某个状态切换时机不正确。 将系统任务模块化，是实现复杂机器人系统分层排查与精准诊断的前提。 继续以“视觉踢球”为例，当“视觉踢球”出现异常（例如机器人跑到球前却不踢球）时，工程化的排查路径并非盲目修改全局代码，而是沿着数据流逐层定位： 

    - **感知层排查**：检查目标检测节点是否持续输出稳定的目标框；

    - **定位层排查**：检查三维坐标变换结果是否存在严重偏差； 

    - **决策层排查**：检查行为树节点中的触发阈值设置是否过高； 

    - **执行层排查**：检查底层动作接口是否正常接收到了触发信号。

结合上述能力划分，本课程提炼出两条贯穿全书的开发主线链路：

1. **任务行为链路（以视觉踢球为例）：**

```Plaintext
相机图像采集
  ↓
目标检测
  ↓
足球位置理解（目标空间坐标转换）
  ↓
追球与减速停稳控制
  ↓
踢球触发逻辑判断
  ↓
踢球动作/策略执行
  ↓
系统运行状态观察评估
```

2. **动作生成****链路（以动作训练为例）****：**

```Plaintext
动作数据采集
  ↓
动作数据表达
  ↓
训练参数配置
  ↓
仿真验证（Sim-to-Sim）
  ↓
模型导出
  ↓
真机部署（Sim-to-Real）
  ↓
物理执行效果观察评估
```

两条链路分别代表了“基于环境信息驱动的智能决策”与“基于数据驱动的高维动作生成”，共同构成本课程中人形机器人开发的核心能力体系。

## 1\.3 核心任务主线

本课程围绕两条核心任务主线展开：动作生成主线和足球任务主线。

- **动作生成主线**解决“身体动作如何产生”的问题。重点学习如何采集动作数据、记录、表达、训练、验证，最终将模型部署至机器人，实现全身姿态与动作的稳定表达。

- 足球任务主线解决“如何根据环境做出反应”的问题。重点学习如何通过相机等传感器采集环境数据，解析足球位置，并在决策后实时驱动机器人完成追球、停稳与踢球等连续任务。

两条主线在实际工程中相辅相成：足球任务中的高难度踢球动作需要依赖动作生成主线训练出的模型，而动作模型的真机运行效果，也需要通过足球任务主线中的传感器反馈与真实环境进行实测验证。

### 1\.3\.1 动作生成主线

与轮式机器人、固定式机械臂不同，人形机器人具备高自由度与非线性动力学特性，无法简单通过末端轨迹规划实现动作。本课程将动作视为“随时间演化的高维全身关节状态序列”，通过数据化、模型化与工程化的方法完成动作开发（动作可以来自示教，也可以来自动作数据和模型训练）。简单来说就是，人形机器人需要协调多个关节，保持身体姿态，并在执行动作时尽量稳定。

Chapter 6 到 Chapter 9 将围绕这条主线展开：

- **Chapter 6｜动作表达与数据结构：**理解关节空间、时序轨迹、CSV 与 NPZ 等数据表达形式。

- **Chapter 7｜BeyondMimic 训练流程：**基于BeyondMimic（动作学习相关框架），使用采集到的动作数据进行动作模型训练。

- **Chapter 8｜模型部署与执行：**讲解模型文件的导出、解析加载以及进入仿真或真机执行流程。

- **Chapter 9｜综合项目：基于 BeyondMimic 学会一个动作：**打通“数据准备 ➔ 模型训练 ➔ 评估导出 ➔ 真机部署”的完整工程闭环。

这条主线的工程目标是让学习者先建立一个清晰认识：人形机器人的动作可以被数据化、模型化和工程化，一个动作从数据到模型、从模型到仿真、再从仿真到真实机器人，是一个需要反复验证的流程。

在本课程中，动作生成主线使用一个训练好的舞蹈动作作为示例。学习者可以先在 MuJoCo 中查看仿真执行效果。

> MuJoCo 是一种常用于机器人动力学仿真的物理引擎，可以用来观察机器人模型在虚拟环境中的动作表现。视频代表 Sim\-to\-Sim 阶段的成功标准。
> 
> 

\[04\.MuJoCo\.mp4\]

在动作生成开发中，系统遵循 **Sim\-to\-Sim ➔ Sim\-to\-Real** 的工程验证路径：

- **Sim\-to\-Sim（仿真到仿真验证）**：在 MuJoCo 物理仿真引擎中导入动作模型，验证动作在虚拟环境中的稳定性与可执行性。

- **Sim\-to\-Real（仿真到真机迁移）**：将仿真验证通过的模型部署至真实 Booster K1 硬件平台，克服真机动力学偏差、传感器噪声与通信延迟，完成物理安全执行，动作生成主线才形成完整闭环。

### 1\.3\.2 足球任务主线

足球任务主线是本课程的综合应用主线，它把感知、控制、空间理解、行为决策和动作触发连接在一起，向学习者传达：一个机器人系统如何从“获得传感器数据”到“完成任务”。该主线分为两个递进的子任务：自主追球和视觉踢球。

#### 1\.3\.2\.1 自主追球

自主追球任务构建了基础的“视觉\-控制”反馈闭环，要求机器人相对足球的位置持续调整运动，其数据流向如下：

```Plaintext
相机图像输入 → YOLO目标检测 → 空间坐标转换 → 运动误差计算 → 速度指令
```

整个过程实现了“看到足球 → 判断方向与距离 → 调整朝向 → 前进靠近 → 稳定停下”的完整闭环，整个过程涉及后续多个章节的能力。

\[01\.自主追球\.MOV\]

> 在视频中，可以重点观察三个现象：机器人是否能够锁定足球，机器人是否能够根据足球位置调整运动方向，机器人靠近足球后是否能够减速并停稳。在 Chapter 17 中，将带领学习者完成自主追球这个综合项目。
> 
> 

#### 1\.3\.2\.2 视觉踢球

视觉踢球任务在自主追球的基础上引入了**“行为决策机制与策略出发条件”**，该任务在看到足球、接近足球的基础上，进一步执行踢球策略，实现结合机器人当前姿态与状态，动态判断并出发对应的踢球动作。这里的动态踢球策略常被称为 VisualKick，它是一种根据视觉目标信息触发踢球行为的策略控制方式，它围绕目标位置、触发条件和动作执行接口形成完整的策略链路。对比自主追球，这个任务多出了几个关键问题：

- 机器人是否已经接近合适的踢球区域；

- 机器人是否已经基本停稳；

- 足球相对机器人身体的位置是否可以触发踢球动作；

- 踢球策略是否能成功执行。

## 1\.5 手册使用方式

本手册采用“教材式解释 \+ 实验手册式指引”的写作方式。也就是说，每章既会解释必要概念，也会说明本章对应的系统任务、代码作用、运行方式和验证现象。

阅读本手册时，建议按以下顺序使用每一章：

1. 先看本章在系统中的位置，理解它解决的是哪一类问题。

2. 再读核心概念，掌握后续代码和实验需要用到的术语。

3. 进入程序案例，理解代码的输入、输出和关键结构。

4. 运行实验，观察终端输出、图像结果、ROS2 话题或机器人动作。

5. 对照实验现象，判断系统是否达到了本章目标。

6. 遇到问题时，优先从数据流、参数、接口和运行状态四个方向排查。

在机器人工程开发中，**代码无语法错误并不等于物理任务执行成功**。机器人在真实环境中还会受到相机视野、光照、网络连接、机器人状态、地面环境、动作稳定性和安全边界等因素影响。因此，本课程特别强调观察和验证。读者需要学会看日志、看话题、看图像、看机器人动作，而不是只看代码是否执行结束。

后续章节中，正文会尽量保持统一结构：

- 先说明本章任务；

- 再解释关键概念；

- 然后进入代码或实验；

- 最后给出运行验证、常见问题和小结。

这种结构有助于在真实任务情境中理解抽象概念。例如，学习 ROS2 时，不只是记住 Node、Topic 和 Service 的定义，而是理解它们如何让视觉节点、控制节点和行为节点协同运行。学习 YOLO 时，也不只是知道模型可以检测足球，而是理解检测结果如何成为追球控制的输入。学习动作生成时，不只是知道模型训练完成，而是理解训练结果如何进入仿真验证和真机部署。

本手册中的视频、图片、代码和实验记录都服务于同一个目标：让读者能够把“看到的现象”和“背后的系统结构”对应起来。读者在学习时可以把每章都看成一个小型工程任务，而不是孤立知识点。

## 1\.6 本章小结

本章建立了《Booster K1 人形机器人应用实践手册》的整体学习地图。

首先，本课程面向本课院校工训中心的人形机器人应用实践教学，适合具备 Python 编程基础、但不一定具备机器人开发经验的读者。课程目标不是介绍零散接口，而是帮助读者理解并完成一个具身智能机器人应用系统。

其次，本章从系统角度拆解了人形机器人任务。一个完整任务通常包含控制、动作、感知、空间理解、行为决策和系统整合等模块。只有理解这些模块的输入输出关系，才能在后续项目中有效运行代码、观察现象和排查问题。

再次，本章明确了两条核心任务主线。动作生成主线关注动作从数据采集、训练、仿真验证到真机部署的流程；足球任务主线关注机器人如何识别足球、追踪足球，并进一步完成视觉踢球。Chapter 1 中展示相关视频只是为了建立目标感，具体技术细节会在后续章节逐步展开。

最后，本章说明了 18 个 Chapter 的学习路径。读者将先建立系统认知，再进入控制系统、动作生成系统、感知系统、策略与行为系统，最终完成自主追球和视觉踢球两个综合项目。

进入下一章后，我们将从整体架构角度理解 Booster K1。读者需要进一步认识 K1 的硬件层、控制层、计算层、软件层和行为层，建立后续所有实验和项目的系统基础。
