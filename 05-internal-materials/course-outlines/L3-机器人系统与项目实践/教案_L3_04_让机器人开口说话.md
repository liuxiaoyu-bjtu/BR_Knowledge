# 教案\_L3\_04\_让机器人开口说话

|**基本信息**|||
|---|---|---|
|**课    题**|让机器人开口说话||
|**教学目标**|||
|**知识与技能**|理解 TTS 的含义，知道文字显示与语音输出的区别。<br>掌握 LuiClient、LuiTtsConfig、LuiTtsParameter、StartTts、SendTtsText、WholeBodyDance 等接口的基本作用。||
|**过程与方法**|通过分段代码运行，完成语音模块初始化、音频输出配置、音色选择、文本播报和全身舞蹈调用。<br>通过修改文本、音色和舞蹈 ID，观察参数变化带来的不同效果。||
|**情感态度与价值观**|体验机器人语音表达带来的交互感，认识声音是人机交互的重要通道。<br>形成多模态表演中注意节奏、等待和安全模式切换的意识。||
|**教学重点**|TTS 语音输出链路，以及语音播报与 WholeBodyDance 的组合流程。||
|**教学难点**|理解 TTS 不是 print，而是文本处理、音色配置、音频输出和扬声器播放共同完成的链路。||
|**教学活动流程**|||
|**教师活动**||**学生活动**|
|环节一：【时长：5分钟】<br>展示 print 文本和机器人语音播报的对比，提出问题：屏幕显示文字为什么不等于机器人说话？<br>说明本课任务：完成“先说话，再跳舞”的开场表演。||活动一：<br>判断 print 和 TTS 的区别。<br>说出机器人真正发声还需要哪些环节。|
|设计意图：用常见误解导入 TTS，明确本课不是学显示文字，而是学语音输出链路。|||
|环节二：【时长：10分钟】<br>讲解声音、数字音频和 TTS 基本流程：文本处理、发音标注、声学建模、声码器、扬声器播放。<br>解释音色模型的含义以及 LuiTtsConfig 中模型字符串的作用。||活动二：<br>记录 TTS 四步流程和“音色模型”概念。<br>举例说明同一句话为什么可以有不同声音。|
|设计意图：补足语音技术背景，让教师和学生知道代码背后发生了什么。|||
|环节三：【时长：12分钟】<br>分段运行代码：初始化 LuiClient、StopTts、pactl 设置音频输出、StartTts、SendTtsText。<br>说明 LuiTtsParameter 是把文本包装成播报参数，time\.sleep 用于等待播报完成。||活动三：<br>观察机器人是否发声，记录每一段代码的作用。<br>修改一句播报文本并运行，验证文本变化带来的效果。|
|设计意图：将语音输出链路落到可运行代码上，同时培养音频配置和等待时间的工程意识。|||
|环节四：【时长：13分钟】<br>讲解 WholeBodyDance 接口，演示 ChangeMode 到 Walking 后调用 kMoonWalk 或 kMichaelDance1。<br>将 TTS 与舞蹈组合成完整开场表演，强调先说话、再动作、动作后等待。||活动四：<br>观察不同舞蹈 ID 的效果。<br>说出语音和动作组合时为什么需要控制顺序和等待时间。|
|设计意图：让学生体验多模态输出，理解机器人表演是语音、模式、动作和节奏的组合。|||
|环节五：【时长：5分钟】<br>总结 TTS 代码结构和表演流程，指出第5课将进入 ASR：机器人不仅会说，还要能听。<br>快速提问：StopTts 有什么作用？音色在哪里设置？为什么舞蹈前要切模式？||活动五：<br>回答回顾问题，整理 TTS、音色、音频、舞蹈接口关键词。|
|设计意图：巩固本课核心代码链路，并自然过渡到语音识别。|||
