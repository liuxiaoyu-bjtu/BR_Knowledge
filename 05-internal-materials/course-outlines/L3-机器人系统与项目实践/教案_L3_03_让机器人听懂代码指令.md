# 教案\_L3\_03\_让机器人听懂代码指令

|**基本信息**|||
|---|---|---|
|**课    题**|让机器人听懂代码指令||
|**教学目标**|||
|**知识与技能**|理解 SDK、API、客户端对象、通信初始化和机器人模式切换的基本含义。<br>掌握 B1LocoClient、ChangeMode、WaveHand、Handshake、Move、Dance 等基础代码控制接口的作用。||
|**过程与方法**|通过分段运行 Notebook，经历导入接口、初始化通信、创建客户端、切换模式、调用动作 API 的完整过程。<br>通过修改参数，观察同一接口在不同参数下产生的动作差异。||
|**情感态度与价值观**|形成用程序组织机器人行为的意识，理解代码控制比遥控器更适合表达顺序、条件和组合任务。<br>建立真实机器人编程中的等待、停止和安全收尾意识。||
|**教学重点**|机器人代码控制链路，以及基础动作 API 的调用顺序与参数含义。||
|**教学难点**|理解 Python 代码不是直接控制电机，而是通过 SDK、通信通道和机器人控制系统触发动作能力。||
|**教学活动流程**|||
|**教师活动**||**学生活动**|
|环节一：【时长：5分钟】<br>回顾第2课遥控器控制，提出问题：如果不用遥控器，能不能让机器人按固定顺序完成欢迎动作？<br>展示本课项目“迎宾动作秀”：模式切换、挥手、握手、前进、舞蹈。||活动一：<br>描述遥控器控制和代码控制的差异。<br>预测完成迎宾动作秀需要哪些动作接口。|
|设计意图：从熟悉的遥控操作过渡到代码控制，让学生感受到程序可以组织连续任务。|||
|环节二：【时长：8分钟】<br>讲解 SDK 与 API 的关系：SDK 是工具包，API 是工具包里的功能入口。<br>用图示说明 Python 程序、Booster SDK、通信通道、机器人控制系统、关节执行之间的链路。||活动二：<br>记录 SDK、API、客户端对象三个概念。<br>用自己的话解释“代码为什么能让真实机器人动起来”。|
|设计意图：先建立代码到实体机器人的中间层概念，避免学生把 API 调用误解成直接驱动电机。|||
|环节三：【时长：12分钟】<br>打开 Notebook，分段讲解并运行：导入 SDK、ChannelFactory 初始化、创建 B1LocoClient、client\.Init、time\.sleep 等代码。<br>强调 IP、通信初始化和等待时间的作用。||活动三：<br>跟随教师观察每段代码运行结果，标记初始化相关代码。<br>判断哪些代码是准备环境，哪些代码是真正触发动作。|
|设计意图：用分段运行降低调试难度，让学生知道机器人编程常常先验证连接，再运行动作。|||
|环节四：【时长：15分钟】<br>讲解并演示 ChangeMode、WaveHand、Handshake、Move、Dance 等接口。<br>特别说明 Move\(vx, vy, vyaw\) 是连续速度控制，必须用 Move\(0,0,0\) 停止。<br>组织学生修改一个参数或动作顺序，观察机器人表现。||活动四：<br>观察动作执行，记录每个 API 对应的机器人行为。<br>尝试说明 vx、vy、vyaw 分别控制什么，为什么前进后必须停止。|
|设计意图：把抽象函数调用与真实动作一一对应，形成代码、参数、行为之间的直接联系。|||
|环节五：【时长：5分钟】<br>总结本课控制链路：初始化通信→创建客户端→切换模式→调用动作→等待→停止。<br>提出下节课预告：机器人不仅能动，还能把文字说出来。||活动五：<br>复述完整流程，整理本课关键 API 名称与作用。|
|设计意图：收束代码控制主线，为第4课 TTS 语音能力的引入保留清晰接口意识。|||
