# K1 信息与状态接口：运行与记录

本次采集截图中的八项接口，取得当前 K1 的实际清单与状态。脚本已编写，真机记录需在机器人环境中运行后生成。

| 接口 | 保存内容 |
| --- | --- |
| `robot_info` | 厂商、型号、名称、序列号、固件版本及全部扩展字段；按属性读取 |
| `get_mode()` | 当前公开模式返回值及类型 |
| `list_gaits()` | 本次返回的全部步态名称 |
| `get_gait()` | 本次步态返回值及类型 |
| `list_frames()` | 本次可见的全部坐标系名称，不预设名称、不只取前几项 |
| `list_joints()` | 全部关节对象及嵌套字段，包括本版本返回的限位、力矩、速度与扩展信息 |
| `list_sensors()` | 全部传感器对象及字段，包括标识、类型、型号、扩展信息 |
| `list_actions()` | 全部动作对象及字段，包括本版本返回的动作标识、类型、时长、可中断性等 |

脚本只查询这八项信息，不执行模式切换、步态切换、动作或踢球。无需安装视觉、语音等额外组件，使用已经能连接机器人的 BoosterOS SDK 环境即可。

## 1. 准备文件

可直接复制[采集工具包](K1信息与状态接口_采集工具.zip)到机器人开发环境，解压后使用。包内是下面三个文件。

将以下三个文件放到机器人开发环境的同一文件夹。选择终端或 Jupyter 中的一种运行方式即可。

- [probe_k1_info_state.py](probe_k1_info_state.py)：实际采集脚本。
- [K1信息与状态接口_真机采集.ipynb](K1信息与状态接口_真机采集.ipynb)：Jupyter 运行入口。
- 本说明：操作及记录含义。

保持当前机器人状态，无须为了采集切换到行走模式。控制台需要能正常创建 `BoosterRobot()`，或者 Jupyter 内核中已经存在可用的 `robot`。

## 2. 运行一次

**终端方式**：打开上述文件所在目录，执行：

```bash
python3 probe_k1_info_state.py --tester xy
```

如需记录本次现场配置，可加备注：

```bash
python3 probe_k1_info_state.py --tester xy --note "K1，当前为prepare模式，未连接额外配件"
```

备注由操作者填写，脚本仍会保存接口真实返回值。无需手工填写固件、序列号或各种清单。

**Jupyter 方式**：打开配套 Notebook，依次运行两格代码。第一格填写测试人和可选备注，第二格运行采集并显示保存位置。程序优先复用当前内核中名为 `robot` 的实例；没有时由采集模块创建。同一模块重复运行会复用已创建的连接，每次另建结果目录。

如果内核中的旧连接已经失效，重启内核后再运行；不在脚本中自动销毁既有连接。终端应使用独立 Python 进程，不在已有机器人连接的 Notebook 中用 `%run` 反复创建进程入口。

## 3. 结果保存在哪里

默认保存在运行时工作目录下：

```text
K1信息状态测试结果/
└── K1信息状态_日期_时间_微秒/
    ├── 原始记录.json
    ├── 采集汇总.md
    ├── SDK接口定义.txt
    ├── 测试脚本.py
    ├── 分接口/
    │   ├── robot_info.json
    │   ├── get_mode.json
    │   └── ……共八项
    └── K1信息状态_日期_时间_微秒.zip
```

最后将打印压缩包的绝对路径。把这个 ZIP 保存并反馈即可，无须手抄清单或另外填写记录表。结果也可复制回知识库 `04-shared/sdk-tests/K1信息状态测试结果/`，再告知具体目录。

需要指定保存位置时，终端增加 `--output 路径`，或修改 Notebook 第一格的 `OUTPUT_ROOT`。

## 4. 运行中怎样判断

控制台逐项显示 `returned` 或 `error`，列表还显示条目数。完整内容在 JSON 和 Markdown 中，不受控制台显示长度影响。

- `returned`：调用返回。列表为零项时按零项记录，不能据此宣称该类能力不存在。
- `error`：保存异常和堆栈，继续查询其他接口；不需要为了收齐一张“全绿”表修改机器人状态。
- `list_frames()`首次为空：在五秒窗口内重读，保留每次结果。窗口结束仍为空就如实登记。五秒用于等待发现数据，不是性能验收标准。
- 出现“导出提示”：接口可能已经返回，但某个字段未能结构化展开。原始 `repr` 和本机定义同时保存，供回读处理，不能将字段导出问题写成接口调用失败。
- 中断采集：已经取得的结果仍保留；正常的键盘中断会生成部分记录压缩包。强制杀进程可能来不及打包，仍可交回已有目录。

命令行退出码 `0` 表示八项均返回，`1` 表示八项已查询但有接口报错，`2` 表示连接失败或采集未完成。成功返回空列表仍须按内容分析；这些退出码不是硬件功能验收结论。

## 5. 后续如何补充 K1 专用信息

回读时核对型号、SDK/固件版本和本次配置，整理实际坐标系、关节字段与限位、传感器标识、步态和动作标识，并注明来源记录。

`list_frames()`列出本次可见的 TF 名称，不证明任意两帧可互相变换，也不能将一次结果当作所有状态下的完整 TF 树。`list_actions()`返回动作元信息，本次不测试执行。`get_gait()`按当前文档记录的是 SDK 最近设置的步态值，不等于运动传感器测得的实际步态；本机实现一并留存以供核对。单位和字段含义先查本机类型定义和对应版本文档，不从字段名或数值大小猜测。

本次结果将补充到 SDK 的 K1 专用说明；在实际记录反馈前，不填写“已在 K1 验证通过”。
