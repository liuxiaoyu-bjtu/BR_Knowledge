## 约束条件

### 约束 #001 | 高职≠K12 延伸 | 2026-07-29

- **来源**：讨论高职课程优先级时提出
- **内容**：高职课程不应是 K12 L4 的简单延伸或放大版。K12 通识课以"系统认知→工程闭环"为主线，高职需独立设计"工程运维 / 二次开发 / 赛证融通"能力线，定位为"能部署、能调试、能二次开发、能对接产业标准"的工程技术人才培养
- **影响**：B2 能力图谱需新增"职业能力维度"；B3 需预留 vocational-track；K12 通识课的课标映射逻辑不适用于高职
- **状态**：✅ 已确认，待高职内容入库后深化

### 约束 #002 | 不成熟的实践不应反哺规范层 | 2026-07-29

- **来源**：讨论 B2 能力图谱锚定策略时提出
- **内容**：K1 通识课 L1-L4 的设计质量参差不齐、整体偏零散，不应直接从课程内容"提取"能力标准。B2/B1 应从课标 + 行业共识 + 高质量锚点（如清华工训课程）**推导**，再用 K1 通识课做**对照校验**，找出差距标注为待优化，而非把现状当标准
- **影响**：B 系列任务的前置条件改为"两条以上课程线 + 质量审计完成"
- **状态**：✅ 已确认

### 约束 #003 | "有内容"优先于"体系健全" | 2026-07-29

- **来源**：讨论高职优先级时提出
- **内容**：在课程设计的早期阶段，客户需要能用的课纲而非完美的理论框架。紧急任务（如高职课程构建）优先于体系任务（如 B 系列），体系任务从旁记录约束条件，等实践充分后再正式启动
- **影响**：执行路径调整为"补内容 → 记约束 → 审计 → 建标准"，B 系列不取消但暂缓
- **状态**：✅ 已确认

### 调研 #001 | 高职通识课定义 | 2026-08-04

- **来源**：WebSearch + 教职成〔2019〕13号 + 《人工智能通识课程体系规范》
- **结论**：
  1. 高职课程分两类：公共基础课程（通识课）和专业（技能）课程。通识课=公共基础课，是面向全校各专业学生的必修/限定选修课，不以专业技能培养为目标
  2. 高职通识课包括：思政、体育、军事、心理健康、信息技术、语文、数学、外语、职业发展与就业指导、创新创业等
  3. 通识课通常**不涉及专业设备实操和编程**。如果一门课以 K1 机器人实操和 SDK 编程为主要内容，它在高职课程体系中应归类为**专业课**（专业基础课或专业核心课），而非通识课
  4. 教育部 2025 年要求高校开设 ≥1 学分的"人工智能通识课程"，但这是面向全体学生的 AI 认知普及课（不讲具体机器人平台），与具身智能应用开发课性质不同
- **影响**：现有 5/21 课程体系将"通识基础"命名为通识课不准确。正确的定位应为"K1 机器人基础（专业基础课）+ K1 应用开发（专业核心课）"的两段式专业课。未来可单独规划一门"具身智能/AI 通识课"（2 学分，纯认知，无真机实操），与本课互补。
- **状态**：✅ 已确认，将在高职课程框架设计中使用此结论

### 调研 #002 | 高职学分计算标准 | 2026-08-04

- **来源**：WebSearch + 教职成〔2019〕13号《教育部关于职业院校专业人才培养方案制订与实施工作的指导意见》+ 多所高职院校实践
- **结论**：
  1. **学分计算标准**：一般以 **16-18 学时计 1 学分**（教职成〔2019〕13号原文）。实践中多数院校取 16 学时/学分，部分取 18 学时/学分
  2. **三年制高职总学时**：≥ 2500 学时（三年总计），每学年 40 周教学活动
  3. **公共基础课程**：≥ 总学时 1/4，即 ≥ 625 学时
  4. **实践性教学**：≥ 总学时 50%
  5. **选修课**：≥ 总学时 10%
  6. **专业核心课**：一般设置 6-8 门
  7. **关于本课（32 vs 16 课时）**：
     - 32 课时 = 2 学分（按 16 学时/学分），属于**专业核心课的典型学分**。高职人工智能专业常见专业课如《人工智能应用基础》为 2 学分/32 学时
     - 16 课时 = 1 学分，通常用于专业拓展课或专业限选课，不适合作为专业核心课
     - **结论**：本课作为"应用开发方向"的专业核心课，**32 课时（2 学分）是标准配置**。16 课时偏少，无法承载"应用开发"所要求的能力深度
- **影响**：确认本课应采用 32 课时 / 2 学分配置，与 5/21 框架的 32+32 方案一致
- **状态**：✅ 已确认

### 调研 #003 | BoosterOS SDK V1.0 API 覆盖审查 | 2026-08-04

- **来源**：阅读 `/root/uploads/1785830408754983913-BoosterOS 开发者接口文档 - V1.0.md`（5780行）
- **审查结论**：V1.0 文档**完全覆盖**此前识别出的所有 API 缺口：
  1. ✅ **视觉/检测**：`Detection` 类（`detect()` → `list[DetectionResult]`，含 class_name/class_id/confidence/bbox；`plot()` 可视化）
  2. ✅ **语音**：`Speech` 类（`recognize_stream()` 流式 ASR + 回调；`chat()` 语音对话 + `ChatConfig` 配置系统提示词/音色/音量）
  3. ✅ **示教管理器**：`BoosterHandGuidingManager`（`start_recording()` / `stop_recording()` → `TrajectoryData`；`is_recording` / `get_recording_duration()`）
  4. ✅ **自动踢球管理器**：`SoccerKickManager`（`start()` / `update_command(direction, power)` / `update_ball(x, y)` / `stop()`）
  5. ✅ **轨迹回放**：`execute_trajectory(TrajectoryData)` 异步回放

### 调研 #005 | BeyondMimic 教学可行性审查 | 2026-08-04

- **来源**：阅读清华工训课 18 章全文（Ch1-18），重点审查 Ch5（示教）、Ch6（动作数据）、Ch7（BeyondMimic 训练）、Ch8（模型部署）、Ch9（综合项目）
- **结论**：BeyondMimic **完全可用于高职教学**，原因如下：
  1. **操作链清晰**：Ch5-9 展示了完整的工程操作链——示教采集（SDK `RecordTrajectory`）→ CSV 理解 → CSV→NPZ 转换（`csv_to_npz.py`）→ 训练配置（task 注册 + `ppo_cfg.py` 参数）→ 训练启动（`train.py` 命令行）→ checkpoint 导出 → MuJoCo 验证 → K1 真机部署
  2. **每步都是工程操作，非算法研发**：学生不需要理解 PPO 数学原理、不需要推导奖励函数、不需要设计网络架构。他们需要理解的是"输入什么文件 → 配置什么参数 → 运行什么命令 → 产出什么结果 → 怎么验证"
  3. **命令行驱动**：训练入口是 `python scripts/rsl_rl/train.py --task=... --headless`，导出用 `play.py`，部署用 `deploy.py`——都是标准化的工程操作
  4. **有预训练模型可用**：`k1_mj_dance_002_2025-12-03_00-10-28.pt` 可作为教学中的"参考模型"，学生不必等待完整训练即可体验部署链路
  5. **硬件门槛是唯一约束**：训练需要 NVIDIA GPU + Isaac Sim/Lab 环境，但这是教学机房配置问题而非课程设计问题
  6. **高职适配策略**：高职课程应聚焦"使用已有 NPZ → 配置训练参数 → 启动短训练 → 导出模型 → MuJoCo 验证 → K1 部署"，不涉及上游重定向（BVH/SMPL-X→K1 CSV），将训练迭代数降低（如几百轮体验即可），重点放在"理解链路、能操作、能验证"
- **影响**：BeyondMimic 可作为高职课程中「示教与动作生成」单元的**核心内容**，占 6-8 课时
- **状态**：✅ 已确认
