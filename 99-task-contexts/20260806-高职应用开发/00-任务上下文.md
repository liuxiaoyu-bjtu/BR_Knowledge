# 高职「具身智能应用开发」课程设计 — 任务上下文

## 一、任务概述

为加速进化（Booster Robotics）设计面向**职业院校**的「具身智能应用开发」专业核心课程。课程以 Booster K1 人形机器人为教学载体，聚焦「应用开发」能力——会调用、会集成、会调试、会部署，不以算法推导为核心。

## 二、课程基础信息

| 项目 | 内容 |
|---|---|
| 课程名称 | 具身智能应用开发 |
| 适用对象 | 职业院校机器人/人工智能/自动化/智能制造等相关专业，二年级下学期或三年级上学期 |
| 课程性质 | 专业核心课 |
| 先修要求 | 完成「K1 机器人基础」（32 课时）或同等能力 |
| 总课时 | **32 课时**（16 次课 × 2 课时/次，90 分钟/次课） |
| 学分 | 2 学分 |
| 教学载体 | Booster K1 人形机器人 |

## 三、课程架构（已定稿）

### 3.1 七模块 32 课时

| 模块 | 主题 | 课时 | 主线 | 主要实验来源 |
|---|---|---|---|---|
| M1 | 视觉输入与基础调试 | 3 | A | 清华 Ch10 |
| M2 | 目标检测与方位判断 | 6 | A | 清华 Ch11 |
| M3 | 目标驱动运动控制 | 4 | A | 清华 Ch14 |
| M4 | 状态机与任务流程 | 4 | A | 清华 Ch13 |
| M5 | 语音交互与多模态 Agent | 4 | A+B | 豆包 SDK |
| M6 | 动作模仿与数据迁移 | 6 | B | 清华 Ch05-09 |
| M7 | 综合项目开发与展示 | 5 | A+B | 清华 Ch17-18 |

### 3.2 两条能力主线

- **主线 A（视觉感知驱动行为）**：M1→M2→M3→M4→M7，全体学生必修
- **主线 B（动作数据驱动行为）**：M6→M7，差异化进阶路径

## 四、已确认的关键设计决策

1. **空间定位深度**：使用 **bbox 启发式判断**（`norm=(error_x, error_y)` 直接驱动控制），**不引入**单目几何定位（相机内参/射线求交）
2. **行为架构**：使用 **FSM（有限状态机）**而非行为树——if-else + 枚举，三态 SEARCH→CHASE→HOLD
3. **语音模块**：独立 4 课时模块，聚焦 **LLM 调用 + Agent 人设 + 语音闭环**，不涉及语音信号处理
4. **GPU 依赖**：仅 M6 第 3 课时（训练流程理解）需要 GPU，采用**教师演示**模式，其余全部 CPU
5. **综合项目结构**：全体学生完成视觉踢球基础版（课时 1-3），课时 4-5 按兴趣三选一分流（踢球增强/语音 Agent/动作展示）
6. **复用策略**：清华工训课做减法、高职场景做加法——整体复用度约 45%，模块 5（语音 Agent）原创度最高

## 五、课程设计约束

- 高职学生基础：Python 入门级、无 ROS2 深度经验、无机器学习基础
- 教学节奏：90 分钟/次课（导入 10min → 讲授 25min → 实验 40min → 总结 15min）
- 设备条件：2-3 人/台 K1，学生电脑 Ubuntu 22.04 + Python 3.11
- 教师能力假设：具备 Python 编程能力，不一定有 ROS2/ML 深度背景
- 安全第一：追球/运动控制实验有明确安全规范

## 六、参考资源体系
