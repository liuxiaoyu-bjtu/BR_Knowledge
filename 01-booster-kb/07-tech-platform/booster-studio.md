# Booster Studio — 具身智能原生开发平台

> **定位**: Booster Studio 是加速进化（Booster Robotics）于 **2026 年 6 月底**发布的**全球首款专为具身智能开发打造的原生集成开发环境（IDE）**。它不是通用 IDE 的轻量改版，而是为机器人开发从头设计的原生平台，把可视化仿真、代码编辑、物理调试、实时可视化与真机部署全部收进一个桌面客户端，构建起覆盖"开发 → 调试 → 验证 → 部署"的全链路闭环。
>
> **官方下载**: [studio.booster.tech](https://studio.booster.tech)
> **官方文档中心**: [docs.booster.tech/zh-CN](https://docs.booster.tech/zh-CN/developer-guide/)

## 一、产品定位与核心主张

| 维度 | 说明 |
|---|---|
| **定位** | 机器人领域的"默认工具"，对标 VS Code |
| **形态** | 原生桌面客户端，支持 Windows / macOS / Ubuntu，开箱即用 |
| **主张** | 仿真与真机共享代码与接口；在虚拟里调通，一键下发真机 |
| **门槛** | **零硬件门槛**——不买实体机器人也能调用顶配机器人模型做仿真 |
| **发布时间** | 2026 年 6 月底 |

Booster Studio 的能力归为五类，其中 **IDE 本体**是承载其余四类的容器：在同一个 IDE 窗口里写代码、跑仿真、看可视化、点部署。其余四类专项能力——仿真、Vibe Coding、实时可视化、Sim-to-Real——不是独立软件，而是长在这个 IDE 里的功能。

## 二、安装与环境配置

### 2.1 下载与安装

访问 [Booster Studio 官网](https://studio.booster.tech/cn/)，选择操作系统对应的安装包。

| 操作系统 | 安装方式 |
|---|---|
| **Windows** | 双击运行 `.exe` 安装程序，按向导选择安装路径，勾选"创建桌面快捷方式" |
| **macOS** | 双击 `.dmg` 文件，将 Booster Studio 图标拖入 Applications 文件夹 |
| **Ubuntu** | `sudo dpkg -i booster-studio-xxx.deb` |

### 2.2 Docker 依赖

Booster Studio 采用 Docker 容器技术将仿真环境封装在容器中。安装 Docker 后，Studio 能一键拉取容器镜像，迅速部署仿真环境。

- **Windows**：可使用 `install_env.zip` 一键安装 Docker 环境（含 WSL2）
- **macOS**：从 [Docker 官网](https://www.docker.com/products/docker-desktop/) 下载 Docker Desktop，安装后重启，保持后台运行
- **无需登录 Docker 账号**，Booster Studio 会自动识别并控制 Docker Desktop 引擎

### 2.3 硬件配置建议

| 组件 | 最低配置 | 推荐配置 |
|---|---|---|
| **CPU** | AMD Ryzen 7 8745H 及同级 | R9 8945HX / R7 8840HS / Core Ultra 9 |
| **内存** | 16GB | 32GB 双通道 |
| **显卡** | CPU 集成核显（如 Radeon 780M） | 无强制要求 |

> 本地配置不足时，可使用[云桌面](#六云桌面2026年8月已上线)接入云端高性能开发环境。

## 三、五大核心能力

### 3.1 IDE 本体

Booster Studio 是一个有完整开发界面的桌面 IDE，默认视图是典型 IDE 的三栏布局：

- **左侧**：项目浏览器（以 `Agent` 为开发单元组织工程）
- **中间**：多标签代码编辑器（语法高亮、行号、代码导航；默认 Python，支持 C++ 工具链）
- **右侧**：AI Assistant 辅助编程面板
- **底部**：集成终端（直接运行 build 等命令，支持 AI 能力，`Ctrl+K` 触发）

**开发单元**：以 `Agent` 为单位组织工程，类似手机上的 App。一台机器人同一时间运行一个 Agent，可随时切换。入口文件通常为 `agent_main.py` / `main.py`。

### 3.2 仿真能力

仿真能力帮助开发者跨越真实硬件开发的四道高墙——成本高、风险高、迭代慢、难复现。

- **像素级物理引擎**：复现重力、地面摩擦、刚体碰撞与柔性接触，建模传感器噪声特性（IMU 漂移、摄像头畸变、关节摩擦不确定性）
- **数字孪生模型**：无需购买实体硬件，直接加载 Booster T1、K1 等机型的数字孪生模型跑控制算法
- **可复现实验**：固定随机种子精确重放故障；支持域随机化（Domain Randomization）主动扰动质量、摩擦、光照、噪声参数
- **受控步长**：可加速、可单步，与自动化测试、回归验证绑定，迭代节奏从天级压缩到分钟级
- **3V3 足球仿真赛**：多机器人协同、足球比赛规则、对战功能、支持选择对战 Agent

### 3.3 Vibe Coding（AI 辅助编程）

`Vibe Coding` 由 Andrej Karpathy 于 2025 年 2 月提出，核心理念是用自然语言驱动 AI 生成代码，人类退到审核与引导的位置。Booster Studio 将这一理念引入机器人开发领域。

- **自然语言描述意图**：例如"让机器人在收到视觉信号后向左转 90 度并蹲下"，AI 自动生成对应控制逻辑
- **计划模式（Plan Mode）**：先让 AI 输出任务分解与方案供人审题，用户确认后再正式生成代码——给 Vibe Coding 加装一道安全闸，避免错误改动导致物理世界中的高昂代价
- **人类角色**：审核、引导、纠偏，而非逐行手写；专家经验从"写代码"转移到"定方向、判好坏"
- **多模型支持**：支持 Kimi-K3、Qwen3.8Max、deepseek-v3、DeepSeek-V4-Flash 等，并支持自定义模型接入

### 3.4 实时可视化

Booster Studio 把 3D 场景、点云、摄像头流、时序图、URDF 模型等收进统一视图实时渲染，建立「感知—决策—执行」的整体直觉。

**可视化组件（Widgets）体系**：

| 类别 | 组件 |
|---|---|
| **通用组件** | 2D View、3D View、Image、Plot、Gauge、Indicator、Log、Notebook、Parameters、Pie Chart、Publish、Raw Messages、State Transitions、Table、Terminal、Topic Graph、Data Source Info |
| **Booster 专属组件** | Booster Motion Control、Booster Vision、Booster Head Control、Booster Joints Temperature History、Booster Battery History、Booster Robot Status、Booster Robot Body Display |

- **统一坐标系叠加**：视觉、深度、激光、IMU 等数据在统一坐标系下叠加呈现，直观分辨「模型以为自己看到了什么」与「真实是什么」的偏差
- **真值对比（Ground Truth）**：仿真场景中同时显示算法估计值与仿真真值，获得真机难以提供的上帝视角
- **ROS bag 回放**：深度集成，快速回到故障发生时刻，排查传感器异常、复盘运动轨迹、做失败归因
- **可观察调试链**：运行异常 → 回放定位 → 回到代码/Vibe Coding 修正 → 再跑

### 3.5 Sim-to-Real（仿真到现实）

Sim-to-Real Gap 是机器人仿真领域的核心难题。Booster Studio 的解法：仿真不是独立软件，而是与真机调试集成，共用同一套通信架构与控制接口。

- **无需重写底层协议**：代码在虚拟沙盒里调通后，直接迁移到真机
- **一键部署**：仿真验证无误后，一次点击将代码下发给物理真机，实现高精度映射与毫秒级响应
- **双向闭环**：真机表现不稳定时，使用日志功能复看传感器与轨迹，回到开发阶段修正，形成 `仿真 ↔ 真机` 双向闭环
- **数据反哺**：真机跑出的数据可再次喂回仿真与可视化，驱动下一轮改进

```python
# 仿真模式与真机模式共用同一套接口，无需改代码
robot = BoosterRobot()  # 仿真中连接虚拟机器人
robot = BoosterRobot()  # 真机模式自动发现实体机器人
```

## 四、机器人连接与管理

### 多类型机器人连接

- **Booster 真机机器人**：K1、T1、T2
- **自定义机器人**：支持自定义配置
- **虚拟机器人**：基于 Docker 容器创建，支持 Booster T1 / K1 型号选择

### 连接方式

- **局域网扫描连接**：自动扫描局域网中的机器人，列表中选择并连接
- **SSH 远程连接**：支持 Remote-SSH 连接机器人本体，输入各板用户名和密码
- **多板连接支持**：支持连接机器人多个计算板（运动板、感知板等）
- **连接后自动安装**：Booster Studio server，进入机器人配置页面

连接成功后，默认显示 Booster 机器人专属组件：各关节状态、摄像头视频、运动控制、头部控制、电池电量变化图表、关节温度变化图表。

## 六、云桌面（2026年8月已上线）

> **状态**：✅ 已上线（2026 年 7 月 P0 立项，8 月 4~10 日当周正式发布）

- **产品定位**：用加速豆租用云端性能更好的 Linux 电脑，预装开发环境
- **解决的问题**：学生/开发者本地电脑配置不足 → 零门槛入门
- **创建流程**：Studio 内置创建流程，支持选择操作系统 → 设置 workspace → 选加速豆数量（决定云端机器配置）→ 选架构 → 创建
- **配置可选**：GPU 规格 / 系统盘 / 数据盘 / 镜像 / SSH 连接
- **按使用量计费**：消耗加速豆
- **价值**：无需升级本地硬件，通过浏览器/Studio 直接接入预配置的高性能云端开发环境

## 七、AI 助手与 Vibe Coding

集成在 Studio 右侧面板中的智能编程助手（标题 "Work with AI Assistant"）：

- **AI 对话**：自然语言问答，通过 `@` 引用上下文、`/` 调用内置技能
- **代码生成**：根据描述生成或修改控制逻辑
- **多文件编辑**：支持多文件项目
- **多模型支持（已上线）**：Kimi-K3、Qwen3.8Max、deepseek-v3、DeepSeek-V4-Flash 等国内主流模型 + 用户自定义模型接入
- **计划模式（Plan Mode）**：AI 先输出任务分解与方案供人审题，确认后再生成代码
- **MCP 支持**（在研）：Model Context Protocol，自定义工具调用
- **Agent 日志自动改代码**（在研）：根据运行日志自动修改代码，AI 辅助调试

## 十、常见问题

**Q：没有实体机器人可以用 Booster Studio 吗？**
A：可以。Studio 内置虚拟机器人和仿真环境，整个开发流程不依赖真机。等需要在真机上验证效果时再连接即可。

**Q：Booster Studio 支持哪些操作系统？**
A：支持 Windows 10/11、Ubuntu 20.04/22.04、macOS 12+（Apple Silicon）三大平台。

**Q：本地电脑配置不够，跑不动仿真怎么办？**
A：可使用 Booster 云桌面，通过浏览器/Studio 直接接入预配置的高性能云端开发环境，无需升级本地硬件。

**Q：使用 Microsoft Edge 下载安装包被拦截怎么办？**
A：点击下载项右侧「…」→ 选择「保留」→ 安全弹窗中点击「删除」旁下拉箭头 → 选择「仍然保留」即可正常安装。（弹窗为 Microsoft Defender SmartScreen 安全校验，发布方为 Booster Robotics Technology Co., Ltd，文件安全）

**Q：打开软件弹出「已阻止访问受保护的文件夹」警告怎么办？**
A：这是 Windows 安全中心受控文件夹访问防护拦截了 Booster Studio 读取 Documents 目录权限。在弹窗页面点击「同意/允许」授权，授权完成后重启软件即可。

**Q：什么是 Agent？**
A：Agent 是运行在机器人上的程序，类似手机上的 App。一台机器人同一时间运行一个 Agent，可以随时切换。

## 十一、教学价值

### 11.1 降低硬件门槛

- 学生可在无实体机器人的情况下进行编程学习
- 一个班级可共享少量真机 + 每人一个仿真环境
- 云端仿真 + 云桌面进一步消除本地配置需求

### 11.2 提高教学效率

- 仿真中可加速、暂停、回放，便于教学演示
- 不怕学生操作失误损坏设备
- 支持批量部署和统一管理

### 11.3 完整工程闭环

```
创建项目 → 编写代码（或 Vibe Coding） → 仿真测试 → 实时可视化调试 → 真机验证 → Agent 部署
```

学生经历从原型到部署的完整工程流程，培养工程思维和调试能力。
